# 本机反向代理超时归属与加固

## 适用

只监听回环地址、跑在本机的转发层（UA 改写代理、鉴权前置、本地 sidecar、SSE 透传）。症状典型为「进程活着、连接接受、但请求超时或断在半路」，或「改了没生效」。

生产与核心服务的代理配置不套用本流程：先给方案与回滚，等明确批准。

## 改动边界

现役代理/客户端的停启由用户本人执行，Agent 只提供已核对的精确 PID、影响面与回退步骤；自动结束仅限本会话创建的隔离测试进程，先枚举整棵子进程树并逐个核验归属，含用户或外来进程时不得使用 `/T`。

**外来监听负对照**：在沙箱里起一个同端口但命令行不含本代理特征的假监听，确认启停脚本不会杀它；只按镜像名（`node.exe`）或端口杀进程是禁止项。

## 0. 先证明跑的是新代码

任何"上次修过还是坏"都先做这一步，否则会把未生效的修复当成逻辑缺陷继续追查：

- 进程启动时间 vs 脚本文件 mtime；晚于启动的改动不可能生效。
- 服务健康端点回显的版本 / 源码 sha256 前 12 位 vs 磁盘文件哈希。
- 不一致 ⇒ 判「新代码未加载」，按 `windows-hidden-autostart-daemon` 的停启顺序重启后**复验一致**才算生效；判据链见 `verify-before-claim`。

## 1. 超时归属三分类（看代理日志，不看客户端报错）

| 类别 | 日志签名 | 结论 | 别做什么 |
|---|---|---|---|
| 客户端先放弃 | `outcome=CLIENT_DISCONNECTED elapsed_ms≈<客户端阈值>` 且该请求 id **没有** `REQ ... phase=headers` 行 | 代理与上游都没错，是调用方首包超时 | 不要调代理超时来"修"它——阈值不属这里 |
| 代理自身超时 | `UPSTREAM_HEADERS_TIMEOUT` / 代理侧计时到点 | 代理配置的超时值真被触发 | 先确认阈值来自哪个环境变量，别和上一类混判 |
| 上游慢 / 限流 | `REQ ... elapsed` 很大，或 SSE 正文里带 error 事件、`rate_limit` | 上游侧问题 | 换模型或等待；不要在本机反复重试打爆额度 |

要点：**上游会把错误塞进 HTTP 200 的 SSE 正文**，光看状态码查不出来。旁路嗅探响应前若干 KB 并记一行 `UPSTREAM_ERROR kind=rate_limit|upstream_canceled|unauthorized|error_event`——看到这行就是上游侧问题；正常响应不该出现这行（本身就是负对照）。

## 2. 可失败实验：假慢上游夹具

在临时目录起一个自签 TLS 的假上游 + 独占端口，跑两场景：

1. **头延迟 > 阈值**：应触发保活路径，首包在阈值内到达、连接不被客户端切断、最终完整返回。
2. **上游返回非 2xx**：状态码若已发出则改以错误事件收尾并保留上游原文；未发出则原样透传。
3. **负对照**：快上游必须走原透传路径（保活标志为空）——证明加固没把常规路径改掉；再请求一条故意编造的路径，确认返回形态与正例不同。

夹具产物、日志写获准的非系统盘；自签证书只用于本地校验，不要为此关掉生产 TLS 验证。

## 3. 加固项与其算法代价

- **早期响应头 + 心跳保活**：对 `accept: text/event-stream` 请求，若上游在 `EARLY_HEADERS_MS` 内不回头，先回 `200` 并按固定间隔写注释行保活，上游真头到达后转正常 pipe。**阈值选择**：调用方的等待窗口 ≈ 早期头阈值 + 客户端首包上限；注释行心跳**不能**延长窗口，只有上游有效数据才重置计时。阈值必须小于调用方上限，否则等于没保活。
- **超时与连接**：显式设 `keepAliveTimeout`、上游头/体超时；不要跨请求共享 keepAlive 池去"省连接"——池卡死会表现为"接受连接但不转发"。清理断连监听 `res.on('close')`；用 `req.on('close')` 会在请求体发完即触发，把上游请求立刻打死。
- **重复守护抢端口**：捕 `EADDRINUSE` 后保持进程存活并按间隔重试绑定，前一实例退出即接管；直接退出会让上层守护每 N 秒拉起一个必死进程（风暴）。
- **日志**：按尾部轮转（保留最近 N 行/大小），别把保活心跳写成一秒几十行的噪声淹没判据；日志里不回显凭据。

## 4. 归因纪律

新实例在独立端口成功，只证明**该实例状态**异常，不证明根因是连接池；`CLOSE_WAIT` 堆积、上游连接数为 0 都是线索不是结论。单变量实验逐个否证，拿不下时按 `intermittent-hang-ab-triage` 收敛为「根因未定」，并如实把未证实的归因写成假设。

## 5. 透明 SSE 代理回归矩阵

先明确三条禁止项：**不伪造前导事件、不改写响应 ID、不改写序号**。代理只转发与必要的保活，不扮演模型。

用增量 UTF-8 解码与标准 SSE 解析，覆盖：

| 维度 | 用例 | 判据 |
|---|---|---|
| 字节切分 | 任意切块、跨多字节汉字、一行拆成多块 | 解码后文本完整，无替换字符 |
| 行尾 | CRLF / LF / CR / 混合 | 事件边界不丢、不合并 |
| 多 data 行 | 一个事件多条 `data:` | 按协议拼接后一致 |
| 截断 | EOF 未收到完成事件 | 判失败，不得报成功 |
| 前导 | 注释/心跳行 | 不得导致重复 `created` |
| ID | 首尾响应 ID | 必须一致，不重写 |
| 工具调用 | 完整参数、空参数、分片参数 | 参数完整且有终态 |
| 输出 | 空输出、HTML、超长输出 | 分别判定，不互相替代 |
| 超时 | DNS / 响应头 / 空闲 / 上传 / 流中途 | 分层归因，不混成一个“超时” |

分别断言四件事，不能相互替代：**传输完成**（连接正常结束）、**协议完整**（SSE 事件闭合）、**模型生成成功**（有正常终态/完成事件）、**内容一致**（与上游逐字节或逐事件一致）。
