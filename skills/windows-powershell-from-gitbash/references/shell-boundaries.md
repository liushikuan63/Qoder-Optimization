# 参数、编码与退出码的验收边界

这些方法由已验证的跨 Shell 排查流程提炼。每次使用仍核对当前解释器和工具链；历史机器、码页、客户端名及授权不作为默认值。

## 解释器与参数

1. 当前调用记录解释器实际路径、自报版本与工作目录。`PATH` 中的 `bash` 可能是 WSL；项目需要 Git Bash 时使用核对过的 Git 安装入口。
2. 复杂载荷放自有文件，结构化参数优先于多层字符串拼接。路径含空格要正确引用；不能因某个旧包装器的引号缺陷而普遍去掉路径引号。
3. 给每一跳确定接收端期望。用已安装 `shell-boundary-probe.cjs` 比较当前 Node 的 argv；另一个原生 exe 是否正确解析参数仍须由它的接收端或可观测业务结果验证。
4. 不无依据启用 `windowsVerbatimArguments:true`；该选项改变 Windows 命令行引用责任，不是保真开关。

## Git Bash/MSYS 到原生程序

MSYS 可能在原生程序启动前转换 `/groups` 等看起来像路径的参数。确需保留这些开关时，先用自有 argv 期望做正反对照，再对单次调用设置 `MSYS2_ARG_CONV_EXCL`，能限定前缀就限定前缀。

排除转换也会影响本来需要转换的路径。先用 `cygpath -w` 等得到目标 exe 要求的 Windows 路径，再传给已核对的可执行文件；不要全局禁用路径转换，也不要普遍把 `/` 改成 `//`。子程序内部再设置排除变量无法修复已发生的父层转换。

同名工具可能被 Git 的 Unix 版本遮蔽，添加 `.exe` 后缀也不等于 System32 实现。先核实际可执行文件，再判断开关是否适用。自有 argv 探针已经足够时，不用账号组、注册表或服务命令作探针。

## 编码

| 对象 | 核对方法 |
| --- | --- |
| 含中文 `.ps1` | 分别用目标5.1/7解析；核对脚本BOM和实际解释器，不仅看扩展名 |
| PowerShell字符串输出 | 明确目标版本与写盘API；5.1的 `>`/`Out-File` 与7的默认行为分别取证 |
| 原生 stdout/stderr | 分流保留原始字节与BOM，核对程序编码约定及本轮样例 |
| JSON或其他消费端文件 | 回读原始字节，再由实际消费端解析；控制台看起来正常不够 |

严格 UTF-8 失败只支持“不是有效UTF-8”，不能证明是GBK。纯ASCII样例不能区分多种兼容编码；需要非ASCII对照。不可为探针修改系统码页、TLS校验或代理设置。

## 三态与副作用

- 正常输入：接收端参数、业务结果及进程退出码均符合已独立确定的期望。
- 业务失败：子程序明确 `exit 7` 时，包装器实际返回7；只打印 `EXIT=7` 不算。
- 输入/解析失败：损坏脚本或缺少参数必须明确失败，不能继续打印完成并退0。

`-File` 不保证所有 PowerShell 错误都会非零退出；必要的cmdlet错误要适当升级为终止错误，必要结果做明确断言。原生命令退出码立即保存，不能被后续成功命令覆盖。stderr、错误关键词、警告和业务失败的关系由目标程序契约确定。

未知的提交或发布超时先按操作标识只读查回；不以重跑验证是否成功。诊断不授予注册表、服务、提权、前台输入或其他外部写入权限。

## 记录

保留命令入口、参数样例文件摘要、实际退出码、stdout/stderr原始记录、机器与解释器身份，以及期望与反例。分别说明当前argv这一跳、后续原生程序和真实业务是否已验，不把静态脚本或模拟结果当实际运行。
