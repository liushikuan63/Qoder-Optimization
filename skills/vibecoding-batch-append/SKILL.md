# Vibecoding 批次卡追加（向既有任务包立卡）

## 定位与边界

- 只管**追加**：包里已有 `B00-共享上下文.md`、`总发起指令.md`、批次卡、`验收与台账.md`、`_AUTHORING.md` 与自带 `<包目录>/scripts/validate.mjs`。
- 建包走 `vibecoding-doc`；按卡写实现代码走 `vibe-coding-workflow` 或卡内开工提示词。本技能**不写实现代码**。
- **包内文件是真源**：`_AUTHORING.md` 的编写约束与 `<包目录>/scripts/validate.mjs` 的检查项永远优先于本技能列出的清单；第一步必读，冲突时以包内为准。

## 第 0 步 定位与读规则（不可跳过）

```sh
ls <包目录>   # 期望：B00 / 总发起指令 / 批次卡 / _FACTS / _AUTHORING / 验收与台账 / scripts/validate.mjs
```

读五样：`_AUTHORING.md`（事实契约与轮次边界）、`<包目录>/scripts/validate.mjs`（**判红的真源**，逐条看硬规则）、最近一张已通过的批次卡（格式范本）、`_FACTS.md` 与台账末尾（现状、未验证项、接续入口）、根 `AGENTS.md` / `spec.md` / `plan.md`（若存在，卡内只引用它们的命令、不做清单与契约）。

包内没有自带校验器时：退回 `node ~/.qoder/skills/vibecoding-doc/scripts/check-vibecoding-doc.js <包目录>` 做结构底线，并跳过第 5 步的存档刷新。

## 第 1 步 需求收敛：先裁决，再落笔

- **判「新批次 vs 并入既有批次」**：新方向、可独立验证的增量 → 新卡；对已验收批次的修补/延伸 → 并入该卡（改卡 + 台账补记），**不占新号**（防批次号膨胀）。
- 需求含糊或存在方案分歧点时，**一次弹窗**（AskUserQuestion）给全选项与推荐项，拿到结论再写卡；把裁决结论写进卡内（依赖行、必做清单、开放问题），不能只留在对话里。
- 用户中途收窄/扩大范围时（如实测案例："是对所有检测和管理的进程"），把范围变化落进标题、必做清单与验收，而不是只改一句话。

## 第 2 步 现读核对源码行号（最容易判红）

校验器对每条 `[标签](相对路径#L起-L止)` 只验证三件事：链接能解析、`1 ≤ 起 ≤ 止`、`止 ≤ 文件总行数`。**语义对不对它查不了**，而「行号是工作树快照、随代码漂移」是这类包的明文约定。所以：

1. 引用前**打开文件读目标区间**，确认内容与卡片主张一致；不凭记忆或旧文档写行号。
2. 用脚本列全部引用逐条对照：

```sh
node ~/.qoder/skills/vibecoding-batch-append/scripts/line-refs.mjs <包目录>/<新卡>.md
```

输出每条引用的解析路径、文件总行数、`OK/OUT_OF_RANGE/MISSING` 与首末行预览；坏引用退出码 1。

3. 链接红线：包内文档用相对路径、源码用 `../../` 起（相对包目录）；**不得**出现 `-svn`/`副本` 路径、非 HTTPS 外链、私网地址（10. / 192.168. / 172.16-31.）、密钥或 `password/token/secret` 赋值。

## 第 3 步 写卡：命名、8 章节、硬格式

- 文件名 `B<两位序号>-<批次名>.md`。校验器要求**从 B01 起严格连续**（"存在即可"不够）——能追加到末尾就追加；要在中间插号，必须把后续全部重命名并同步整个包的链接与索引（代价大，先问用户）。
- 头部块：`# B13 · 名称` 式标题、`- 依赖：…`（**必须存在 `- 依赖：` 行**，内容含 `B\d\d` 且依赖存在、不成环）、`- 优先级/状态/工期/风险`。
- **8 个必需二级标题**，用**精确字符串**（含空格；校验器按子串匹配，写错即判红）：
  `## 〇 现状`、`## 必做清单`、`## 输入 / 输出契约`、`## 固定约定`、`## 可勾选验收`、`## 产出文件清单`、`## 禁止项`、`## 开放问题`
- **开工提示词**用「四个反引号 + text」围栏（`` ````text `` 开头、`` ```` `` 结尾，各自独占一行）：围栏必须闭合；写成三个反引号会让内层代码块提前闭合而判红。提示词里带上该包口径：先复核既有链路、先写可失败夹具、未授权项显式标注未验证。
- **可勾选验收 ≥3 条 `- [ ]`，每条至少含一个数字**（组数/条数/次数/行数/秒数），并写清判定方式与对照。形容词（更快/更稳）不合格；真机、现场、未授权项单列一条，写明「未获授权时标注未验证，不以桩测代替」。
- 事实契约（以包内 `_AUTHORING` 为准，常见条款）：新接口/DTO/表/字段名标"**拟新增**"；未确认的规模/工期/SLO 写"待确认"；静态问题写触发条件、不写成"已在线复现"；版本以 `pom.xml`/`package.json` 声明为准；严格区分"静态确定 / 待实测 / 建议新增"；不写真实口令与内网地址。
- 卡内不重复 `AGENTS.md` 的命令/禁区，也不重复 `spec.md` 的目标/不做/验收与 `plan.md` 的技术栈（引用文件+节号即可），只写本批差异与契约。

## 第 4 步 同步索引与登记（缺一即判红）

- `总发起指令.md`：① 索引覆盖——包里**每个 `.md` 都必须**能从它以 `](文件名)` 链接到（新增文档不登记 → `index` 判红）；② 批次状态与装配表补一行（依赖产物 / 状态 / 装配边界）；③ 阅读顺序或说明句补一句新卡状态。
- `_FACTS.md`：新增/更新现状条目（编号续号），写清"拟新增 / 未实施"并附证据行号。
- `验收与台账.md`：追加台账行（`日期 / 单元 | 做了什么 | 怎么验的 | 没做什么 / 已知边界 | 下一项`）；"未验证与接续入口"补本批待授权项。
- **整包收口必须含最终审计**：台账单列「最终审计」章节与证据行——落地后只读跑 `production-readiness-audit`，报告过 `node ~/.qoder/scripts/readiness-report-check.cjs <report.json> --json` 且 **EXIT=0** 才计入全绿；报告路径与退出码入台账，未执行写「未执行 + 原因」。小项目可裁剪清单子集，不得整段省略。
- 接续载体：项目有 `.qoder-work-queue.md` 时补接续入口（卡片路径 + 提交号 + 当前状态），并跑 `node ~/.qoder/scripts/work-queue-check.js` 自检；有项目记忆则同步一句。

## 第 5 步 双命令校验 + 存档刷新（提交前最后一步）

```sh
node <包目录>/scripts/validate.mjs              # 结构 / 链接 / 行号 / 敏感模式
node <包目录>/scripts/validate.mjs --self-test  # 全部变异分支都必须被检出
```

- 判绿标准：**两条命令退出码 0**，`--self-test` 的 `rejectedMutations` 与包内既有值一致；读输出里的 `documents/batches/localLinks/sourceLinks`。
- 包内存档（如 `document-validation.json` / `validator-self-test.json`）**必须在最后一次文档编辑之后**重跑覆写，并把台账里的数字改成与存档一致。实测踩坑：卡片最后两处编辑发生在存档之后 → 台账 233 与存档 235 不一致，只能补一次"刷新存档"提交。
- 覆写前先确认退出码 0 再重定向（`node … > 存档.json` 在失败时会把存档清空）；更稳的写法是先输出到临时文件、成功后再覆盖。
- 收尾顺序固定：**所有文档编辑 → 重跑双命令 → 覆写存档 → 回填台账数字 → 提交**。

## 第 6 步 提交：只加明确路径

- 先 `git status --short` 分辨归属：只提交本轮的文档路径；工作区里既有的未跟踪/未提交改动（可能是别人或他轮的工作）一律不碰。
- **禁 `git add -A` / `git add .`**，逐条列出路径；提交信息跟随仓库惯例（实测：`wiki 立卡 B13：…` 这类中文短句）。
- 默认**只做本地提交**，不推送、不部署、不连现场；推送需另获用户批准。
- Git Bash 下提交偶发挂起转后台时，**读输出文件确认结果**再继续，不把"命令已发出"当成功。

## 第 7 步 停点：立卡=待评审

- 立卡完成即停，**不自动开始实现**；实现是另一批工作（按卡开工，先夹具后实现）。
- 汇报：卡片路径 + 关键裁决落点 + 校验命令与两个退出码 + 提交号 + "未做/未验证"（未写业务代码、未部署、真机未授权项）。

## 提交前自检清单

- [ ] 包内 `_AUTHORING` 与 `validate.mjs` 已读，卡内容与其一致
- [ ] 批次号连续、`- 依赖：` 行存在且依赖存在无环
- [ ] 8 章节精确标题齐、四反引号提示词块闭合、验收 ≥3 条且每条含数字
- [ ] 每条行号引用已现读核对（边界 + 语义）、无 `-svn`/副本路径、无私网地址/凭据
- [ ] 总发起指令索引与批次表已更新；`_FACTS`、台账、接续载体已登记
- [ ] 双命令退出码 0，且存档是最后编辑之后重跑的；台账数字与存档一致
- [ ] 只提交本轮明确路径；他人改动未触碰

## 本仓库实测案例（2026-09-30，B13 立卡）

包：`wiki/lite-evolution-vibecoding/`（guanyun Git lite 演进）。流程：四问裁决 → 现读核对 15 条行号引用 → 写卡 → `_FACTS` R04 / 总发起指令 / 路线图 / 台账登记 → 双命令退出 0（20 文档 / 13 批次 / 235 内部链接 / 83 源码引用）→ 本地 3 个提交（`ca4551bc` / `2f1ce6aa` / `a930208b`）。

```sh
node ~/.qoder/skills/vibecoding-batch-append/scripts/line-refs.mjs wiki/lite-evolution-vibecoding/B13-进程自启与守护检测及自愈.md
node wiki/lite-evolution-vibecoding/scripts/validate.mjs
node wiki/lite-evolution-vibecoding/scripts/validate.mjs --self-test
```
