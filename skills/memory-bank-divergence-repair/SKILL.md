# 双侧记忆分叉修复

## 适用

`sync-memory.sh` 报「分叉 / 单边」，或两侧 `MEMORY.md`、记忆正文不一致。

**核心判据：先测包含关系，别默认每个分叉都要人读。** 实测 17 个"分叉"里 14 个只是某侧滞后，可直接覆盖；只有 3 个真的两侧都有独有内容。

## 1. 列全清单

```bash
bash ~/.qoder/scripts/sync-memory.sh 2>&1 | tail -40
```

不要只看前几行——脚本会截断，单边与分叉两类要分别数。

## 2. 测包含关系（分档）

```bash
comm -23 <(tr -d '\r' < ~/.qoder-cn/memory/X.md | sort -u) <(tr -d '\r' < ~/.qoder/memory/X.md | sort -u) | grep -c .
comm -13 <(tr -d '\r' < ~/.qoder-cn/memory/X.md | sort -u) <(tr -d '\r' < ~/.qoder/memory/X.md | sort -u) | grep -c .
```

或用一次性脚本一次算完：读两侧、去 `\r`、按行成集合，输出「仅 A 有 / 仅 B 有」两列。

| 结果 | 档位 | 处置 |
|---|---|---|
| 一侧独有行 = 0 | **纯滞后**（该侧是另一侧的子集） | 直接 `cp` 超集过去（先备份），无损 |
| 两侧都有独有行 | **真分叉** | 进第 3 步逐段合并 |
| 只有一侧有文件 | **单边** | 补到另一侧 + 补索引项 |

注意：行集比较会因**同一规则被改写**而产生"两侧都有独有行"，这种多半是版本差异而非两套事实，读一眼就能定性。

## 3. 真分叉的合并规则

1. 把两侧独有行都列出来，**逐条判**：是"同一事实的旧/新表述"（取新）还是"另一侧独有的事实"（必须保留）。
2. 常见形态与落位：
   - **头注 / 拓扑说明**：取较新的一次实测，并把被推翻的旧结论写成"已推翻"而不是直接删（否则下次又会有人按旧口径推断）。
   - **索引（MEMORY.md）**：取**指针并集**，同名条目取较新描述；另一侧独有条目要连同文件一起补过来。
   - **正文新增段**：两侧各有的段并行保留，不要互相覆盖。
3. 合并后**两侧写同一份内容**（CRLF 与原文保持一致）。
4. 索引超过 200 行时：**压头部说明而不是删条目**（删条目会让文件变孤儿）。

## 4. 验收（每条都能失败）

```bash
bash ~/.qoder/scripts/sync-memory.sh      # 期望：两侧一致（N 个文件），索引自洽
md5sum ~/.qoder/memory/MEMORY.md ~/.qoder-cn/memory/MEMORY.md   # 期望相同
```

再自查三条：
- 文件数 == 索引唯一引用数（悬空指针 0）
- 零字节文件 0
- 行数 ≤ 200（超了客户端只加载一部分）

## 5. 汇报口径

「N 个分叉 + M 个单边 → 修复 K 个文件（其中纯滞后 X / 真合并 Y / 单边补齐 Z）→ 两侧 md5 相同、sync 报两侧一致、悬空指针 0」；真合并的那几条要写清保留了哪些独有事实。

## 坑

- **别用 mtime 判赢家**：一侧"没动过"不代表内容旧，另一侧可能只是改了错别字。
- **别整份覆盖真分叉**：会静默抹掉另一侧的独有正文（sync 脚本拒绝自动覆盖就是这个原因）。
- **`find` / `du` 不穿 junction**：判"库是不是空的"要用 `ls` / `readdirSync` 复测。
- **记住 `MEMORY.md` 也是共享追加型文件**：合并前先读最新内容再落笔，避免覆盖并行会话刚写的行；
- 改完顺手看一眼记忆里是否有指针仍指向旧名/旧路径。
