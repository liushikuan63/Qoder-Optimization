# 双侧记忆分叉修复

## 边界

先核对本轮对象、真源与写入授权。只读审阅不备份、不写文件；修复已获授权也不自动恢复已撤销的许可或删除的记忆。不创建不存在的另一客户端。

## 1. 获取现场和共同基线

运行 `bash ~/.qoder/scripts/sync-memory.sh` 列出分叉与单边文件，分别检查索引和正文。已有客户端目录以现场为准。

共同基线必须是两侧分叉前的同一已核验版本，例如有哈希记录的备份或版本控制快照。mtime、文件大小、行集合包含关系都不能证明版本新旧；行集合还会丢失顺序和重复项。

没有可信共同基线时，报告两侧差异、引用关系及已知删除记录；不得自动判赢家、求并集或复制单边文件。只有当前真源得到明确确认后才能据此修复。

## 2. 三方比较

设共同基线为 B，两侧当前版本为 A、C。比较完整文件内容以及文件是否存在，不先排序或去重。

| 情形 | 判定与处置 |
|---|---|
| A == C | 已一致，不写入 |
| A == B，C != B | C 是单侧变更候选，核对授权后传播；C 的删除也必须保留 |
| C == B，A != B | A 是单侧变更候选，核对授权后传播；A 的删除也必须保留 |
| 两侧均偏离 B | 三方合并；删除/修改冲突、相反许可或重排必须逐项裁决 |
| 文件只存在一侧 | 区分新增与另一侧主动删除；无基线不自动补齐 |

可以用 `git merge-file -p <A> <B> <C>` 只输出文本合并结果；退出码与冲突标记必须检查，自动文本合并无冲突也不证明语义一致。不得把合并命令输出直接覆盖现役文件。

## 3. 形成候选并核对语义

- 逐条比较主体、动作、对象、条件、否定、例外与授权范围；过期许可不因另一侧仍有记录而恢复。
- 索引与正文作为同一变更集处理：删除正文时删除对应索引；新增指针必须有正文，不盲取索引并集。
- 判断每个独有段是新增、删除、改写还是移动，保留来源证据；无法判断的冲突保留待确认，不默认为新增。
- 写入前重新读取两侧并核对与审阅时的哈希一致，发现并行改动先重新比较；按备份策略保存回滚点。

## 4. 验收

先在隔离目录验证候选，再在本轮授权范围内应用。检查两侧目标内容哈希、零字节文件、索引悬空、孤儿文件和主索引行数，不把两侧相等当成内容正确的唯一判据。

必含反例：

1. B 中有临时许可，A 主动删除，C 未变：结果保留删除，不能把 C 的超集覆盖到 A。
2. A、C 各自新增不同条款：两项均保留；同一条款一侧删除另一侧修改：必须显式报告冲突。
3. 无共同基线或写入前哈希已变化：停止该项自动合并，现役文件保持原样。

## 5. 汇报

区分已确认新增、保留删除、已解决冲突和未决项；记录采用的基线指纹、候选验证、实际写入范围及回滚入口。不把字符计数、行集合或同步脚本通过称作语义无损证明。
