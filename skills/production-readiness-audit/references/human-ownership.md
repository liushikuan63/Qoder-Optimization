# 哪些格子必须是人（13 条角色项）

清单原文末尾还有一段：除了让上面 147 条每天一直工作下去，产品仍然需要懂行的人。这 13 条**不是产品检查项**，不参与 ID 覆盖校验；它们是**责任归属表**，用来回答「这条格子谁负责、agent 能替到哪一步」。

审查报告里遇到这些格子，写清「已有人负责 / 无人负责 / 由 agent 代做但缺人复核」，**不要把 agent 做过当成有人负责**。

| 角色项 | 谁负责 | agent 能替到哪一步 | 替不了的部分（必须人） |
| --- | --- | --- | --- |
| 上线前读完 AI 写的每一行 | 资深工程师 | 生成 diff 摘要、按风险分层指出重点、跑独立对抗审查 | 对「该不该上线」负责，签字 |
| 在第二个客户压垮之前设计数据模型 | 后端工程师 | 给候选 schema、约束与迁移方案、推演变更影响 | 选定模型并承担长期后果 |
| 解释 AI 修一个 bug 为什么造出两个 | 资深工程师 | 复现、二分定位、给根因证据链 | 判断根因结论是否成立 |
| 部署、回滚、服务器与云账单 | DevOps | 写流水线、跑回滚演练、拉成本明细 | 批准生产变更与预算 |
| 凌晨三点支付停了有人接页 | 值班人 | 告警聚合、runbook、初步定位 | 真的接电话并做决策 |
| 漏洞公开那周打框架补丁 | 安全 | 扫依赖、给升级方案与回归范围 | 决定停机窗口与风险接受 |
| 带审计师走一遍患者数据流向 | 安全与合规 | 画数据流、收集证据、对齐问卷 | 面对审计师作答与承诺 |
| 测 AI 声称测过的东西 | QA | 跑测试、留退出码与截图、做负对照 | 判断验收是否真的充分 |
| 在线库上跑迁移不丢一行 | 后端工程师 | 写迁移、隔离库演练、给回滚脚本 | 在生产执行并盯真实数据 |
| 对会弄坏另外三个功能的需求说不 | 技术负责人 | 列影响面与冲突证据 | 说「不」并承担业务后果 |
| 把「我本机能跑」变成「所有客户同时能跑」 | 架构师 | 压测、容量估算、给方案对比 | 选定架构与取舍 |
| AI 自己调不动时去调代码 | 资深工程师 | 取证、缩小范围、给假设与实验 | 在证据不足时做判断 |
| 一年后还记得为什么这么建 | 当初在场的人 | 写 ADR、维护接续文档 | 提供当时的业务上下文 |

## 对 agent 的三条硬含义

1. **不可逆动作前必须有人批准**（对应 AI-08）。agent 可以把方案、影响面、回滚步骤准备到可审阅，但生产变更、对外发布、数据破坏性操作的批准权不在 agent。
2. **agent 的「已验证」必须带可失败证据**。没有本轮命令与退出码、没有真实运行与截图的结论，一律标未验证——否则 QA 那一格等于空着。
3. **bus factor 不能靠 agent 补**。文档、权限、值班备份三项都要有第二个人能接手；只有 agent 知道怎么跑的系统，bus factor 仍然是 1。
