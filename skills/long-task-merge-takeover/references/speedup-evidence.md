## 2. 红轮根因与可避免性

- **v22 红＝硬编码计数假绿**：`skill-trigger-uniqueness.test.js` 写死 133，新增技能后真值 134。本可先跑该 targeted test（秒级）抓住，却烧了 27min 全量。修复＝派生目录全量真值（提交 `82cfcea`）。
- **v16–v20 红＝迭代缺陷-修-重跑循环**：每轮发现一个缺陷→修→重跑全量。若每次修后先跑最小复现集（秒级）确认，再批量进全量，可显著减少全量红轮。
- 共性：**拿 26min 全量套件当主缺陷检测循环**。全量套件应是「最终 HEAD 放行门」，不是「找缺陷的探针」。

## 3. ①②③④ 措施的本项目落地

- **① 快靶前置门**：改 `scripts/cua-cursor-guard.js` 先跑 `cua-cursor-guard.test.js`（130 条，秒级–分钟级），绿了再进全量；计数/契约类缺陷先用对应 targeted test 抓。批量字节改动（守卫＋CHANGELOG＋文档）落定后才跑最终 HEAD 全量（v23）。
- **② agent 轮次**：anti-polling（靠 Monitor/通知，曾反复重读日志浪费轮次）；reconcile 引用语法 cheat-sheet（`X.exit 为 N`、`X.log 为 N PASS、0 红`、点名段、一句一号，避免 22→2→0 试错）；升级测试 old/new 参数化（v3 写死 0.1.5/0.1.6 导致 v4 重生成）；计数派生真值。
- **③ 上下文 rot**：制作端会话 19.4MB、压缩 3 次 ⇒ 应早交接＋搬新会话；大输出（套件日志/扫描 JSON 89KB）落盘只带结论＋路径。
- **④ 流程摩擦**：发布/部署/清理授权开工一次预取（本轮 publish/cleanup 曾被 classifier 中途拦再重发）；stop-gate R13 误报按 §9 处理不空转；网络代理基线前置核验。
