# 超长任务合并接管与串行收口

把「多个互相阻塞的超长任务」合并成单会话串行推到底（收口→发布→部署），并把过程处理方式与踩坑沉淀成可复用范式。主线是跨项目通用流程与判据；某次具体任务的路径、读数与缺陷实例见 `references/`（按需读取，不常驻）。

## 0. 什么时候用

- 两个及以上超长任务各自占用会话，且**放行判据互相依赖**形成死锁（A 等 B 静默、B 等 A 停产）。
- 需要接管别的会话留下的分离进程、未提交改动、冻结 worktree，串行推到发布/部署。
- 复盘一条超长任务链，把「怎么处理、踩了什么坑」提炼成后续解决思路。

不适用：普通单步任务、无互锁的独立任务（直接各自推进，不必合并）。

## 1. 死锁判定与合并决策（范式起点）

**先证明死锁，再合并**，不要凭「任务很长」就合并：

1. 写出每个任务的**唯一放行判据**（不是模糊的「做完」）。例：B 批恢复判据 `QUIET_EXT`＝「A 批证据目录静默 ≥600s ＋ 工作区脏＝0」。
2. 找互锁环：A 持续产新候选并部署现役 ⇒ A 证据目录永不静默 ⇒ B 永远不放行 ⇒ B 占用的资源又挡 A。环成立才合并。
3. 合并方式＝**单会话串行**（写入收敛一个会话），不是并行加速。理由：互锁的根因是「两个写入者互相等对方静默」，并行只会加深互锁。
4. 合并前停原会话，但**保留其分离进程让它跑完**（其 `.exit` 往往正是接管后第一格判据）；只杀本会话进程树，先预览 PID＋负对照，不误杀并行会话。

正例：判据互锁环成立 → 合并单会话串行 → 死锁解除。
反例：把「任务长」当死锁 → 强行合并两个本可独立推进的任务 → 白白串行化、拖慢交付。

## 2. 接管盘点与继承真值核验

接管别的会话，**先核验现场真值，不采信摘要/队列声明**：

- 逐项盘点：分离进程（PID/起跑时间/写哪个目录）、未提交脏文件、冻结 worktree 钉在哪个 commit、哪些判据已绿哪些待跑。
- **继承真值要现读磁盘**：`.exit` 文件、套件 `SUMMARY`、`headStable`、字节哈希——摘要里的「已绿」只作线索，接管后必须重核（守卫字节可能已变，旧绿只作历史出处）。
- **分辨改动归属**：跑版本控制状态命令，区分「本轮改的」与「工作区本就有的/并行会话的」。不属于本会话的**不提交、不还原、不修改**；用户明确授权收口的批次除外。
- 主动中止 vs 崩溃要分清：主动中止（对抗审查抓出缺陷、被测字节要变）无需另查根因；异常崩溃必须先定位终止原因再续做。

## 3. 串行推进纪律

- **写入收敛单会话串行**；只读探索/取证可并行（只读子代理），但重活交子代理只要结论＋证据路径，不把大输出灌回上下文。
- **预算判断只在开工前**；开工后不许以预算为由停手，改「切小单元」继续（能独立验证＋独立提交的一格）。
- **不随意停止**：只有封闭例外清单（对外可见/不可逆/缺用户凭据或口径/需求缺失到写不出判据/同类修复连败三次/触红线）才停；其余按计划推到底，待裁决项列清单后继续做不依赖裁决的格子。
- **不重复问已答项**：同一对象/动作/环境/批次的授权按范围有效；计划级授权已覆盖逐文件决策时，不再逐条重问。
- 抑制 polling 冲动：长套件/后台任务靠 Monitor 或完成通知，**不反复重读日志浪费轮次**；退出码落盘后一次性现读。

## 4. 最终 HEAD 重跑与发布门槛

- **守卫/被测字节一变，旧套件绿只作历史出处**：所有源与文档提交落定后，把冻结 worktree 重钉到**真正的最终 HEAD**，在该树重跑全量套件＋出包门禁，全绿才发布。
- 发布是对外动作，需有效授权覆盖目标与批次；**完整全绿是推送/开 PR/部署/发布的硬门槛**（本地增量提交按影响面配比：一条能失败的判据＋相关测试）。
- 出包门禁逐道 exit 0；升级路径必须实测「上一版→新版」＋本地改动冲突保护，不能只过全新安装/单测。
- 下载件 sha256 必须与本地构建一致（分发产物字节一致/内容完整/干净环境消费）。

## 5. 三路合并部署（保留现役较新）

部署＝现役 vs 旧基线 vs 新包的三方分类，**逐文件定合并方式**：

- 现役==旧 pristine ⇒ UPDATE（采纳包内，无本地分歧才覆盖）。
- 现役与包内有分歧 ⇒ REVIEW_UPDATE（**逐字节保留本地**，不拿包内文本覆盖本地定制）。
- 现役==新包 ⇒ KEEP。
- `settings.json` 一律 KEEP（除非单独批准）；跨侧 junction 要验「确为链接且解析到同一真源」，不是「两侧一致」（合并后恒真）。
- 部署面外零触碰：改动/新增/删除件全部落在获准清单内；**运行时缓存件**（设备 token 缓存等）要显式排除并断言「排除件不在获准落地清单」＋负对照，不能靠排除洗白安装器落地件。
- 回滚料按内容核实：每个被覆盖件都能在恢复目录找到改前字节（prior-N/old-N，含整目录备份），不是「有没有文件」。

## 6. 有效验证纪律（每条断言都要能失败）

- **退出码取自磁盘 `.exit`，不经管道**（管道会吞退出码）；报「全绿」要能说出本轮命令、退出码、覆盖范围。
- **负对照**：判据写完先问「改动发生后它还能失败吗」。篡改一位哈希必判不符、幻影路径必判缺失、把获准路径换幻影名必判越界——证明断言不是恒真。
- **单变量机制证明**：负载 A/B 要 loaded 全绿、idle 全绿、只拧回一个变量必红且红全在该变量侧；不是「跑一遍绿了」就算证明。
- **改前红**：修复类先复现红（变异体/旧字节必红），再修，再绿；control 非空转绿 vs 全 revert 红＝0 vs 1。
- **字节核实**：分发/部署产物逐字节比对，目录型逐文件 walk；引用历史结果必须标出处（哪次提交/哪一轮）。
- 前台/用户可见变化必须「真跑＋实际截图」才算完成；拿不到截图显式标「未做视觉验证＋原因」。

## 7. 踩坑对策表（通用）

| 坑 | 根因 | 对策 |
|---|---|---|
| 硬编码计数判据假绿 | 断言写死旧基线数（如技能数 133），新增后真值变 134 | 改「现算真值」（目录全量/同一来源），保留可失败性；不是放宽 |
| 对账器引用语法误判 | 文档引用用了 parser 读不懂的格式（`pass=N fail=M`、`N/M` 比值、裸 `VERDICT=`、通配文件名） | 用对账器认的语法（`X.exit 为 N`、`X.log 为 N PASS、0 红`、点名段、一句一号）；先跑对账到 CONSISTENT |
| 运行时缓存件误判越界 | 设备 token 缓存被客户端刷新，不在 catalog | 显式 EXCLUDE_ROOT_FILES＋「排除件∉获准清单」断言＋负对照 |
| 套件中断当崩溃查 | 实为主动中止（字节要变） | 先分清主动中止 vs 崩溃；主动中止无需另查根因 |
| 重跑当修复 | 同一手段重跑绿了但根因未明 | 先定位根因再修；连败两次升级怀疑层级（环境/语言/账号/数据/版本），三次停手上报 |
| 机制 vs 授权冲突 | stop-gate 把三路部署误判成文本合并，要求重开已授权决策 | 机制是执行约束非授权来源；只暂停受限动作、报告差异，不按机制错误目标落地、不重复问已答项 |
| 网络/代理残留 | 隐藏启动的代理改了系统代理位 | 恢复无代理基线（ProxyEnable=0＋停 GUI/Core，helper 不动），只读核实端口静默 |

## 8. 反例边界（不做什么）

- 不为凑绿放宽判据或抬预算；不把「重新跑一次」当修复。
- 不 `git add -A`/`.`；只加明确路径；不提交/还原/修改并行会话改动。
- 不动已发布 tag；不动属并行会话的 worktree；移除冻结 worktree 用显式单条路径。
- 不凭摘要宣布完成；继承真值现读磁盘。
- 不把机制（hook/stop-gate）当授权来源去重开已授权完成的工作。

## 9. 机制 vs 授权冲突处理

stop-gate/hook 是 fail-open 的执行约束，**不替代平台权限、不是授权来源**。当机制要求与用户已授权完成的状态冲突时：只暂停受限动作、报告差异、不按机制的错误目标落地；不重复问已答项、不重开已授权决策。真实权限拒绝不换工具/身份/通道绕过。

## 10. 提速与耗时分解

超长任务的时间通常不在算力，而在**红轮白跑、agent 轮次浪费、上下文 rot、流程摩擦**。先量化分解耗时再优化，别凭感觉提速。

**先量化**：把全量套件/构建的每轮耗时与红绿落盘统计（轮数 × 单轮时长、红轮占比）。红轮＝没产出可发布结果的白跑，是最高杠杆。实例：一次合并任务 11 轮全量套件 ≈4.6h，其中 6 轮红 ≈2.6h 白跑（见 `references/speedup-evidence.md`）。

**① 砍套件红轮（最高杠杆）**：

- 快靶前置门：改哪个文件先跑它的 targeted test（秒级），绿了再进全量套件（几十分钟）。别拿全量套件当主缺陷检测循环。
- 批量字节改动后才跑最终 HEAD 全量；不要改一处跑一次。
- 红轮先跑最小复现集定位根因，不盲目重跑全量（重跑 ≠ 修复）。

**② 砍 agent 轮次浪费**：

- anti-polling：长任务靠 Monitor/完成通知，不循环重读日志；退出码落盘后一次性现读。
- 对账/校验器语法预先文档化（cheat-sheet），避免引用格式试错。
- 测试版本参数化（old/new 作 argv），不写死字面量导致重生成。
- 计数断言派生真值（目录全量/同一来源），不硬编码基线数。

**③ 砍上下文 rot**：

- 会话 ≥15MB 或压缩 ≥2 次就早交接＋搬新会话，不在 rot 上下文硬撑。
- 大输出（日志/子代理报告/网络）落盘，只带结论＋证据路径回上下文。

**④ 砍流程摩擦**：

- 发布/部署/清理授权开工时一次预取，避免中途 classifier 拦再重发。
- 机制 vs 授权冲突按 §9 处理，不反复辩解空转。
- 网络/代理基线前置核验，别等连不上才排错。

正例：红轮先跑秒级靶测试抓住硬编码计数缺陷 → 省下一轮 27min 全量。
反例：每改一处就跑全量套件、反复重读日志等结果 → 算力与轮次双重浪费。
