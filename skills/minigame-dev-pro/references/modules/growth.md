# 用户增长引擎

## 微信生态内合规增长策略总览

### 增长来源分类

| 来源 | 成本 | 可控性 | 天花板 | 适合阶段 |
|------|------|--------|--------|---------|
| 微信搜索 | 零 | 低（靠排名） | 中 | 全阶段 |
| 社交分享 | 零 | 中（靠设计） | 高 | 产品验证后 |
| 群排行/社交 | 零 | 中 | 中 | 有社交玩法时 |
| 小程序跳转 | 零-低 | 中 | 中 | 有矩阵时 |
| 订阅消息 | 零 | 高 | 低（频率限制） | 有留存基础后 |
| 公众号/视频号 | 零-低 | 高 | 中 | 有内容能力时 |
| 微信广告买量 | 高 | 高 | 高 | 企业+ROI正 |
| 外部引流 | 中-高 | 中 | 高 | 有预算时 |

### 核心原则

1. **产品不行别推** — 次留<25%时做增长=往漏桶里倒水
2. **合规第一** — 微信对违规分享奖励/强制关注打击极严，一次违规可能封号
3. **先验证再放量** — 小范围测试→数据OK→逐步放量
4. **自然流量是基础** — 买量只是放大器，不是救命药

## 自然流量获取

### 1. 微信搜索优化

```
用户行为：微信 → 下拉/搜索 → 输入关键词 → 看到小游戏

优化点：
├── 游戏名称
│   ├── 包含品类关键词（"消除""合成""跑酷"）
│   ├── 好记好搜（别用生僻字/英文）
│   ├── 不要和热门游戏撞名（搜不到你）
│   └── 名称确定后不能改（软著绑定）→ 慎重
│
├── 简介/描述
│   ├── 第一句话包含核心关键词
│   ├── 写清楚"这是一个什么游戏"
│   └── 加入用户会搜的词（"打发时间""益智""休闲"）
│
├── 类目选择
│   ├── 选最精准的类目（不要选大类蹭流量）
│   └── 类目影响搜索排名权重
│
└── 权重因素（微信未公开，经验总结）
    ├── DAU越高排名越前
    ├── 留存好权重高
    ├── 分享量大有加权
    └── 新上线有短期流量扶持（约7天）
```

### 2. 分享卡片优化

分享卡片是社交传播的第一触点，决定别人点不点：

| 元素 | 要求 | 优化技巧 |
|------|------|---------|
| 标题 | ≤22字 | 制造好奇/挑战/炫耀（"我在第37关卡了3天"） |
| 图片 | 5:4比例，≤128KB | 用游戏内高光截图/成绩图，不要纯文字 |
| 描述 | 辅助信息 | 补充说明+行动引导 |

```typescript
// 分享配置代码
wx.shareAppMessage({
    title: '我在「示例消除」里合出了最大西瓜！你能超过我吗？',
    imageUrl: '资源服务器/share/score_1000.png', // 动态生成成绩图
    query: 'from=share&uid=12345&score=1000'  // 回流参数
});

// 监听分享结果（注意：微信不再回调分享成功/失败）
wx.onShareAppMessage(() => ({
    title: this.getShareTitle(),  // 动态标题
    imageUrl: this.getShareImage() // 动态图片
}));
```

### 3. 群排行/社交关系

```
合规用法：
- 好友排行榜（用wx.getFriendCloudStorage）
- 群内排行（用wx.getGroupCloudStorage）
- 超越好友提醒（"你超过了张三，排名第3"）
- 群挑战（"本群最高分5000，你能打破吗？"）

技术实现：
- 开放数据域（子域）渲染排行榜
- 主域不能直接读取好友数据（隐私限制）
- 通过子域Canvas绘制排行UI
```

### 4. 小程序/小游戏跳转

```
合规跳转方式：
- 自己的小程序矩阵互跳（同主体）
- 游戏内"更多游戏"入口（需申请跳转权限）
- 小程序关联（后台设置，最多关联50个）

限制：
- 不能跳转到竞品
- 跳转需要用户主动点击（不能自动跳）
- 个人主体跳转能力有限
```

## 社交裂变合规设计

### 可以做 vs 不能做

| 行为 | 合规判断 | 说明 |
|------|---------|------|
| 分享后获得游戏内奖励（金币/道具） | ❌ 违规 | "分享后无任何深度互动即得奖励"属违规分享奖励；稳妥做法是分享不绑定任何奖励 |
| 邀请好友一起玩（双方得奖励） | ⚠️ 谨慎 | 仅当奖励与被邀请者的"深度互动"（组队/协作）绑定且规则清晰时处于合规边界，否则按违规处理；建议以官方最新规范为准 |
| 好友排行榜 | ✅ 可以 | 用官方开放数据域API |
| 群挑战/群PK | ✅ 可以 | 自愿参与，不强制 |
| 分享解锁新关卡 | ❌ 违规 | 分享解锁任何内容均属强制分享 |
| 生成成绩图/海报分享 | ✅ 可以 | 用户主动选择分享，不绑定奖励 |
| "分享到3个群才能继续玩" | ❌ 违规 | 强制分享=违规分享奖励 |
| "分享后100%获得iPhone" | ❌ 违规 | 虚假奖励 |
| "不分享就扣除已有奖励" | ❌ 违规 | 胁迫性分享 |
| 分享后弹窗"再分享到5个群" | ❌ 违规 | 连续引导分享 |
| 用现金/现金奖励引导分享 | ❌ 违规 | 直接封号 |
| 强制关注公众号才能玩 | ❌ 违规 | 封号 |
| 自动发送消息到群 | ❌ 违规 | 技术上也做不到 |
| 分享后实际不给奖励 | ❌ 违规 | 欺骗用户，举报后封号 |

### 合规裂变设计模板

```
正确姿势：分享是"可选的加速器"，不是"必须的门槛"，且分享不绑定任何游戏内奖励

示例1（消除游戏）：
- 正常路径：打关卡 → 获得金币 → 买道具
- 主动分享：通关/破纪录时分享成绩卡片 → 好友可见（无任何游戏内奖励）

示例2（合成游戏）：
- 正常路径：合成 → 升级 → 解锁新物品
- 社交对比：好友排行榜（开放数据域）→ 排名对比，好友点击挑战

示例3（解谜游戏）：
- 正常路径：解谜 → 看提示（看广告）→ 继续
- 社交求助：分享关卡求助卡给好友 → 好友看到提示（求助者无游戏内奖励，也可看广告获得提示）

关键原则：
1. 不分享也能正常游戏（分享是加分项不是必选项）
2. 分享行为不绑定任何游戏内奖励（金币/道具/体力/续命等一律禁止）
3. 不限制分享次数但不鼓励刷屏
4. 分享文案不能暗示"必须分享"或"分享得奖励"
```

### 违规后果

| 违规等级 | 处罚 | 恢复时间 |
|---------|------|---------|
| 轻微（首次） | 警告+限制分享能力7天 | 7天 |
| 中度 | 暂停分享能力30天 | 30天 |
| 严重 | 下架+暂停服务7-30天 | 30天+ |
| 极严重（多次/恶意） | 永久封号 | 不可恢复 |

## 订阅消息策略

### 基本规则

| 项目 | 说明 |
|------|------|
| 触发条件 | 用户主动点击按钮授权（不能静默获取） |
| 消息类型 | 一次性订阅（点一次发一条）/ 长期订阅（仅政务/医疗等） |
| 小游戏可用 | 一次性订阅消息（每次点击=1次发送机会） |
| 频率限制 | 用户点N次=你最多发N条（不是无限发） |
| 内容限制 | 必须用审核通过的模板，不能自定义内容 |

### 适用场景

| 场景 | 模板示例 | 触发时机 |
|------|---------|---------|
| 体力恢复 | "你的体力已恢复满，快来继续闯关！" | 体力回满时 |
| 好友超越 | "你的好友张三超过了你的分数！" | 被超越时 |
| 活动开始 | "限时活动「春节大作战」已开启！" | 活动上线时 |
| 每日提醒 | "今日签到奖励已刷新，登录即可领取" | 每日固定时间 |
| 建造完成 | "你的城堡已建造完成，快来查看！" | 计时器到期时 |

### 实施要点

```typescript
// 请求订阅（必须在用户点击事件中调用）
onButtonClick() {
    wx.requestSubscribeMessage({
        tmplIds: ['template_id_1', 'template_id_2'], // 最多3个
        success(res) {
            // res['template_id_1'] === 'accept' 表示用户同意
            if (res['template_id_1'] === 'accept') {
                // 记录：这个用户有1次发送机会
                server.addSubscribeChance(userId, 'energy_full');
            }
        },
        fail(err) {
            // 用户拒绝或关闭了弹窗
            // 不要反复弹（体验差），下次自然触发再请求
        }
    });
}

// 服务端发送（有发送机会时）
// POST 第三方平台/cgi-bin/message/subscribe/send
{
    "touser": "openid",
    "template_id": "template_id_1",
    "page": "pages/index/index",  // 点击消息跳转的页面
    "data": {
        "thing1": { "value": "体力已恢复" },
        "time2": { "value": "2026-07-10 14:00" },
        "thing3": { "value": "快来继续你的冒险吧！" }
    }
}
```

### 订阅消息优秀实践

1. **触发时机自然化** — 在"体力恢复等待中""关卡失败后""退出游戏前"请求订阅
2. **不要一进来就弹** — 用户还没玩就让他订阅=打扰
3. **一次请求多个模板** — 一次最多3个，减少弹窗次数
4. **消息内容有价值** — 不是骚扰，是"你等的东西好了"
5. **控制频率** — 同一用户一天最多收1-2条，多了会被屏蔽

## 买量指导（企业开发者）

### 前提条件

- 必须是企业主体（个人不能投微信广告）
- 必须有已上线的游戏（不能给未上线的投）
- 必须有正向ROI预期（否则就是烧钱）
- 建议先有自然量验证产品（次留>30%再投）

### CPA参考（2026年）

| 品类 | CPA范围 | 说明 |
|------|---------|------|
| 休闲消除 | 5-15元 | 量大但用户质量参差 |
| 合成/放置 | 8-20元 | 中等 |
| 模拟经营 | 10-25元 | 用户质量较好 |
| 中重度RPG | 20-50元 | 需要精准定向 |
| 棋牌/竞技 | 15-30元 | 竞争激烈 |

### ROI计算

```
投放ROI = 用户LTV / CPA

用户LTV（生命周期价值）= 人均日收入 × 平均生命周期天数

示例：
- CPA = 10元
- 人均日广告收入 = 0.15元（DAU收入/DAU）
- 平均生命周期 = 30天（留存曲线积分）
- LTV = 0.15 × 30 = 4.5元
- ROI = 4.5 / 10 = 0.45（亏损）

结论：这个产品不适合买量（LTV < CPA）

什么时候适合买量：
- ROI > 1.0（赚）
- ROI 0.7-1.0（微亏但能接受，靠自然量补）
- ROI < 0.7（不要投，先优化产品）
```

### 投放渠道

| 渠道 | 特点 | 适合 |
|------|------|------|
| 微信广告（朋友圈/公众号/小程序） | 精准、贵、量大 | 中重度/高LTV产品 |
| 巨量引擎（抖音系） | 量大、便宜、质量一般 | 休闲游戏跑量 |
| 广告平台B（平台生态） | 和微信生态打通 | 微信小游戏首选 |
| 广告平台C | 下沉市场 | 休闲/棋牌 |
| 广告平台D | 搜索意图 | 特定品类 |

### 投放素材要点

```
高转化素材特征（休闲游戏）：
1. 前3秒展示核心玩法（不要放logo动画）
2. 展示"差一点就成功"的画面（激发尝试欲）
3. 真人试玩 > 纯录屏 > 纯动画
4. 时长15-30秒（太长没人看完）
5. 结尾明确行动指令（"点击立即玩"）

素材迭代频率：
- 每周至少3套新素材
- 单套素材生命周期约7-14天（之后衰减）
- 跑量素材特征：CTR>3%，转化率>10%
```

## 增长实验框架

### 实验流程

```
第1步：提出假设
格式：如果我们[做什么]，那么[哪个增长指标]会提升[X%]，因为[原因]

示例假设库：
- "如果分享卡片用动态成绩图，分享点击率会提升30%，因为个性化内容更吸引"
- "如果在第3关失败后弹出好友求助，分享率会提升20%，因为失败时有社交动力"
- "如果加入每日签到，7留会提升5个百分点，因为给了每天回来的理由"

第2步：设计实验
- 实验组/对照组怎么分
- 核心指标是什么（只能有1个）
- 护栏指标是什么（不能变差的）
- 需要多少样本/跑多久

第3步：执行
- 最小可行改动（不要为了一个实验重构代码）
- 灰度发布（先10%用户→50%→全量）
- 埋点确认数据在正确收集

第4步：测量
- 实验周期内每天看数据（但不提前下结论）
- 排除外部因素（节假日/大版本更新/竞品事件）
- 统计显著性检验（p<0.05才算显著）

第5步：决策
- 显著正向 → 全量上线 + 记录到知识库
- 不显著 → 不上线 + 分析为什么没效果
- 显著负向 → 回滚 + 反思假设哪里错了
- 无论结果 → 提出下一个假设（增长是持续实验）
```

### 增长实验优先级排序（ICE模型）

| 实验 | Impact(1-10) | Confidence(1-10) | Ease(1-10) | 总分 | 排序 |
|------|-------------|-----------------|-----------|------|------|
| 优化分享卡片 | 7 | 6 | 9 | 22 | 1 |
| 加每日签到 | 6 | 8 | 8 | 22 | 1 |
| 好友排行榜 | 8 | 5 | 5 | 18 | 3 |
| 群挑战玩法 | 9 | 4 | 3 | 16 | 4 |

- Impact：对核心指标影响多大
- Confidence：你有多确信会有效
- Ease：实现难度（10=极简单，1=极复杂）

## 个人开发者零成本增长策略

### 第一阶段：产品内置增长（开发时就做好）

```
必做清单：
□ 分享卡片精心设计（标题+图片，至少做3版轮换）
□ 游戏内自然分享点（通关/破纪录/获得稀有物品时）
□ 好友排行榜（开放数据域）
□ 群排行（群内竞争）
□ 分享入口（仅用户主动触发，分享不绑定任何奖励）
□ 游戏名称包含搜索关键词
□ 简介写好（包含用户会搜的词）
```

### 第二阶段：上线后冷启动（第1-2周）

```
具体操作：
1. 自己的微信群（家人群/朋友群/同事群）
   - 不要直接甩链接（会被踢）
   - 先说"我做了个小游戏，帮我试试给个反馈"
   - 目标：获得前50个种子用户+真实反馈

2. 朋友圈
   - 发开发过程（"做了3个月终于上线了"）
   - 发有趣的游戏截图/成绩
   - 不要天天发（一周1-2次）

3. 相关社区
   - 即刻/小红书/V2EX/独立开发者社区
   - 分享开发故事（不是硬广）
   - "独立开发者做了个XX游戏，求体验反馈"

4. 微信搜索
   - 确保名称/简介/类目都优化过
   - 上线第一周有流量扶持，确保产品体验好
```

### 第三阶段：数据驱动增长（第3周起）

```
如果次留>30%：
- 产品OK，重点做分享优化
- 分析分享数据：哪个场景分享最多？回流率多少？
- 优化分享卡片（A/B测试标题和图片）
- 增加社交玩法（好友挑战/群PK）

如果次留<30%：
- 别推了，先改产品
- 参考 analytics.md 诊断问题
- 改到次留>25%再考虑增长

如果分享率>10%但回流<10%：
- 卡片有问题（别人看到了但不想点）
- 换标题/换图片/换描述
- 测试"挑战型"vs"炫耀型"vs"求助型"文案

如果分享率<5%：
- 分享入口不够明显/分享动力不足
- 在情绪高点提供分享入口（刚破纪录/刚通关/刚获得稀有物品），分享不绑定奖励
- 用"炫耀型/挑战型"卡片文案提升主动分享率
```

### 第四阶段：规模化（DAU>1000后）

```
可以考虑：
1. 小程序矩阵
   - 做2-3个同品类小游戏
   - 游戏内"更多游戏"互跳
   - 共享用户池

2. 公众号/视频号
   - 发游戏攻略/趣味视频
```
