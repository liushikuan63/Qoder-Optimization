## 一、广告变现策略

### 1.1 广告类型优先级

```
收益贡献排序：激励视频 > 插屏广告 > 格子广告 > Banner广告
```

| 广告类型 | eCPM（元） | 日展示上限建议 | 收益占比目标 | 用户体验影响 |
|---------|-----------|--------------|-------------|-------------|
| 激励视频 | 40-120 | 不限（用户主动） | 60-70% | 极低 |
| 插屏广告 | 15-40 | ≤5次/用户/日 | 20-25% | 中等 |
| 格子广告 | 5-15 | 按页面展示 | 5-10% | 低 |
| Banner | 3-10 | 持续展示 | 3-5% | 低（但收益低） |

### 1.2 eCPM优化策略

| 优化方向 | 具体方法 | 预期提升 |
|---------|---------|---------|
| 提升点击率 | 广告位放在自然停顿点 | +10-20% |
| 提升完播率 | 激励视频奖励有吸引力 | +15-30% |
| 增加竞价 | 开启多渠道广告聚合 | +20-40% |
| 时段优化 | 晚8-11点广告价值最高 | +10-15% |
| 用户分层 | 高价值用户少展示广告 | 长期LTV提升 |
| 频次控制 | 避免广告疲劳 | 减少卸载 |

### 1.3 广告位设计原则

```markdown
### 核心原则：广告是服务，不是打扰

**DO（应该）：**
- ✅ 放在自然停顿点（关卡结束、暂停、结算）
- ✅ 激励视频给用户明确收益
- ✅ 广告与内容有视觉区分
- ✅ 提供关闭/跳过选项（非激励类）
- ✅ 加载失败时静默处理
- ✅ 首次体验前3分钟不展示广告

**DON'T（不应该）：**
- ❌ 遮挡核心操作区域
- ❌ 突然弹出（无预兆）
- ❌ 强制观看（非激励视频）
- ❌ 连续展示多个广告
- ❌ 广告面积>屏幕50%
- ❌ 误导点击（伪装成游戏按钮）
```

### 1.4 广告聚合方案

| 方案 | 说明 | 适用阶段 |
|------|------|---------|
| 微信原生广告 | 默认方案，接入简单 | 初期 |
| 多平台聚合 | 微信+多家广告平台 | DAU>1万 |
| 程序化竞价 | 多广告源实时竞价 | DAU>5万 |

## 2026年变现格局变化（重要更新）

### 核心数据

> 与 references/knowledge/market-data.md「变现结构」同源（微信公开课披露，需实时验证），此处仅摘要引用避免双份维护漂移。

- IAP（内购）月活用户：3亿
- IAA（广告）月活用户：4亿
- 内购收入占比：已达68%（超过广告）
- 2026年IAP首发新游激励上限：400万元
- iOS平台：将接入苹果IAP支付能力

### 趋势判断
- 纯广告模式（IAA）天花板明显
- 混合变现（IAP为主+IAA为辅）成为主流
- 从"流量生意"转向"内容生意"
- 头部产品路径：小游戏验证→APP放量→PC端增量

### 对个人开发者的影响
- 个人开发者目前仍以广告变现为主
- 但需密切关注平台政策变化（内购门槛可能降低）
- 建议：即使现在做纯广告，也要在设计时预留内购接口
- 广告+轻度内购（去广告、皮肤）是个人开发者的最优解

### 广告变现优化（2026年）
- AI生成广告素材成本降至传统1/10
- 巨量引擎全域智能投放（UBA）等AI投放工具在广告消耗中的占比持续提升（以官方最新数据为准）
- 素材必须与实际玩法一致（2026年新规，不一致会被处罚）
- 激励视频仍是eCPM最高的广告形式
- 广告面积不超50%、不遮挡核心操作（不变）

### 内购设计要点（企业/有版号）
- 首充设计：高价值感、低门槛（6元档）
- 月卡/通行证：稳定收入来源
- 皮肤/装饰：不影响平衡的付费点
- 去广告：最自然的内购理由
- 随机抽取：必须公示概率（合规红线）

## 二、激励视频场景设计

### 2.1 高转化场景

| 场景 | 触发时机 | 奖励设计 | 预期转化率 |
|------|---------|---------|-----------|
| 复活/续命 | 游戏失败时 | 原地复活1次 | 40-60% |
| 双倍奖励 | 结算页面 | 本局金币×2 | 30-50% |
| 解锁道具 | 道具不足时 | 获得1次使用道具 | 25-40% |
| 随机抽取 | 每日免费次数用完 | 额外1次随机抽取机会 | 35-55% |
| 跳过等待 | 建造/冷却倒计时 | 立即完成 | 20-35% |
| 额外体力 | 体力不足时 | 恢复5点体力 | 30-45% |
| 每日签到加倍 | 签到页面 | 今日奖励×2 | 20-30% |
| 解锁皮肤试用 | 皮肤商城 | 试用24小时 | 15-25% |

### 2.2 场景设计原则

```markdown
### 激励视频设计四原则：

1. **价值感明确**
   - 用户一眼看出"看了能得到什么"
   - 奖励价值 > 用户时间成本感知
   - 示例："观看视频 → 获得500金币（约等于3关收入）"

2. **时机自然**
   - 在用户"想要但得不到"的时刻出现
   - 不打断正在进行的操作
   - 示例：失败时想继续 → 提供复活选项

3. **频率克制**
   - 同一场景每日触发≤3次
   - 不同场景间隔≥2分钟
   - 用户主动选择，永不强制

4. **反馈即时**
   - 视频播完→奖励立即到账
   - 有明确的"奖励已发放"动效
   - 中途关闭→明确提示"未获得奖励"
```

### 2.3 激励视频代码要点

```javascript
// 关键逻辑检查清单
// 1. 预加载（提前加载，减少等待）
// 2. 播放前确认（用户点击→确认→播放）
// 3. 完播回调（onClose中判断isEnded）
// 4. 失败降级（加载失败→隐藏入口/给安慰奖）
// 5. 频率控制（本地记录今日观看次数）
// 6. 奖励发放（仅isEnded=true时发放）
```

## 三、广告合规红线

### 3.1 硬性规则（违反=处罚）

| # | 红线 | 具体标准 | 违规后果 |
|---|------|---------|---------|
| 1 | 广告面积 | ≤ 屏幕面积的50% | 警告→下架 |
| 2 | 核心功能遮挡 | 广告不可遮挡核心操作按钮 | 警告→下架 |
| 3 | 激励视频频率 | 同一场景每日≤3次/用户 | 警告 |
| 4 | 强制观看 | 非激励广告必须可关闭 | 警告→下架 |
| 5 | 误导点击 | 不可伪装成游戏功能按钮 | 下架 |
| 6 | 首次体验 | 首次进入前60秒不弹广告 | 警告 |
| 7 | 关闭按钮 | 关闭按钮清晰可见、可点击 | 警告 |
| 8 | 广告内容 | 不展示违规/虚假广告 | 下架→封号 |

### 3.2 软性建议（影响审核/体验）

| 建议 | 说明 |
|------|------|
| 前3关无广告 | 让新用户先体验核心乐趣 |
| 广告间隔≥60秒 | 避免连续弹出 |
| 插屏≤5次/日 | 超过用户会流失 |
| Banner不常驻 | 仅在非游戏页面展示 |
| 广告失败静默 | 不弹错误提示 |

## 四、内购设计（企业主体）

### 4.1 付费点设计

| 付费点 | 定价区间 | 设计要点 | 适用类型 |
|--------|---------|---------|---------|
| 去广告 | 6-12元 | 一次性，永久去除非激励广告 | 所有 |
| 首充礼包 | 1-6元 | 超值感，降低首次付费门槛 | 中重度 |
| 月卡/周卡 | 6-30元/月 | 每日领取，提升留存 | 所有 |
| 道具包 | 1-30元 | 消耗品，重复购买 | 中重度 |
| 皮肤/装饰 | 6-68元 | 纯外观，不影响平衡 | 有社交的 |
| 通行证/赛季 | 30-68元/季 | 阶梯奖励，长线目标 | 中重度 |
| 体力/次数 | 1-6元 | 小额高频 | 有体力系统 |

### 4.2 定价策略

```markdown
### 定价原则：
1. **锚定效应**：先展示高价礼包，再展示常规价格
2. **小额起步**：首充1-6元，降低决策门槛
3. **价值对比**：付费内容 vs 免费获取时间对比
4. **梯度设计**：1元→6元→30元→68元→128元
5. **限时优惠**：新手期/节日折扣（需真实）

### 定价禁忌：
- ❌ 不付费无法通关（Pay to Win过度）
- ❌ 虚假折扣（先涨价再打折）
- ❌ 引导未成年人不当消费（"告诉爸爸妈妈买"）
- ❌ 隐藏扣费（自动续费不明确）
- ❌ 概率不公示（付费随机抽取）
```

### 4.3 首充设计模板

```markdown
### 首充礼包设计：
- 价格：1元 / 6元
- 触发：首次进入游戏24小时内
- 内容：
  - 等值钻石/金币
  - 限定道具（首充专属）
  - 去广告体验卡（3天）
  - 额外体力×5
- 展示：主界面醒目位置，倒计时营造紧迫感
- 限制：仅限购买1次
```

### 4.4 月卡设计模板

```markdown
### 月卡设计：
- 价格：6元/月 或 30元/月
- 权益：
  - 购买即得：X钻石
  - 每日领取：Y金币 + Z体力
  - 专属标识：月卡用户头像框
  - 额外特权：每日1次免费随机抽取
- 总价值：约为直接购买的3-5倍
- 续费：到期前3天提醒，不自动扣费
```

## 五、收益预估模型

### 5.1 广告收益公式

```
日广告收入 = DAU × 人均广告展示次数 × eCPM / 1000

其中：
- DAU：日活跃用户数
- 人均广告展示次数：激励视频+插屏+Banner
- eCPM：每千次展示收入（元）
```

### 5.2 分类型计算

```
日激励视频收入 = DAU × 激励视频人均次数 × 激励视频eCPM / 1000
日插屏收入 = DAU × 插屏人均次数 × 插屏eCPM / 1000
日Banner收入 = DAU × Banner展示次数 × Banner eCPM / 1000

日总广告收入 = 激励视频 + 插屏 + Banner
月总收入 = 日总收入 × 30
```

### 5.3 预估示例

| 参数 | 保守 | 中等 | 乐观 |
|------|------|------|------|
| DAU | 1,000 | 10,000 | 100,000 |
| 激励视频人均次数 | 2次 | 3次 | 4次 |
| 激励视频eCPM | 50元 | 70元 | 100元 |
| 插屏人均次数 | 2次 | 3次 | 4次 |
| 插屏eCPM | 20元 | 25元 | 35元 |
| **日收入** | **380元** | **2,850元** | **54,000元** |
| **月收入** | **11,400元** | **85,500元** | **1,620,000元** |

> ⚠️ 以上为纯公式计算示例（DAU×人均次数×eCPM×30），仅用于演示计算逻辑，**不构成任何收益承诺**。实际收入受留存、广告单价、填充率、市场变化、平台政策等因素影响，可能远低于示例值。所有数值使用前须通过官方数据助手实时验证。

### 5.4 内购收益公式（企业）

```
日内购收入 = DAU × 付费率 × ARPPU

其中：
- 付费率：通常1-5%（休闲游戏）
- ARPPU：每付费用户平均收入

月内购收入 = DAU × 付费率 × ARPPU × 30
开发者实际收入 = 月内购收入 × 60%（扣除平台40%分成）
```

### 5.5 综合收益模型

```
月总收入 = 广告月收入 + 内购月收入 × 60%

关键指标健康度：
- ARPDAU（每DAU日收入）> 0.3元 → 健康
- 广告占收入比 < 80% → 结构合理（有内购时）
- LTV > CPA × 1.5 → 可买量
```

## 七、数据监控重点

### 7.1 每日必看（5分钟）

| 指标 | 健康范围 | 异常处理 |
|------|---------|---------|
| DAU | 波动≤20% | 骤降→检查服务器/版本/渠道 |
| 新增用户 | 稳定或增长 | 骤降→检查分享/搜索入口 |
| 次日留存 | ≥30%（休闲） | <20%→检查新手体验 |
| 崩溃率 | <1% | >2%→紧急排查 |
| 广告收入 | 稳定 | 骤降→检查广告配置/eCPM |
| 平均时长 | ≥5分钟 | 骤降→检查内容/难度 |

### 7.2 每周必看（30分钟）

| 指标 | 分析维度 | 行动 |
|------|---------|------|
| 7日留存 | 趋势变化 | 下降→优化中期内容 |
| 关卡通过率 | 逐关分析 | 某关过低→调整难度 |
| 广告eCPM | 分类型/分时段 | 优化展示策略 |
| 分享率 | 分享→回流转化 | 优化分享激励 |
| 用户反馈 | 分类统计 | 高频问题→排入迭代 |
| 竞品动态 | 新功能/活动 | 评估是否跟进 |

### 7.3 每月必看（2小时）

| 指标 | 分析维度 | 行动 |
|------|---------|------|
| 30日留存 | 长期趋势 | 评估产品生命周期 |
| LTV | 用户生命周期价值 | 指导买量预算 |
| 收入结构 | 广告/内购占比 | 优化变现策略 |
| 用户画像 | 年龄/地域/设备 | 调整运营方向 |
| 流失分析 | 流失节点/原因 | 针对性挽留 |
| ROI | 投入产出比 | 调整资源分配 |
| 版本效果 | 更新前后对比 | 评估迭代方向 |

### 7.4 数据看板建议

```markdown
### 核心看板（每日打开）：
┌─────────────────────────────────────────┐
│  DAU: _____  新增: _____  留存: _____%  │
│  收入: ¥_____  eCPM: ¥_____           │
│  崩溃率: _____%  平均时长: _____min     │
└─────────────────────────────────────────┘

### 告警规则：
- DAU日环比下降>30% → 立即告警
- 崩溃率>2% → 立即告警
- 广告收入日环比下降>50% → 当日告警
- 次留<20% → 周报告警
```

### 8.2 反馈分类与响应

| 类型 | 响应时限 | 处理方式 | 负责人 |
|------|---------|---------|--------|
| 崩溃/闪退 | 4小时 | 紧急修复→热更新 | 技术 |
| 功能Bug | 24小时 | 排入最近版本 | 技术 |

| 投诉/不满 | 24小时 | 安抚+解决方案 | 运营 |
| 好评/鼓励 | 可选 | 感谢回复 | 运营 |
| 违规举报 | 2小时 | 核实→处理 | 合规 |

### 8.3 反馈处理SOP

```
收到反馈
  ↓
Step 1: 分类（Bug/建议/投诉/好评）
  ↓
Step 2: 评估严重度
  - P0（崩溃/数据丢失）→ 4小时响应
  - P1（功能异常）→ 24小时响应
  - P2（体验问题）→ 3天响应
  - P3（优化建议）→ 排入迭代
  ↓
Step 3: 回复用户
  - 感谢反馈
  - 说明处理计划
  - 给出预期时间
  ↓
Step 4: 内部跟进
  - 创建任务单
  - 指定负责人
  - 跟踪修复进度
  ↓
Step 5: 闭环
  - 修复后通知用户（如可能）
  - 记录到知识库
  - 分析是否有系统性问题
```

### 8.4 差评应对策略

```markdown
### 差评处理原则：
1. 24小时内回复（态度诚恳）
2. 不辩解、不推卸
3. 给出具体解决方案和时间
4. 修复后主动告知

### 回复模板：
"感谢您的反馈！我们已关注到[具体问题]，
计划在[时间]的版本更新中修复。
给您带来不好的体验非常抱歉，
我们会持续优化。如有其他问题欢迎随时反馈！"
```

## 九、版本迭代策略

### 9.1 迭代优先级矩阵

| 优先级 | 类型 | 示例 | 决策标准 |
|--------|------|------|---------|
| P0 | 紧急修复 | 崩溃/数据丢失/安全漏洞 | 影响>10%用户 |
| P1 | 核心优化 | 性能/核心玩法体验 | 影响留存 |
| P2 | 功能迭代 | 新关卡/新玩法/新活动 | 提升留存/收入 |
| P3 | 体验优化 | UI美化/动效/文案 | 提升满意度 |
| P4 | 技术债务 | 代码重构/架构优化 | 长期健康 |

### 9.2 版本规划模板

```markdown
## 版本规划 v[X.Y.Z]

### 版本目标

- 量化指标：[具体数字]

### 功能清单
| # | 功能 | 优先级 | 预计工时 | 状态 |
|---|------|--------|---------|------|
| 1 |      | P1     |         |      |

### 风险评估
| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
|      |      |      |      |

### 时间计划
- 开发：MM/DD - MM/DD
- 测试：MM/DD - MM/DD
- 提审：MM/DD
- 上线：MM/DD（预计）

### 审核注意
- 新功能是否需要额外资质
- 是否涉及类目变更
- 版本说明如何撰写
```

### 9.3 新功能审核要求

| 变更类型 | 是否需要重新审核 | 注意事项 |
|---------|----------------|---------|
| 新增广告位 | 是 | 确保合规 |
| 新增内购 | 是 | 需版号 |
| 新增玩法 | 是 | 可能需调整类目 |
| 数值调整 | 是（常规提审） | 版本说明注明 |
| Bug修复 | 是（可加急） | 说明修复内容 |
| 纯文案修改 | 是 | - |
| 后端逻辑调整 | 否（无需提审） | 前端无变化 |
| 活动配置更新 | 视实现方式 | 远程配置则无需 |

### 9.4 热更新 vs 提审更新

| 方式 | 适用场景 | 限制 |
|------|---------|------|
| 提审更新 | 代码/资源变更 | 需审核，1-2天 |
| 远程配置 | 数值/开关/文案 | 无需审核，即时生效 |
| 分包更新 | 新关卡/新资源 | 需审核 |

> 建议：将活动配置、数值参数、开关控制设计为远程可配置，减少提审频率。

## 十一、上线后违规处罚说明

### 11.1 处罚等级

| 等级 | 处罚措施 | 触发条件 | 影响 |
|------|---------|---------|------|
| 警告 | 站内信警告 | 轻微违规/首次 | 需整改，不影响运营 |
| 限流 | 减少推荐/搜索权重 | 多次警告未改 | DAU下降 |
| 暂停服务 | 临时下架（1-7天） | 中度违规 | 无法访问 |
| 下架 | 强制下架 | 严重违规 | 需整改后重新提审 |
| 封禁 | 永久封禁账号 | 极严重/多次违规 | 不可恢复 |

### 11.2 常见违规行为及处罚

| 违规行为 | 首次处罚 | 再次处罚 | 说明 |
|---------|---------|---------|------|
| 广告遮挡核心功能 | 警告 | 暂停服务 | 限期整改 |
| 违规分享/强制关注 | 警告 | 限流/暂停 | 删除违规引导逻辑 |
| 隐私违规 | 暂停服务 | 下架 | 严重可能直接下架 |
| 内容违规 | 下架 | 封禁 | 零容忍 |
| 无版号内购 | 下架 | 封禁 | 零容忍 |
| 违规机制 | 下架 | 封禁 | 零容忍 |
| 虚假宣传 | 警告 | 暂停服务 | 截图/描述不实 |
| 数据造假/作弊 | 限流 | 下架 | 零容忍 |
| 侵权（IP/音乐） | 下架 | 封禁 | 需权利人投诉触发 |
| 防沉迷未执行 | 暂停服务 | 下架 | 限期整改 |

### 11.3 处罚应对SOP

```
收到处罚通知
  ↓
Step 1: 确认处罚类型和原因
  - 公众平台→站内信/通知
  - 记录处罚时间、原因、期限
  ↓
Step 2: 评估影响
  - 影响范围（全量/部分用户）
  - 持续时间
  - 收入影响
  ↓
Step 3: 紧急处理
  - 警告：24小时内整改
  - 暂停：立即排查，准备申诉/整改
  - 下架：全面排查，准备重新提审
  ↓
Step 4: 整改
  - 定位违规点
  - 修复/删除违规内容
  - 全面自查是否有其他类似问题
  ↓
Step 5: 申诉（如认为误判）
  - 公众平台→申诉入口
  - 准备证据材料
  - 48小时内提交
  ↓
Step 6: 恢复
  - 整改后重新提审
  - 恢复后加强巡检
  - 记录教训，避免再犯
```

### 11.4 预防措施

```markdown
### 避免违规的日常习惯：
1. 每次更新前过一遍合规清单（小林审查）
2. 关注微信开放社区公告（每周）
3. 广告配置变更需合规确认
4. 新素材（图片/音乐/字体）确认版权
5. 用户协议/隐私政策年度更新
6. 防沉迷机制定期验证
7. 建立内部合规红线文档，团队共享
8. 保留所有素材的版权证明
```
