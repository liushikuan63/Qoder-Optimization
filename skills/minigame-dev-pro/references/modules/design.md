# 游戏策划指导模块 (Game Design)

## 设计原则

- 策划文档不是"灵感记录"，是"施工图纸"。写出来的东西必须能直接指导开发。
- 所有数值给具体数字，不说"适当增加难度"，说"第11关开始，障碍物速度从3px/帧提升到4.5px/帧"。
- 根据用户技术背景调整输出深度：开发者给完整数值表，非技术人员给"找外包时怎么描述需求"的版本。
- 核心循环是一切的基础。如果核心循环不好玩，加再多系统也救不回来。

---

## 策划文档输出结构

### 完整策划文档目录（按顺序输出）

```
1. 游戏概述（1页）
   - 一句话描述（如："用物理引擎合成水果，合成越大分越高"）
   - 目标用户（年龄/性别/游戏经验）
   - 核心体验关键词（如：爽快、解压、竞技）
   - 参考产品（2-3个，说明参考什么不参考什么）

2. 核心循环设计（2-3页）
   - 微循环（30秒内）
   - 中循环（5分钟）
   - 宏循环（30分钟）
   - 循环之间的衔接关系

3. 功能清单（1-2页）
   - MVP功能（必须有）
   - V1.1功能（上架后第一个更新）
   - V2.0功能（验证数据后再做）
   - 明确标注"不做"的功能

4. 关卡/内容设计（2-4页）
   - 关卡结构
   - 难度曲线
   - 内容量规划

5. 数值体系（2-3页）
   - 经济系统
   - 难度参数
   - 奖励节奏

6. 变现设计（1-2页）
   - 广告位设计
   - 内购设计（如适用）
   - 付费点与免费体验的边界

7. 社交设计（1页）
   - 分享机制
   - 排行/对比
   - 合规边界

8. 首次用户体验 FTUE（1-2页）
   - 前3分钟流程
   - 引导设计
   - 首次会话目标
```

### 按用户技术背景调整输出

**developer（会写代码）：**
- 数值表给完整Excel格式（可直接导入Cocos/Unity）
- 功能描述附带伪代码逻辑
- 状态机图用文字描述（状态→条件→转移）
- 示例："敌人AI状态机：idle→(玩家进入200px范围)→chase→(距离<50px)→attack→(血量<30%)→flee"

**semi_technical（用过工具但不写代码）：**
- 数值表给Excel格式，但附带"这个参数在Cocos Creator哪里设置"
- 功能描述用"当XX时，发生YY"的自然语言
- 附带Cocos Creator可视化编辑的操作路径
- 示例："在Cocos Creator中：选中敌人节点→属性检查器→添加脚本→EnemyAI.js→把'追击距离'参数设为200"

**non_technical（零基础）：**
- 数值表给"需求描述"格式，用于找外包沟通
- 功能描述用"玩家看到什么/做什么/得到什么"三段式
- 附带"外包验收标准"（怎么判断外包做对了）
- 示例："需求：敌人会在玩家靠近时追过来。验收标准：玩家走到距离敌人约2个身位时，敌人开始移动追踪，速度比玩家慢20%，玩家跑远后敌人回到原位。"

## 核心循环设计指导

### 三层循环模型

#### 微循环（30秒内）——"一次操作"

定义：玩家执行一次最小有意义操作，获得即时反馈。

**设计模板：**
```
微循环 = 输入 → 动作 → 反馈 → 结果

示例（合成类）：
  输入：玩家选择落点（左右滑动）
  动作：松手，水果下落（物理引擎）
  反馈：碰撞音效+粒子特效+屏幕微震
  结果：两个相同水果合成→变大→得分飘字

示例（消除类）：
  输入：玩家交换两个方块
  动作：方块交换位置
  反馈：匹配成功→消除动画+连击音效
  结果：得分+上方方块下落+可能触发连锁

示例（跑酷类）：
  输入：玩家点击屏幕
  动作：角色跳跃
  反馈：跳跃弧线+落地 dust 特效
  结果：越过障碍→继续跑/撞到→死亡
```

**微循环设计检查清单：**
- [ ] 操作到反馈 < 100ms（不能有感知延迟）
- [ ] 每次操作都有视觉+听觉反馈（不能"按了没反应"）
- [ ] 单次操作有明确结果（成功/失败/部分成功）
- [ ] 操作方式不超过2种（点击+滑动，最多加个长按）
- [ ] 失败也有趣（不是惩罚，是"再来一次"的动力）

---

#### 中循环（5分钟）——"一局/一关"

定义：玩家完成一个完整的挑战单元，获得阶段性奖励。

**设计模板：**
```
中循环 = 开始挑战 → 难度递增 → 高峰/危机 → 结算 → 奖励

示例（合成类）：
  开始：空棋盘，随机给3个水果
  递增：棋盘越来越满，可落点越来越少
  高峰：差一步就合出最大水果/棋盘快满了
  结算：游戏结束→显示分数→历史最高对比
  奖励：金币（用于解锁皮肤）+ 排行榜排名更新
  时长：3-5分钟一局

示例（益智解谜类）：
  开始：展示谜题+规则提示
  递增：尝试→失败→调整策略
  高峰：找到关键突破口
  结算：通关→星级评价（1-3星）
  奖励：星星+解锁下一关+偶尔掉道具
  时长：2-8分钟一关（难度越高越长）
```

**中循环设计检查清单：**
- [ ] 每局/每关有明确的"开始"和"结束"信号
- [ ] 难度在单局内有递增（不能从头到尾一个难度）
- [ ] 有"差一点就成功"的时刻（制造"再来一局"冲动）
- [ ] 结算时间 < 5秒（不要放长动画拖时间）
- [ ] 奖励即时可见（分数飘字、金币入袋动画）
- [ ] 失败后重新开始 < 2秒（一键重来，不要回主菜单）

---

#### 宏循环（30分钟）——"一次游玩会话"

定义：玩家从打开游戏到关闭游戏的完整体验弧线。

**设计模板：**
```
宏循环 = 登录奖励 → 多局游戏(中循环×N) → 成长/解锁 → 目标推进 → 退出钩子

示例（合成类）：
  登录：每日签到→领金币/道具
  多局：玩3-5局合成（每局3-5分钟）
  成长：用金币解锁新水果皮肤/新棋盘主题
  目标推进：完成每日任务（"今天合出3个西瓜"）→ 周目标进度
  退出钩子："明天登录领限定皮肤碎片(3/7)"
  总时长：20-35分钟

示例（放置类）：
  登录：收取离线收益（"你离开了8小时，获得12000金币"）
  多局：升级建筑→解锁新区域→打Boss
  成长：角色等级+1、解锁新技能
  目标推进：主线任务"到达第5层"→完成→开启新章节
  退出钩子："8小时后离线收益满，记得回来收"
  总时长：15-30分钟（放置类单次会话短但频率高）
```

**宏循环设计检查清单：**
- [ ] 登录前3秒有正反馈（签到/离线收益/红点提示）
- [ ] 单次会话有"目标感"（不是无脑重复，是在推进什么）
- [ ] 有成长可见性（等级/收集进度/解锁列表）
- [ ] 退出时有"明天回来的理由"（限时/连续签到/离线收益）
- [ ] 单次会话不超过40分钟（小游戏用户碎片化，不要设计成端游）

## 留存机制设计

### 次日留存（次留）——靠"首次体验+未完成感"

**目标：** 用户今天玩了，明天还想打开。行业参考：休闲小游戏次留>30%算合格，>40%算优秀，<25%需预警。

**具体机制：**

| 机制 | 实现方式 | 注意事项 |
|------|----------|----------|
| 新手大礼包分天发放 | Day1给一部分，提示"明天登录领剩余奖励" | 奖励必须是玩家已经体验过想要的东西 |
| 未完成的短目标 | 首次会话结束时，主线任务进度到80%（差一点完成） | 不能让玩家首次就完成所有目标 |
| 限时首充/首看 | "24小时内看3个广告得限定皮肤" | 必须是限时，过期不候 |
| 社交钩子 | "你的好友XXX超过了你，明天来反超" | 需要好友关系链，冷启动难 |
| 悬念/解锁预告 | "明天解锁新玩法：双人对战" | 必须真的解锁，不能骗 |

**次留杀手（绝对不能做）：**
- 首次会话超过10分钟还没让玩家体验到核心乐趣
- 首次就弹出"评价我们""关注公众号"
- 新手引导超过5步（每多一步流失20%用户）
- 首次就死很多次（难度过高）

---

### 7日留存（7留）——靠"习惯养成+成长线"

**目标：** 用户连续一周每天打开。行业基准：7留>15%算合格，>25%算优秀。

**具体机制：**

| 机制 | 实现方式 | 数值参考 |
|------|----------|----------|
| 7日签到递增 | Day1:100金币 → Day2:150 → ... → Day7:500+限定道具 | 第7天奖励必须是前6天总和的50%以上 |
| 每日任务 | 3个简单任务（玩2局/合成5次/分享1次）→ 完成给活跃值 | 任务完成时间 < 10分钟 |
| 周目标 | "本周累计得分达到10000" → 完成给大奖 | 正常玩5天能完成，不需要肝 |
| 成长线可见 | 等级系统/收集图鉴（"已解锁12/50个皮肤"） | 每2-3天有一次解锁/升级 |
| 难度递进 | 新关卡/新挑战每天解锁一批 | 不能让玩家一天打完所有内容 |

---

### 30日留存（30留）——靠"社交绑定+长线目标"

**目标：** 用户一个月后还在玩。行业基准：30留>5%算合格，>10%算优秀（休闲游戏）。

**具体机制：**

| 机制 | 实现方式 | 注意事项 |
|------|----------|----------|
| 赛季/章节制 | 每30天一个赛季，赛季结束重置排行榜 | 赛季奖励必须足够诱人 |
| 收集系统 | 50+个可收集物品，稀有度分层 | 最稀有的需要30天才能集齐 |
| 好友排行 | 周排行/月排行，好友间对比 | 需要用户有微信好友在玩 |
| 成就系统 | 长期成就（"累计合成1000个水果"） | 成就给永久称号/边框 |
| 内容更新 | 每周/每两周新增关卡/活动 | 这是30留最核心的因素 |
| 损失厌恶 | "连续登录30天得限定头像框，中断归零" | 允许1-2次补签（看广告补） |

## 数值体系框架

### 难度曲线设计

**核心原则：** 难度不是线性增长，是"阶梯式上升+周期性回落"。

**具体数值模板（以20关益智游戏为例）：**

```
关卡难度值（1-10分）：
  关1: 1.0  ← 教学关，不可能失败
  关2: 1.5
  关3: 2.0
  关4: 2.5
  关5: 3.5  ← 第一个小Boss关（难度跳升）
  关6: 2.5  ← 回落（让玩家喘口气，建立信心）
  关7: 3.0
  关8: 3.5
  关9: 4.0
  关10: 5.0 ← 第二个Boss关
  关11: 3.5 ← 回落
  关12: 4.0
  关13: 4.5
  关14: 5.0
  关15: 6.0 ← 第三个Boss关
  关16: 4.5 ← 回落
  关17: 5.0
  关18: 5.5
  关19: 6.0
  关20: 7.5 ← 最终Boss（允许失败，设计"差一点"体验）

规律：
  - 每5关一个难度峰值
  - 峰值后下一关难度回落30%
  - 整体趋势上升，但斜率递减（前期升得快，后期升得慢）
  - Boss关难度 = 前一关 × 1.3-1.5
```

**动态难度调节（DDA）：**
```
如果玩家在同一关失败3次：
  → 第4次尝试时，暗中降低难度10%（如：多给1步/多给5秒/减少1个障碍）
  → 不告知玩家（不能让玩家觉得"被施舍了"）
  
如果玩家连续3关一次通过：
  → 下一关难度额外+10%（保持挑战感）
  
实现方式：维护一个 hidden_difficulty_modifier 变量，范围0.7-1.3
```

### 奖励节奏设计

**核心原则：** 奖励频率从高到低递减，但单次奖励价值递增。

**具体节奏表：**

```
时间轴（首次会话）：
  0:00 - 完成教学 → 奖励：100金币 + 音效"叮！"（即时正反馈）
  0:30 - 第一次合成成功 → 奖励：50金币 + 粒子特效
  1:00 - 完成第1局 → 奖励：结算分数 + 200金币
  2:00 - 解锁新皮肤 → 奖励：视觉变化（免费体验1个付费皮肤）
  3:00 - 完成每日任务1/3 → 奖励：活跃值+30
  5:00 - 完成每日任务2/3 → 奖励：活跃值+30
  7:00 - 完成每日任务3/3 → 奖励：活跃值+40 + 随机道具奖励
  
规律：
  - 前2分钟：每30秒一次奖励（高频低值，建立"这游戏很大方"的印象）
  - 2-5分钟：每1-2分钟一次奖励
  - 5分钟后：每3-5分钟一次奖励（频率降低，但单次价值提高）
  - 绝对不能出现超过5分钟无任何正反馈的时段
```

**奖励类型配比：**
```
软货币（金币）：占60% —— 量大，用于日常消耗
硬货币（钻石）：占10% —— 稀缺，用于关键解锁
道具（复活/提示）：占15% —— 功能性，降低挫败感
视觉（皮肤/特效）：占10% —— 炫耀性，无实际功能
社交（称号/边框）：占5% —— 稀有，长期目标
```

### 经济平衡

**核心公式：**
```
玩家每小时获得的金币 = 基础产出 × (1 + 广告加成)
玩家每小时消耗的金币 = 升级费用 + 道具费用

平衡目标：
  - 免费玩家：每小时净收入略为正（+5-10%），感觉"在进步但不够快"
  - 看广告玩家：每小时净收入明显为正（+30-50%），感觉"看广告有用"
  - 付费玩家（如有内购）：效率是免费的3-5倍，但不是"不买就玩不了"
```

**防通胀设计：**
```
金币消耗坑（sink）设计：
  - 升级费用指数增长：Level N 升级费 = 100 × 1.5^N
    Level 1: 100, Level 5: 759, Level 10: 5766, Level 20: 332,526
  - 道具消耗：复活=500金币/次，提示=200金币/次
  - 皮肤/装饰：纯消耗，500-5000金币/个
  - 随机抽取：1000金币/次，概率获得稀有物品

确保：玩家永远觉得"金币不够用"，但"差一点就够了"（驱动看广告/继续玩）
```

## 心流设计（挑战与技能平衡）

### 心流通道模型

```
        高 │         ╱ 焦虑区
   挑战    │        ╱
   难度    │       ╱ ← 心流通道（目标区域）
           │      ╱
           │     ╱
        低 │    ╱  无聊区
           └──────────────────
           低    玩家技能    高
```

### 具体实现

**保持心流的5条规则：**

1. **即时反馈规则：** 每个操作在100ms内有反馈。玩家跳跃→立即看到弧线；玩家消除→立即看到消除特效。不能有"按了等0.5秒才反应"。

2. **难度匹配规则：** 玩家成功率维持在60-80%区间。
   - 成功率>90% → 太简单，玩家无聊 → 加速/加障碍/减少时间
   - 成功率<40% → 太难，玩家焦虑 → 给道具/降速/加提示
   - 测量方式：记录每关的失败次数，动态调整

3. **目标清晰规则：** 玩家在任何时刻都知道"我现在要做什么"和"做到什么程度算完成"。
   - 关卡开始：显示目标（"得到3000分"/"消除所有蓝色方块"）
   - 游戏中：进度条/计数器始终可见
   - 接近完成：视觉/音效提示（进度条变红、音乐加速）

4. **掌控感规则：** 失败时玩家觉得"是我的问题"而不是"游戏不公平"。
   - 死亡回放：让玩家看到自己怎么死的
   - 不能随机导致失败（不能"突然从屏幕外飞来一个障碍物"）
   - 所有失败元素必须在失败前至少1秒可见

5. **渐进复杂规则：** 新机制引入速度 = 每5分钟最多1个新概念。
   - 第1关：只有基础操作
   - 第3关：引入1个新元素（如：移动平台）
   - 第5关：引入第2个新元素（如：弹簧）
   - 第8关：组合使用（移动平台+弹簧）
   - 绝对不能在一关内同时引入2个新机制

## 合规社交机制设计

### 能做的（合规）

| 社交功能 | 实现方式 | 合规要点 |
|----------|----------|----------|
| 好友排行榜 | `wx.getFriendCloudStorage()` 获取好友分数 | 只能展示，不能强制比较 |
| 分享挑战 | 分享卡片"我在XX关得了5000分，你能超过我吗？" | 分享仅用户主动触发，不绑定任何奖励 |
| 群排行 | 分享到群后，群内成员可看到排名 | 不能"分享到3个群才能复活" |
| 好友助力 | "邀请好友帮你加速建造" | 助力是可选加速，不是必须 |
| 对战/竞速 | 异步PK（你玩你的，他玩他的，比分数） | 不能涉及真钱/虚拟货币的金钱投入 |
| 赠送道具 | 每天可给好友送1次体力/道具 | 不能赠送付费货币 |

### 不能做的（违规）

| 违规功能 | 为什么违规 | 替代方案 |
|----------|-----------|----------|
| "分享到3个群才能复活" | 强制分享，违反红线10 | 改为"看广告复活"或"等30秒复活" |
| "分享后100%获得SSR" | 违规分享奖励 | 分享不绑定任何奖励；"看广告获得SSR"也需公示抽取概率 |
| "邀请5个好友才能解锁关卡" | 强制社交门槛 | 改为"邀请好友可加速解锁"（不邀请也能解锁，只是慢） |
| "好友对战，输的扣金币" | 违规机制 | 改为"赢的额外得金币，输的不扣" |
| "分享到朋友圈得奖励" | 微信禁止检测朋友圈分享 | 不要做，技术上也无法验证 |
| 实时语音/文字聊天 | 需要额外内容审核资质 | 用预设表情/快捷短语代替 |

### 社交设计合规检查清单

```
- [ ] 分享功能仅用户主动触发，不绑定任何游戏内奖励
- [ ] 没有"不分享就卡进度"的设计
- [ ] 排行榜只展示，不惩罚排名低的用户
- [ ] 没有真钱/虚拟货币的金钱博弈设计
- [ ] 没有强制关注/下载其他产品
- [ ] 社交功能关闭后，游戏仍可完整游玩（单机可玩）
```

## 首次用户体验（FTUE）设计

### 前3分钟黄金流程

**核心目标：** 3分钟内让玩家体验到"核心乐趣"，并建立"我还能变得更强/解锁更多"的预期。

**逐秒设计模板（以合成类游戏为例）：**

```
0:00-0:05  打开游戏
  - 不要Logo动画（或最多2秒，可跳过）
  - 不要"点击任意位置开始"（多一步操作多流失10%）
  - 直接进入游戏画面

0:05-0:10  第一次操作
  - 屏幕上只有1个可操作元素（高亮+手指动画引导）
  - 玩家点击/拖动 → 立即看到结果
  - 不要文字说明，用动画演示

0:10-0:30  教学（无文字）
  - 第1次：引导合成一次（手指动画指示落点）
  - 第2次：引导合成一次（只给箭头提示）
  - 第3次：不给提示，让玩家自己操作
  - 如果玩家5秒没操作 → 再次显示手指动画
  - 绝对不能：弹出文字框"欢迎来到XXX，本游戏的规则是..."

0:30-1:00  第一次"爽"
  - 让玩家合出一个比较大的水果（暗中提高好水果出现概率）
  - 合成瞬间：大特效+音效+屏幕震动+分数飘字
  - 这是"hook moment"——玩家第一次感受到核心乐趣

1:00-2:00  自由游玩
  - 不再引导，让玩家自己玩
  - 难度极低（水果种类只有3-4种，容易合成）
  - 持续给正反馈（连击提示、分数飞涨）

2:00-2:30  第一次"差一点"
  - 棋盘快满了，玩家即将失败
  - 或者：差一步就能合出最大水果但没位置了
  - 游戏结束 → 结算画面

2:30-3:00  结算+钩子
  - 显示分数 + "历史最高"（第一次玩就是最高，给成就感）
  - 显示"你解锁了：新皮肤碎片(1/5)"
  - 按钮："再来一局"（最大、最显眼）
  - 次要按钮："领取新手奖励"（引导到签到/任务系统）
  - 不要在这个时刻弹广告！
```

### FTUE设计检查清单

```
- [ ] 从打开到第一次操作 < 5秒
- [ ] 前30秒内完成教学（不超过3步引导）
- [ ] 前1分钟内体验到核心乐趣（"hook moment"）
- [ ] 前3分钟内完成一局完整游戏
- [ ] 教学全程无文字（纯动画/视觉引导）
- [ ] 首次会话不弹任何广告
- [ ] 首次会话不弹"评价""关注""分享"
- [ ] 失败后"再来一局"按钮在1秒内可点击
- [ ] 首次会话结束时，玩家有"未完成"的感觉（想明天再来）
- [ ] 新手引导可跳过（老玩家/第二次打开不再显示）
```

### 常见FTUE错误

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 开场5步文字引导 | 每步流失15-20%，5步后只剩40% | 最多3步动画引导，融入游戏中 |
| 第一关就很有难度 | 玩家觉得"这游戏不适合我" | 前3关不可能失败 |
| 开场就弹隐私弹窗+权限请求 | 玩家还没体验就被关闭 | 隐私弹窗放在第一次需要时触发 |
| 主菜单有10个按钮 | 玩家不知道点哪 | 首次打开只展示"开始游戏"1个按钮 |
| 教学关强制不可跳过 | 二测用户/老玩家烦躁 | 检测到非首次打开→跳过教学 |
| 第一局结束就弹广告 | 直接卸载 | 前5局/前10分钟不弹广告 |

## 按用户技术背景调整建议深度（完整对照）

### 同一设计点的三种输出示例

**设计点：敌人追击AI**

**给 developer 的输出：**
```
敌人AI状态机：
  状态：IDLE / PATROL / CHASE / ATTACK / RETURN
  转移条件：
    IDLE → PATROL: 游戏开始后2秒
    PATROL → CHASE: 玩家进入检测范围(detectionRadius=200px)
    CHASE → ATTACK: 与玩家距离<attackRange=50px
    CHASE → RETURN: 玩家离开追击范围(chaseRadius=350px) 或 追击时间>5秒
    ATTACK → CHASE: 攻击动画结束 且 玩家距离>attackRange
    RETURN → PATROL: 回到巡逻路径点

参数表：
  patrolSpeed: 60 px/s
  chaseSpeed: 120 px/s（玩家的80%，确保能跑掉）
  attackCooldown: 1.5s
  detectionRadius: 200px
  chaseRadius: 350px

代码架构建议（Cocos Creator）：
  EnemyAI.ts 继承 Component
  使用 cc.Enum 定义状态
  update(dt) 中根据状态执行行为
  用 cc.tween 做巡逻路径
  用 Physics2D 碰撞检测做范围判断
```

**给 semi_technical 的输出：**
```
敌人行为设计：
  1. 敌人在固定路线来回走（巡逻）
  2. 玩家靠近到约2个屏幕宽度时，敌人转向追玩家
  3. 敌人追击速度是玩家的80%（玩家能跑掉，但有紧迫感）
  4. 追到玩家身边时，停顿1.5秒做攻击动作
  5. 玩家跑远后（约3.5个屏幕宽度），敌人放弃追击，走回原位

在Cocos Creator中实现：
  - 创建敌人节点 → 添加 BoxCollider2D（范围200px）做检测
  - 添加脚本 EnemyAI.js
  - 巡逻：用 cc.tween 在两个路径点之间来回移动
  - 追击：在 onBeginContact 中切换为追踪模式
  - 速度参数在脚本顶部定义为变量，方便调整

需要调整的数值（在属性检查器中改）：
  - patrolSpeed: 巡逻速度，先设60试试
  - chaseSpeed: 追击速度，设120（玩家速度150的80%）
  - detectionRadius: 发现距离，设200
```

**给 non_technical 的输出：**
```
敌人行为需求（给外包的描述）：

"关卡中有一种会追人的敌人。它的行为是：
  1. 平时在固定两个点之间来回走，速度比较慢（玩家走路速度的40%）
  2. 当玩家走到离它大约2个身位远的时候，它发现玩家，开始追
  3. 追的速度比玩家跑步慢一点（玩家能跑掉，但要跑才行）
  4. 如果追到玩家旁边，它会停下来做一个'打'的动作（约1.5秒）
  5. 如果玩家跑远了（大约3-4个身位），它就不追了，慢慢走回原来的位置

验收标准：
  □ 敌人巡逻时，玩家从远处经过不会被发现
  □ 玩家靠近后，敌人在0.5秒内转向并开始追
  □ 玩家全力跑可以甩掉敌人（约3-4秒后脱离）
  □ 敌人不会穿过墙壁/障碍物追人
  □ 敌人回到原位后，恢复巡逻状态
  □ 整个过程没有卡顿/穿模"
```
