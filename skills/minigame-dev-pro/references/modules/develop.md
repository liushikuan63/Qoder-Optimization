### 选型红线

- 个人开发者做第一个游戏 → 不要选Unity（坑太多，会劝退）
- 包体敏感（休闲游戏） → 不要选Unity（framework.js无法压缩）
- 需要3D物理/粒子/后处理 → 不要硬用Cocos（能力有限）
- 不要同时学两个引擎 → 选一个深入

## 技术规范速查

### 硬性限制（违反=无法上线）

| 项目 | 限制 | 备注 |
|------|------|------|
| 主包大小 | ≤ 4MB | 包含代码+首屏必须资源 |
| 总包大小 | ≤ 30MB（含所有分包） | 超出用CDN |
| 单个普通分包 | 无硬性大小限制（独立分包≤4MB） | 建议≤15MB 提升加载体验 |
| 网络请求 | 必须HTTPS | HTTP直接报错 |
| 域名白名单 | 必须在后台配置 | request/uploadFile/downloadFile分别配 |
| 基础库版本 | 用最新版（当前3.x） | 在project.config.json中设置 |
| WebSocket | 必须wss:// | ws://不行 |
| 本地存储 | 单个key≤1MB，总量≤10MB | 别存大数据 |

### 软性建议（影响体验和审核）

| 项目 | 建议 | 原因 |
|------|------|------|
| 首屏加载 | ≤ 3秒（4G网络） | 超3秒流失率>50% |
| 帧率 | 稳定60fps（至少30fps） | 低于30fps用户感知卡顿 |
| 内存占用 | ≤ 256MB（低端机） | 超了会被系统杀进程 |
| DrawCall | ≤ 50（同屏） | 超了掉帧 |
| 音频格式 | MP3/AAC，≤ 5MB/首 | WAV太大 |
| 图片格式 | PNG/JPG/WebP | 不支持SVG渲染 |

## 分包策略

### 主包放什么（≤4MB，寸土寸金）

```
主包/
├── game.js          # 入口文件（必须）
├── game.json        # 配置（必须）
├── project.config.json
├── js/
│   ├── core/        # 核心框架代码（游戏循环、事件系统、资源管理）
│   ├── net/         # 网络层（登录、数据同步）
│   └── ui/          # 首屏UI（Loading页、登录页、主界面）
├── resources/
│   ├── loading/     # 加载页资源（背景图+进度条，控制在100KB内）
│   └── fonts/       # 首屏必须字体（子集化后）
└── libs/            # 引擎运行时（Cocos约1.5-2MB）
```

### 分包怎么拆

```
分包策略（按功能模块拆）：
├── subpackage-game/     # 核心玩法（关卡逻辑+玩法资源）
├── subpackage-shop/     # 商城系统（商品列表+购买逻辑）
├── subpackage-social/   # 社交功能（排行榜+好友+分享）
└── subpackage-activity/ # 活动系统（运营活动+节日皮肤）

CDN远程资源（不计入包体）：
├── 关卡配置JSON
├── 大图/动画/特效资源
├── 音频文件
└── 活动资源（频繁更新的）
```

### 分包铁律

1. **分包之间不能互相引用** — A分包不能require B分包的代码
2. **主包可以引用所有分包** — 但分包只能引用主包
3. **分包加载是异步的** — 进入分包场景前必须先loadSubpackage
4. **共享代码放主包** — 多个分包都要用的工具类/组件放主包
5. **资源引用不能跨分包** — 分包A的图片不能在分包B的prefab里引用

### 分包加载代码示例（Cocos Creator 3.x）

```typescript
// 加载分包
assetManager.loadBundle('subpackage-game', (err, bundle) => {
    if (err) {
        console.error('分包加载失败', err);
        showRetryDialog();
        return;
    }
    // 进入子场景
    director.loadScene('game');
});

// 加载远程资源（CDN）
const remoteUrl = 'https://cdn.example.com/levels/level_10.json';
const asset = await assetManager.loadRemote(remoteUrl, { ext: '.json' });
```

## 性能优化清单

### 渲染优化（最有效）

| 优化项 | 方法 | 效果 |
|--------|------|------|
| 减少DrawCall | 图集合并、静态合批、动态合批 | 大幅提升帧率 |
| 纹理压缩 | 使用ETC2/ASTC格式 | 减少显存占用 |
| 对象池 | 复用频繁创建销毁的对象（子弹、特效） | 减少GC |
| 遮挡剔除 | 不渲染屏幕外的对象 | 提升帧率 |
| LOD | 远处对象用低精度模型 | 中重度游戏适用 |
| 粒子优化 | 限制粒子数量，使用图集 | 减少性能开销 |

### 内存优化

| 优化项 | 方法 | 效果 |
|--------|------|------|
| 资源卸载 | 场景切换时卸载无用资源 | 防止内存泄漏 |
| 音频流式加载 | 大音频文件用流式而非全量加载 | 减少内存峰值 |
| 图片压缩 | 用WebP替代PNG（节省30-50%） | 减少内存 |
| 纹理尺寸 | 不超过2048x2048 | 兼容性+内存 |
| 字体子集化 | 只保留用到的字符 | 大幅减少字体文件大小 |

### 加载优化

| 优化项 | 方法 | 效果 |
|--------|------|------|
| 首屏资源最小化 | 只放必须资源（Loading+Logo） | 提升首屏速度 |
| 预加载 | 空闲时预加载下一关资源 | 消除卡顿 |
| 分包加载 | 非首屏资源走分包 | 降低首包大小 |
| CDN加速 | 大资源放CDN | 降低包体 |
| 资源版本管理 | 文件名带hash，避免缓存问题 | 更新可靠 |

## 常见坑点

| 序号 | 坑点 | 说明 |
|------|------|------|
| 1 | 首包超4MB | 最常见的驳回原因，严格监控主包大小 |
| 2 | 用了HTTP请求 | 微信强制HTTPS，HTTP直接报错 |
| 3 | 域名没配白名单 | 所有请求域名必须在后台配置 |
| 4 | 本地存储太大 | 超过10MB会被清掉，重要数据走云端 |
| 5 | 内存泄漏 | 场景切换不释放资源，长时间运行崩溃 |
| 6 | 忽略低端机 | 高端机流畅，红米/OPPO卡成PPT |
| 7 | 分包加载没做loading | 分包加载慢，用户以为卡死了 |
| 8 | 图片不压缩 | 一张2MB的PNG就能让首包超限 |
| 9 | 用废弃API | 如wx.getUserInfo（2021年已废弃），导致审核失败 |
| 10 | 不同步更新基础库版本 | 新版基础库修复了旧版Bug，不及时更新会踩坑 |

## 快速调试技巧

### 微信开发者工具

```bash
# 打开项目
wechat-devtool-cli open --project /path/to/project

# 预览（生成二维码）
wechat-devtool-cli preview --project /path/to/project

# 上传
wechat-devtool-cli upload --project /path/to/project --version 1.0.0 --desc "首次发布"
```

### 常用调试方法

1. **真机调试**：开发者工具 → 预览 → 扫码 → 手机端实时调试
2. **性能面板**：工具 → 性能面板 → 查看FPS/内存/CPU
3. **vConsole**：手机上查看日志（开启debug模式）
4. **Network面板**：查看网络请求和资源加载
5. **Storage面板**：查看本地存储数据
