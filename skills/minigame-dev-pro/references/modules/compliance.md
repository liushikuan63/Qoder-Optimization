# 合规引擎模块 (Compliance)

## 设计原则

- 合规不是"建议"，是硬门槛。不满足就不能上架，没有例外。
- 每次给出合规建议时，必须附带具体操作路径（哪个网站、填什么表、等多久）。
- 时间线前置提醒是核心功能——用户最大的坑不是"不知道要办"，而是"不知道要提前多久办"。
- 个人和企业走完全不同的路径，不能混为一谈。

---

## 14条红线：完整检查逻辑

以下14条是微信小游戏审核的硬性要求，任何一条不满足都会被拒审。

> 适用范围：微信小游戏（platform=wechat）。其他平台红线以各平台官方审核规范为准；虚拟支付/软著等规则见 `references/knowledge/compliance-rules.md` 的「平台×变现模式」矩阵。

### 红线1：主体资质合法

**检查逻辑：**
- 个人主体：身份证正反面照片 + 微信扫码验证（注册时已完成）
- 企业主体：营业执照在有效期内 + 经营范围包含"软件开发"/"信息技术服务"/"网络文化"中至少一项
- 检查点：登录 [mp.weixin.qq.com](微信公众平台) → 设置 → 基本设置 → 查看主体信息 → 确认"主体类型"和"有效期"

**不通过后果：** 无法注册/无法提审
**修复方式：** 企业去工商局变更经营范围（5-10个工作日），个人无法变更只能重新注册

---

### 红线2：软件著作权登记证书（软著）

**检查逻辑（软著要求取决于「平台 × 变现模式」，禁止一刀切）：**
- **微信 + 纯广告（IAA，无内购）**：软著**非必填**，默认走《著作权自我声明》即可提审（名称不与软著绑定）。
- **微信 + 含内购（IAP）/ 抖音（任一变现）**：软著**必填**，且软著名称与游戏名称**一字不差**（包括标点、空格、大小写）；软著权利人必须是小游戏账号主体（个人对应个人姓名，企业对应公司全称）；状态须为"已授权"（非"受理中"）。
- 其他平台（QQ/快手/支付宝/百度/淘宝/快游戏）软著要求以各平台开放平台官方文档为准，执行前须二次核实，未核实一律标"待官方核实"。
- 软著名称锁定规则、办理时间线详见 `references/knowledge/sop/software-copyright-sop.md`（按变现模式分支）。
- 检查点：登录 [中国版权保护中心](https://www.ccopyright.com.cn) → 软件登记 → 查看证书状态

**名称锁定规则（极重要）：**
```
⚠️ 软著名称 = 游戏名称 = 小程序名称，三者必须完全一致！

错误示例：
  软著名："[游戏名]V1.0" → 游戏名："[游戏名]" → ❌ 不一致（多了V1.0）
  软著名："[游戏名]" → 游戏名："[游戏名]Pro" → ❌ 不一致（多了Pro）
  软著名："我的小镇" → 游戏名："我的小镇" → ✅ 一致

正确流程：
  Step 1: 先确定游戏最终名称（上架后改名极麻烦）
  Step 2: 用这个名称（不加任何版本号/后缀）去申请软著
  Step 3: 微信后台填写游戏名称时填写同一名称
  Step 4: 提审时上传软著证书

注意：软著"软件全称"应填写游戏名称本身，不带"V1.0""软件""系统"等后缀，
软著名称与游戏名称必须一字不差（详见 references/knowledge/sop/software-copyright-sop.md）。
```

**办理时间线：**
- 普通申请：30-60个工作日（约1-2个月，官费免费）
- 加急申请：1-2周（代办费约2000-5000元，通过代理机构）
- 代理机构推荐：云服务商知识产权（aliyun.com/product/copyright）、权大师（quandashi.com）
- 自己办理：中国版权保护中心（https://www.ccopyright.com.cn）→ 软件登记 → 计算机软件著作权登记 → 在线填报

**前置依赖：** 无。游戏名称确定后即可立即申请。
**关键提醒：** 在策划阶段就确定名称并立即提交软著，不要等开发完再办！

### 红线3：ICP备案（全部主体都需要）

**检查逻辑：**
- 所有主体（个人/企业）的小游戏都必须完成小程序ICP备案（2023年9月起施行）
- 备案主体必须与小程序主体一致
- 备案号格式：粤ICP备2026XXXXXX号-XA（省份前缀不同）
- 检查点：登录 微信公众平台 → 设置 → 基本设置 → 小程序备案 → 查看备案状态

**办理时间线：**
- 通过微信公众平台免费提交：7-20个工作日（平台初审1-2天 + 管局终审7-20个工作日）
- 前置依赖：无需域名和服务器！小程序备案的对象是小程序本身，与网站ICP备案（需域名+服务器）不同
- 具体操作（详见 references/knowledge/sop/icp-filing-sop.md）：
  1. 登录 微信公众平台 → 设置 → 基本设置 → 小程序备案 → 开始备案
  2. 填写主体信息（个人：姓名+身份证；企业：营业执照+法人信息）
  3. 上传材料（身份证正反面/营业执照、负责人手持身份证照等）
  4. 等待平台初审（1-2天）→ 管局终审（7-20个工作日），期间注意接收短信验证

**总计：7-20个工作日，0元费用（自行办理）**

### 红线4：游戏版号（特定品类需要）

**检查逻辑：**
- 2023年后微信小游戏版号政策：
  - 纯广告变现 + 无内购 → 暂不强制要求版号（但政策随时可能收紧）
  - 有内购/虚拟支付 → 必须有版号
  - 含"竞技""对战""卡牌收集"等元素 → 大概率需要版号
- 个人主体：**无法申请版号**（版号只发给有出版资质的企业）
- 企业主体：需要有"网络出版服务许可证"或通过有资质的出版社代理申请

**办理时间线：**
- 自己申请（需有出版资质）：6个月-2年（不现实，除非你是大厂）
- 通过出版社代理：3-12个月，费用5万-30万
- 现实建议：
  - 个人开发者 → 走纯广告变现，不涉及内购则无需版号
  - 小企业 → 先做广告变现版本上架，版号作为长期规划
  - 有预算的企业 → 找代理（推荐：中国新闻出版总署官网查询有资质的出版社名单）

**前置依赖链：** 软著(已下证) → 游戏内容完成 → 提交出版社 → 出版社审核(1-3月) → 提交总署 → 总署审批(3-12月)
**总计：6个月-2年（不可控）**

### 红线5：内容合规（无违规内容）

**检查逻辑（逐项排查）：**
- [ ] 无违规付费机制（不能用真钱/虚拟货币进行金钱投入）
- [ ] 无不当内容（角色穿着、台词、音效均需合规）
- [ ] 无违规视觉表现
- [ ] 无违规内容（地图必须用官方版本、内容需通过平台安全审核）
- [ ] 无宗教争议内容
- [ ] 无未成年人不当内容（如果面向未成年人，不能有强制消费引导）
- [ ] 无侵权内容（角色形象、音乐、字体都要有授权）

**具体操作：**
- 地图问题：使用自然资源部官网（www.mnr.gov.cn）的标准地图底图，不要自己画中国地图
- 字体问题：使用免费商用字体（思源黑体、阿里巴巴普惠体、站酷免费字体），不要用微软雅黑（有版权）
- 音乐问题：使用免费商用音乐库（爱给网 aigei.com 筛选"可商用"、FreePD.com）

### 红线6：隐私政策合规

**检查逻辑：**
- 必须有隐私政策页面，且在游戏内可访问（设置→隐私政策）
- 首次打开游戏必须弹出隐私授权弹窗
- 不能强制授权（用户拒绝后仍可游玩基础功能）
- 收集的信息必须与功能对应（不能收集位置信息却不用）

**具体操作：**
- 微信后台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 填写
- 必须勾选实际使用的接口：
  - 头像昵称填写能力（wx.chooseAvatar / input type="nickname"）→ 勾选"用户信息（昵称、头像）"（wx.getUserInfo 已废弃，2022年10月起不再返回昵称/头像）
  - `wx.getLocation` → 勾选"位置信息"（如果不用就别勾）
  - `wx.getStorage` → 勾选"设备信息"
- 代码中在 `app.js` 的 `onLaunch` 里调用 `wx.requirePrivacyAuthorize()`

---

### 红线7：未成年人保护

**检查逻辑：**
- 必须接入微信的未成年人防沉迷系统（2021年9月起强制）
- 不能向未成年人提供付费服务（如果游戏有内购）
- 现行规则：未成年人仅周五/六/日及法定节假日 20:00-21:00 可玩 1 小时，其余时间禁止登录（详见 references/knowledge/sop/anti-addiction-sop.md）

**具体操作：**
- 微信后台 → 功能 → 未成年人保护 → 开启
- 代码中调用 `wx.checkIsUserAdvisedToRest()` 判断是否需要弹出休息提示
- 如果有内购：在支付前调用 `wx.checkIsMinor()` 判断是否未成年

---

### 红线8：广告合规（如果接入广告）

**检查逻辑：**
- 广告不能遮挡核心操作区域
- 激励视频广告必须明确告知用户"看广告获得XX奖励"
- 不能强制用户看广告才能继续游戏（激励视频必须可跳过）
- 插屏广告不能在游戏核心操作时弹出（如跳跃、消除的瞬间）
- Banner广告不能放在误触区域（如"下一步"按钮旁边）

**具体操作：**
- 使用微信官方广告组件：`wx.createRewardedVideoAd()`、`wx.createBannerAd()`、`wx.createInterstitialAd()`
- 不要用第三方广告SDK（会被拒审）
- 广告频率：插屏广告间隔不少于60秒

---

### 红线9：虚拟支付合规

**检查逻辑（小游戏虚拟支付仅 Android 支持，iOS 以官方文档为准）：**
- **Android 端**：必须使用微信官方虚拟支付（米大师）`wx.requestMidasPayment()`，不能接支付宝/微信H5支付。
- **iOS 端**：微信小游戏官方虚拟支付文档标注**未开放**（仅 Android 支持）。`requestVirtualPayment`/`checkIsSupportMidasPayment`/`requestMidasPaymentGameItem` 等为**小程序**虚拟支付 2.0 API，**不适用于小游戏**，禁止在小游戏项目中套用小程序 API。iOS 开放状态以微信小游戏官方文档实时核实为准（执行前须二次核实）。
- 个人主体：完全不能做虚拟支付（无论 Android/iOS）。
- 价格必须明示，不能有"随机金额"。

**具体操作：**
- 微信后台 → 功能 → 虚拟支付 → 开通（需企业主体+已上架）
- 接入米大师API：`wx.requestMidasPayment()`（Android）
- iOS 端未开放前不要展示付费入口（用 `wx.getSystemInfoSync().platform === 'ios'` 判断，隐藏付费按钮）

---

### 红线10：分享机制合规

**检查逻辑：**
- 不能强制分享才能继续游戏（"分享到3个群才能复活"→ ❌ 违规）
- 不能进行无深度互动的违规分享奖励（"分享后无需任何互动即获得金币/道具/体力/续命等奖励"→ ❌ 违规；奖励必须与被分享者的深度互动绑定，且不得作为进入/继续游戏的前提）
- 分享文案不能包含"转发""扩散"等引导分享的措辞

**具体操作：**
- 使用 `wx.shareAppMessage()` 实现分享，仅提供"用户主动点击分享"入口
- 稳妥做法：分享按钮点击后**不给予任何游戏内奖励**（微信已关闭分享成功回调，无法也不应判断"是否真的分享了"）
- 合规替代方案：好友排行榜展示、分享炫耀卡片、群排行等不依赖奖励的社交能力
- 确有"邀请好友组队/协作"奖励需求时，确保存在可验证的深度互动，并以微信官方最新运营规范为准

---

### 红线11：类目选择正确

**检查逻辑：**
- 游戏类目必须与实际玩法匹配
- 个人主体可选类目有限：休闲游戏、益智游戏
- 企业主体可选：所有游戏类目
- 不能选"工具"类目上架游戏（会被下架）

**具体操作：**
- 微信后台 → 设置 → 基本设置 → 服务类目 → 选择"游戏"大类 → 选择子类
- 如果类目不对：设置 → 基本设置 → 服务类目 → 修改（每月只能修改1次）

---

### 红线12：无作弊机制

**检查逻辑：**
- 不能内置修改器、加速器等作弊功能
- 排行榜分数必须有服务端校验（不能纯前端计算后直接提交）
- 不能有"无限金币""无敌模式"等违规获取优势的功能

**具体操作：**
- 分数提交必须有签名验证：前端计算分数 → 用密钥签名 → 服务端验证签名 → 写入排行榜
- 使用微信云开发的数据库存储分数（自带鉴权）
- 设置分数上限校验（如消除游戏单次不可能超过100万分）

---

### 红线13：无强制关注/下载

**检查逻辑：**
- 不能引导用户关注公众号才能玩游戏
- 不能引导下载其他APP
- 不能在游戏内展示其他平台的二维码

---

### 红线14：无虚假宣传

**检查逻辑：**
- 游戏截图/视频必须是实际游戏画面（不能用CG渲染图冒充）
- 游戏名称不能包含广告法禁止的绝对化用语（如"最好""第一""唯一"等宣称表述）
- 描述中的功能必须实际存在（不能写"百人同屏"实际只有单机）

## 个人 vs 企业：合规路径差异

### 对比表

| 合规项 | 个人主体 | 企业主体 |
|--------|----------|----------|
| 软著 | 微信 IAA 非必填（自我声明）；IAP 必填 | 微信 IAA 非必填；IAP 必填；抖音等必填 |
| ICP备案 | ✅ 必须（免费，走微信公众平台） | ✅ 必须（免费，走微信公众平台） |
| 版号 | ❌ 无法申请（纯广告变现不涉及内购则无需版号） | ⚠️ 有内购则必须（可代理申请） |
| 虚拟支付 | ❌ 完全不能开通 | ✅ 可开通（米大师） |
| 广告变现 | ✅ 可以（流量主） | ✅ 可以（流量主） |
| 可选类目 | 休闲游戏、益智游戏 | 所有游戏类目 |
| 未成年人保护 | ✅ 必须 | ✅ 必须 |
| 隐私政策 | ✅ 必须 | ✅ 必须 |

### 个人开发者合规路径（最简路径）

```
确定游戏名称 → 申请软著(30-60天) → 开发游戏 → 接入广告SDK → 
写隐私政策 → 接入防沉迷 → 提审 → 上架

总合规时间：30-60天（ICP 备案与软著按平台要求办理，与开发并行）
总费用：0-300元（软著自办免费，加急代办另计）
```

### 企业合规路径（完整路径）

```
确定游戏名称 → 申请软著(30-60天) ─┐
微信公众平台提交ICP备案(7-20天) ─┼─→ 开发游戏 → 接入支付+广告 → 
                                    │   写隐私政策 → 接入防沉迷 → 提审 → 上架
[如需版号] 找出版社代理(6-12月) ────┘

总合规时间：
  - 无版号（纯广告）：30-60天（ICP 备案与软著按平台要求办理）
  - 有版号（含内购）：6-12个月（版号是瓶颈）
总费用：
  - 无版号：0-500元（软著自办免费，加急代办另计）
  - 有版号：5万-30万元（版号代理费）
```

## 合规检查触发时机

### 自动触发（系统主动检查）

| 时机 | 检查内容 | 输出 |
|------|----------|------|
| 用户确定游戏名称时 | 名称是否可用（查重+敏感词） | 名称可用性报告 |
| 策划文档完成时 | 玩法是否涉及版号（内购/竞技/卡牌） | 合规路径建议 |
| 开发进入第2周时 | 提醒软著进度（如果还没申请则红色警告） | 软著进度追踪 |
| 接入支付SDK时 | 检查主体是否有资格（个人→阻止） | 支付资格校验 |
| 提审前 | 14条红线全量检查 | 合规检查报告 |
| 审核被拒时 | 分析拒绝原因 → 匹配红线编号 | 修复方案 |

### 手动触发（用户主动询问）

用户说"帮我检查合规"/"能不能上架"/"审核要注意什么" → 执行14条红线全量检查

## 驳回后的修复流程

### Step 1: 解读拒绝原因

微信审核拒绝时会给出原因描述，常见原因与对应红线：

| 微信拒绝原因（原文） | 对应红线 | 修复难度 |
|---------------------|----------|----------|
| "未提供软件著作权证书" | 红线2 | 高（需等软著下证） |
| "游戏名称与软著名称不一致" | 红线2 | 低（改名或重新申请软著） |
| "存在违规分享奖励行为" | 红线10 | 低（改代码） |
| "虚拟支付未使用米大师" | 红线9 | 中（改支付逻辑） |
| "缺少隐私政策" | 红线6 | 低（补上） |
| "游戏内容与类目不符" | 红线11 | 低（改类目） |
| "存在违规内容" | 红线5 | 中（改素材） |
| "广告展示不合规" | 红线8 | 低（调广告位置） |

### Step 2: 制定修复方案

```
修复方案模板：

问题：[微信拒绝原因原文]
对应红线：红线X - [名称]
修复步骤：
  1. [具体操作，精确到代码行/后台按钮]
  2. [具体操作]
  3. [具体操作]
预计修复时间：X小时/天
修复后验证：[怎么确认修好了]
重新提审：修改完成后 → 微信后台 → 版本管理 → 提交审核
```

### Step 3: 修复后重新提审

- 修复完成后，在微信后台 → 版本管理 → 开发版本 → 提交审核
- 审核周期：1-7个工作日（通常1-3天）
- 同一版本最多被拒3次，第4次会被锁定24小时
- 如果被拒2次以上同一原因 → 建议联系微信客服（mp.weixin.qq.com → 客服 → 提交工单）

## 名称锁定警告（专项）

### 触发时机

每当用户提到/修改游戏名称时，立即触发以下检查：

### 检查流程

```
1. 名称可用性检查：
   - 打开微信后台 → 小程序 → 设置 → 基本设置 → 名称 → 检测是否已被占用
   - 或直接在注册页面尝试输入名称，系统会实时提示是否可用

2. 敏感词检查：
   - 不能包含：已注册的游戏/品类商标名（需查询确认）
   - 检查方式：中国商标网（sbj.cnipa.gov.cn）→ 商标查询 → 输入名称 → 查看是否有近似商标

3. 名称锁定提醒：
   "⚠️ 名称锁定警告：
    你确定的游戏名称是'XXX'。请注意：
    - 软著申请时的软件全称 = 游戏名称，必须一字不差（不加 V1.0/软件/系统 等任何后缀）
    - 微信后台的小程序名称必须填'XXX'
    - 游戏内的标题/关于页面显示的名称必须是'XXX'
    - 上架后改名需要重新提审，且每年只能改2次
    所以：现在确定，后面就别改了。"
```

### 名称变更处理

如果用户在软著申请后想改名：
- 软著未下证 → 撤回重新申请（免费，但重新排队）
- 软著已下证 → 做软著变更（中国版权保护中心 → 软件登记 → 变更/补充登记，30天）
- 或者：改游戏名称去匹配软著（更省事）
