# 数据分析引擎

## 核心指标表

### 基准线（低于基准=有问题，必须排查）

| 指标 | 健康值 | 警戒值 | 危险值 | 说明 |
|------|--------|--------|--------|------|
| 次日留存 | ≥30% | 25-30% | <25%（需预警） | 第一天玩了，第二天还来 |
| 7日留存 | ≥15% | 10-15% | <10% | 一周后还在玩 |
| 30日留存 | ≥5% | 3-5% | <3% | 一个月后还在玩 |
| 平均游戏时长 | 8-15分钟 | 5-8分钟 | <5分钟 | 单次会话时长 |
| 日均启动次数 | ≥2次 | 1.5-2次 | <1.5次 | 一天打开几次 |
| 广告渗透率 | 40-60% | 25-40% | <25% | 看了广告的用户占比 |
| 人均广告次数 | ≥3次 | 2-3次 | <2次 | 每用户每天看几次广告 |
| eCPM（激励视频） | 40-120元 | 20-40元 | <20元 | 千次展示收入 |
| eCPM（插屏广告） | 15-40元 | 8-15元 | <8元 | 千次展示收入 |
| 分享率 | ≥10% | 5-10% | <5% | 主动分享的用户占比 |
| 分享回流率 | ≥20% | 10-20% | <10% | 点了分享链接进来的人占比 |
| 新手引导完成率 | ≥80% | 60-80% | <60% | 走完新手教程的比例 |

## 危险信号识别

### 看到这些数据，说明这些问题

| 数据表现 | 大概率原因 | 验证方法 | 修复方向 |
|---------|-----------|---------|---------|
| 次留<15% | 新手引导失败/第一关太难/加载太慢 | 看新手引导漏斗+首关通过率 | 简化引导、降首关难度、优化加载 |
| 次留OK但7留骤降 | 缺乏长期目标/内容消耗完/没有成长线 | 看用户最后玩到哪一关 | 加成长系统、增加内容深度 |
| 时长<3分钟 | 核心循环不够吸引/不知道干什么 | 看用户行为路径热力图 | 强化核心循环反馈、明确目标引导 |
| 时长>30分钟但留存低 | 一次玩爽了但没有回来的理由 | 看是否有每日目标/签到/限时内容 | 加每日任务、体力系统、限时活动 |
| 广告渗透<20% | 广告位设计不合理/用户不知道能看广告 | 看广告按钮点击热力图 | 调整广告入口位置、增强奖励吸引 |
| 广告渗透>80% | 广告太多用户反感（短期数据好但留存会崩） | 看7留趋势是否在下降 | 减少强制广告、增加用户主动选择 |
| 分享率<3% | 分享入口不明显/分享没有动力/卡片不吸引 | 看分享按钮曝光→点击→完成漏斗 | 优化分享卡片、增加分享动力 |
| 分享多但回流<5% | 分享卡片标题/图片不吸引/链接打开体验差 | 看卡片点击率 | 优化卡片文案和图片 |
| eCPM持续下降 | 广告填充率下降/用户质量下降/季节性 | 对比不同广告平台数据 | 多平台bidding、优化用户质量 |
| 新增高但留存低 | 买量用户质量差/渠道不匹配 | 分渠道看留存 | 调整投放素材/定向/渠道 |

### 紧急告警规则（日级监控）

```
P0（立即处理）：
- 次留单日下降>10个百分点 → 可能有严重bug或服务器问题
- 崩溃率>2% → 立即查crash日志
- 广告收入单日下降>50% → 广告SDK可能挂了

P1（24小时内处理）：
- 新手引导完成率<50% → 引导流程有阻断
- 某关卡通过率<30% → 难度曲线断了
- 分享功能使用率突降 → 可能被微信限制了

P2（本周处理）：
- 7留连续3天下降 → 内容消耗/疲劳
- 人均广告次数持续下降 → 广告位需要优化
- 新增用户质量下降 → 渠道问题
```

## 埋点设计指南

### 必须埋的事件（上线前缺一不可）

| 事件名 | 触发时机 | 必带参数 | 用途 |
|--------|---------|---------|------|
| app_launch | 每次启动 | source(来源)、is_new_user | 计算DAU、渠道归因 |
| app_hide | 切后台/关闭 | duration(本次时长)、current_level | 计算时长、流失节点 |
| ftue_step | 新手引导每步 | step_id、step_name、result(完成/跳过) | 新手漏斗分析 |
| level_start | 进入关卡 | level_id、level_type、attempt_count | 关卡分析 |
| level_complete | 通关 | level_id、duration、score、star_count | 难度评估 |
| level_fail | 失败 | level_id、fail_reason、progress_percent | 卡点定位 |
| ad_show | 广告展示 | ad_type(激励/插屏/Banner)、ad_position、ad_platform | 广告分析 |
| ad_click | 点击广告 | ad_type、ad_position、ad_platform | 广告转化 |
| ad_complete | 看完广告 | ad_type、ad_position、reward_type | 广告完成率 |
| ad_fail | 广告加载失败 | ad_type、error_code、ad_platform | 广告填充监控 |
| share_trigger | 触发分享 | share_type(主动/被动)、share_content | 分享分析 |
| share_success | 分享完成 | share_channel(好友/群/朋友圈) | 分享渠道分析 |
| share_callback | 分享回流 | from_user_id、share_content | 裂变效果 |
| purchase_click | 点击购买 | item_id、item_price、item_type | 付费漏斗 |
| purchase_complete | 支付完成 | item_id、item_price、currency_type | 付费分析 |
| coin_earn | 获得货币 | amount、source(关卡/广告/任务) | 经济系统监控 |
| coin_spend | 消耗货币 | amount、sink(道具/复活/解锁) | 经济系统监控 |
| error_occur | 报错 | error_type、error_msg、current_scene | 稳定性监控 |

### 埋点实施规范

```typescript
// 统一埋点接口（封装后全项目调用这一个）
class Analytics {
    static track(event: string, params: Record<string, any>) {
        // 1. 本地缓存（防丢）
        this.buffer.push({ event, params, ts: Date.now() });
        
        // 2. 批量上报（每10条或每30秒）
        if (this.buffer.length >= 10) this.flush();
        
        // 3. 微信数据助手上报
        wx.reportEvent(event, params);
        
        // 4. 第三方平台上报（友盟/TalkingData）
        this.thirdPartyTrack(event, params);
    }
    
    static flush() {
        // 批量发送到自己的服务端（用于深度分析）
        wx.request({
            url: '你的服务端/analytics/batch',
            method: 'POST',
            data: { events: this.buffer, device: this.deviceInfo }
        });
        this.buffer = [];
    }
}

// 使用示例
Analytics.track('level_complete', {
    level_id: 15,
    duration: 45,      // 秒
    score: 3200,
    star_count: 3,
    revive_used: false
});
```

### 埋点常见错误

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 只在成功时埋点 | 不知道失败了多少次 | 成功/失败都埋 |
| 参数用中文 | 分析时分组失控 | 用英文枚举值 |
| 没有用户ID | 无法做用户级分析 | 每个事件带user_id |
| 没有版本号 | 无法对比版本效果 | 每个事件带app_version |
| 埋点太多（>50个） | 数据噪音大、存储贵 | 核心事件≤20个，按需扩展 |
| 上线后才加埋点 | 前期数据空白 | 开发阶段就埋好 |

## 数据驱动决策框架

### 每周复盘5步（固定周一做）

```
第1步：看大盘（5分钟）
- 本周DAU趋势（对比上周）
- 本周新增用户数（对比上周）
- 本周广告收入（对比上周）
- 一句话总结：涨了/跌了/持平

第2步：看留存（10分钟）
- 本周新用户次留 vs 上周
- 本周新用户7留 vs 上周
- 如果下降 → 立即定位是哪天新增的用户留存差 → 那天发生了什么

第3步：看漏斗（10分钟）
- 新手引导完成率（分步骤看哪步流失最多）
- 前5关通过率（哪关是卡点）
- 广告触发→展示→完成漏斗（哪步损失最大）

第4步：看异常（5分钟）
- 崩溃率是否>1%
- 广告填充率是否<90%
- 是否有异常数据（某天突然暴涨/暴跌）

第5步：定行动（10分钟）
- 本周最重要的1个数据问题是什么
- 下周要做的1个优化是什么
- 预期效果是什么（量化）
- 谁来做、什么时候完成
```

### 决策矩阵

| 数据信号 | 判断 | 行动 | 优先级 |
|---------|------|------|--------|
| 次留<20% + 引导完成率<60% | 新手体验有严重问题 | 重做新手引导 | P0 |
| 次留<20% + 引导完成率>80% | 核心玩法不吸引 | 调整核心循环 | P0 |
| 次留OK + 7留<10% | 缺乏长期动力 | 加成长线/每日目标 | P1 |
| 时长<5min + 广告渗透<30% | 用户没玩到广告位就走了 | 前置广告触发点 | P1 |
| 分享率<5% + 新增全靠自然 | 社交传播没做起来 | 优化分享机制+卡片 | P1 |
| eCPM<15元 | 广告变现效率低 | 换广告平台/优化bidding | P2 |
| 所有指标都OK + DAU不涨 | 产品OK但缺量 | 投入增长（见growth.md） | P2 |

## 分析工具推荐

| 工具 | 适用场景 | 费用 | 优缺点 |
|------|---------|------|--------|
| 微信数据助手（官方） | 基础数据：DAU/留存/时长/来源 | 免费 | 数据准但维度少，不能自定义事件 |
| 微信小游戏数据助手 | 小游戏专属：关卡/广告/分享 | 免费 | 有广告数据，但分析能力弱 |
| 友盟+ | 自定义事件/漏斗/用户分群 | 免费（基础版） | 功能全，但接入有学习成本 |
| TalkingData | 游戏专属分析/留存/付费 | 免费（基础版） | 游戏行业用得多，报表好看 |
| 自建（服务端+BI） | 深度分析/自定义报表 | 服务器成本 | 最灵活但最贵，DAU>10万再考虑 |

### 推荐组合

```
个人开发者（零成本）：
  微信数据助手（看大盘） + 自建简单埋点上报（看细节）
  
小团队（千元级）：
  微信数据助手 + 友盟（自定义事件+漏斗）
  
成熟项目（DAU>5万）：
  微信数据助手 + TalkingData + 自建BI（Metabase/Grafana）
```

## 流失漏斗分析方法

### 标准漏斗（从新增到付费）

```
新增用户 100%
    │
    ├─ 完成加载 ──────── 目标≥95%（<90%说明包体太大/加载太慢）
    │
    ├─ 完成新手引导 ──── 目标≥80%（<60%说明引导有问题）
    │
    ├─ 通过第1关 ─────── 目标≥90%（<70%说明第1关太难）
    │
    ├─ 通过第5关 ─────── 目标≥70%（<50%说明前5关难度曲线陡）
    │
    ├─ 触发首次广告 ──── 目标≥60%（<40%说明广告位太靠后）
    │
    ├─ 看完首次广告 ──── 目标≥80%（<60%说明奖励不够吸引）
    │
    ├─ 次日回来 ──────── 目标≥30%（<20%说明没有回来的理由）
    │
    ├─ 7日后还在 ─────── 目标≥15%（<10%说明长期内容不足）
    │
    └─ 产生分享行为 ──── 目标≥10%（<5%说明社交动力不足）
```

### 漏斗分析操作步骤

```
1. 拉数据：按天拉新增用户的各步骤完成人数
2. 算转化率：每步完成人数 / 上一步完成人数
3. 找断点：哪一步转化率最低（或低于目标值最多）
4. 定位原因：
   - 加载流失 → 看加载时长分布、看是否某个资源特别大
   - 引导流失 → 看流失在哪一步、那一步做了什么
   - 关卡流失 → 看失败次数分布、看用户最后操作
   - 广告流失 → 看是"没触发"还是"触发了不看"
5. 做改动：只改断点那一步（不要同时改多处）
6. 验证：改动上线后对比前后3天数据
```

### 关卡难度分析模板

| 关卡 | 进入人数 | 通过人数 | 通过率 | 平均尝试次数 | 平均时长 | 判断 |
|------|---------|---------|--------|-------------|---------|------|
| 1 | 1000 | 950 | 95% | 1.1 | 30s | 正常 |
| 2 | 950 | 880 | 93% | 1.3 | 45s | 正常 |
| 3 | 880 | 700 | 80% | 2.1 | 90s | 略难（可接受） |
| 5 | 700 | 350 | 50% | 4.5 | 180s | 太难（需调整） |
| 10 | 350 | 100 | 29% | 8.2 | 300s | 劝退关（必须改） |

判断标准：
- 通过率>90%：太简单（考虑加难度）
- 通过率70-90%：健康
- 通过率50-70%：有挑战（可接受，但要看是否有关卡奖励兜底）
- 通过率<50%：太难（必须降难度或加辅助道具）
- 通过率<30%：劝退（用户大概率在这里流失）

## A/B测试框架

### 什么时候做A/B测试

- DAU > 1000（样本太少结论不可靠）
- 有明确假设（不是"试试看"）
- 改动可量化（能用数据判断好坏）
- 改动可回滚（万一B组更差能切回来）

### A/B测试流程

```
第1步：提出假设
格式：如果我们[做什么改动]，那么[哪个指标]会[提升/降低X%]，因为[原因]
示例：如果我们把第3关的敌人数量从8个减到5个，那么第3关通过率会从65%提升到80%，
      因为当前失败率太高导致用户挫败感强

第2步：设计实验
- 对照组(A)：当前版本（敌人8个）
- 实验组(B)：修改版本（敌人5个）
- 分流方式：按用户ID尾号（0-4=A组，5-9=B组）
- 样本量：每组至少500人（置信度95%）
- 实验周期：至少7天（覆盖一个完整周期）

第3步：执行
- 服务端根据user_id % 10 分组
- 下发不同配置（不要发两个包，用配置控制）
- 埋点带group参数（A/B）

第4步：收集数据
- 核心指标：第3关通过率、次留、7留
- 辅助指标：第3关平均时长、失败后是否继续
- 护栏指标：广告收入不能显著下降

第5步：分析决策
- 通过率提升>10% + 留存不降 → 全量上线B
- 通过率提升但留存降了 → 不上线（说明难度是留存动力）
- 没有显著差异 → 不上线（改动没意义）
- 显著变差 → 立即回滚

第6步：记录
- 记录实验结论到知识库
- 无论成功失败都是学习
```

### A/B测试注意事项

| 注意点 | 说明 |
|--------|------|
| 一次只测一个变量 | 同时改多处无法归因 |
| 不要偷看数据提前下结论 | 至少跑满预设周期 |
| 新用户和老用户分开看 | 改动对新旧用户影响可能相反 |
| 注意节假日/周末效应 | 周末数据和工作日不同 |
| 样本量不够不要硬下结论 | 500人以下只能说"趋势"不能说"结论" |

## 收益预估模型

### 广告收入公式

```
日广告收入 = DAU × 人均广告次数 × eCPM / 1000 × 填充率

月广告收入 = 日广告收入 × 30 × 0.7（微信分成后）

注：微信广告分成比例：
- 安卓：开发者拿70%（微信拿30%）
- iOS：2024年后也是70%（之前是50%）
- 0.7是保守估计（含税务等）
```

### 收益预估表（保守/中性/乐观）

| 场景 | DAU | 人均广告次数 | eCPM | 填充率 | 日收入 | 月收入(×30×0.7) |
|------|-----|-------------|------|--------|--------|----------------|
| 极早期 | 100 | 2 | 30 | 80% | 4.8元 | 101元 |
| 小有所成 | 1,000 | 3 | 40 | 85% | 102元 | 2,142元 |
| 中等水平 | 5,000 | 3.5 | 50 | 90% | 788元 | 16,538元 |
| 做得不错 | 20,000 | 4 | 55 | 90% | 3,960元 | 83,160元 |
| 头部水平 | 100,000 | 4.5 | 60 | 95% | 25,650元 | 538,650元 |

> ⚠️ 上表为纯公式推算示例（DAU×人均次数×eCPM/1000×填充率×30×0.7），仅用于理解收入构成，**不构成收益承诺**。实际收入取决于留存、单价、填充率及平台政策，通常显著低于乐观档，使用前须以官方数据助手实时验证为准。

### 预估时的诚实检查

```
问自己这几个问题：
1. DAU预估依据是什么？
   - "我觉得能到1万" → 没有依据，按100算
   - "同品类同体量的竞品DAU是X" → 有参考，按竞品的30%算
   - "我已经有X个种子用户" → 按种子用户×3算天花板

2. 人均广告次数预估依据？
   - 休闲游戏通常3-5次
   - 中重度游戏通常1-3次
   - 新游戏前两周会偏高（新鲜感），之后下降20-30%

3. eCPM预估依据？
   - 激励视频：40-120元（取80元比较中性）
   - 插屏：15-40元（取25元）
   - Banner：3-10元（取5元，基本可以忽略）
   - 节假日（春节/国庆）eCPM会涨30-50%
   - 1月/9月是广告淡季，eCPM会降20-30%

4. 最坏情况能不能接受？
   - 按最保守估计（DAU×0.3，eCPM×0.5）算一遍
   - 如果最坏情况连服务器成本都覆盖不了 → 重新评估
```

### 收入结构优化方向

| 优化方向 | 预期提升 | 难度 | 优先级 |
|---------|---------|------|--------|
| 增加广告位（从2个到4个） | +40-60%收入 | 低 | 高 |
| 优化广告触发时机 | +15-25%渗透率 | 中 | 高 |
| 多平台bidding（多家广告平台聚合） | +20-30% eCPM | 中 | 中 |
| 增加内购（需企业+版号） | +50-200%收入 | 高 | 看条件 |
| 提升留存（DAU稳定增长） | 长期复利 | 高 | 最高 |
