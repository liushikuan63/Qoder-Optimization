# 决策树定义文件

> 微信小游戏全流程决策引擎。根据用户输入条件，沿决策树路径给出结构化建议。

---

## 一、游戏类型选择决策树

### 入口判断

```
用户输入 → 判断意图类型
├── A. 用户不确定做什么 → 走「品类推荐路径」
├── B. 用户有明确想法 → 走「可行性评估路径」
└── C. 用户想听建议 → 走「蓝海推荐路径」
```

### A. 品类推荐路径（用户不确定）

**Step 1: 采集条件**

| 采集项 | 选项 | 权重 |
|--------|------|------|
| 技术背景 | 无编程经验 / 前端开发 / 游戏开发 / 全栈 | 高 |
| 可投入时间 | 兼职(每周<10h) / 半职(10-30h) / 全职(>30h) | 高 |
| 预算范围 | 0元 / <5000 / 5000-2万 / >2万 | 中 |
| 美术能力 | 无 / 会简单像素画 / 有设计基础 / 可外包 | 中 |
| 目标 | 学习练手 / 赚零花钱 / 全职收入 / 创业 | 高 |
| 偏好类型 | 休闲 / 益智 / 动作 / 模拟经营 / 无偏好 | 低 |

**Step 2: 匹配品类**

| 条件组合 | 推荐品类 | 理由 |
|----------|----------|------|
| 无编程+兼职+0预算 | 合成类/消除类(模板改) | 逻辑简单，模板多，2周可出 |
| 无编程+全职+有预算 | 放置类/模拟经营(外包) | 数值驱动，美术可买素材 |
| 前端开发+兼职 | 文字类/答题类/轻休闲 | 无需游戏引擎，纯逻辑 |
| 前端开发+全职 | roguelike/塔防/卡牌 | 有深度空间，留存好 |
| 游戏开发+任意 | 中重度休闲/混合玩法 | 技术不是瓶颈，拼创意 |
| 有美术+任意 | 视觉驱动型(装扮/装修/涂色) | 美术是核心壁垒 |

**Step 3: 排序推荐**

输出格式：
```
推荐排序：
1. [品类名] - 匹配度 XX%
   理由：...
   代表案例：...
   预估开发周期：...
   预估月收入区间：...
2. [品类名] - 匹配度 XX%
   ...
3. [品类名] - 匹配度 XX%
   ...
```

### B. 可行性评估路径（用户有想法）

**四维评估矩阵：**

| 维度 | 评估指标 | 评分标准 |
|------|----------|----------|
| 市场饱和度 | 同品类在线数量/头部集中度/新品存活率 | 1-5分，5=蓝海 |
| 个人适配度 | 技术匹配/时间匹配/兴趣匹配/能力匹配 | 1-5分，5=完美匹配 |
| 开发成本 | 时间成本/资金成本/机会成本 | 1-5分，5=极低成本 |
| 收入天花板 | 品类ARPU/广告eCPM/用户规模上限 | 1-5分，5=天花板高 |

**判定规则：**

| 总分(满分20) | 判定 | 建议 |
|--------------|------|------|
| 16-20 | GO | 立即启动，给出执行计划 |
| 12-15 | GO(附条件) | 可以做，但需调整XX方面 |
| 8-11 | CAUTION | 风险较高，建议调整方向或降低投入 |
| 4-7 | STOP | 强烈不建议，给出替代方案 |
| 0-3 | STOP(紧急) | 明确告知不可行原因，推荐3个替代方向 |

**输出格式：**
```
可行性评估报告
━━━━━━━━━━━━━━
想法：[用户描述]
品类归属：[判断]

市场饱和度：X/5 - [分析]
个人适配度：X/5 - [分析]
开发成本：  X/5 - [分析]
收入天花板：X/5 - [分析]

总分：XX/20
判定：[GO/CAUTION/STOP]

详细说明：...
调整建议：...（如适用）
```

### C. 蓝海推荐路径（用户想听建议）

**输出结构：**

1. **蓝海品类推荐**（当前竞争度低、增长中的品类）
   - 品类名称 + 为什么是蓝海 + 数据支撑
   
2. **窗口期判断**
   - 该品类处于什么阶段（萌芽/增长/成熟/衰退）
   - 预估窗口期剩余时间
   - 进入建议（立即/观望/放弃）

3. **个人友好品类**（适合个人开发者的）
   - 开发周期短（<1个月）
   - 不需要服务器或轻量服务器
   - 美术要求低或可用AI生成
   - 变现路径清晰

## 二、合规路径决策树

### 入口判断

```
开发者类型？
├── 个人开发者 → 路径A
└── 企业开发者 → 路径B
```

### 路径A：个人开发者

**必办清单（缺一不可）：**

| 序号 | 事项 | 办理方式 | 耗时 | 费用 | 前置条件 |
|------|------|----------|------|------|----------|
| 1 | 微信小游戏账号注册(个人主体) | mp.weixin.qq.com | 1天 | 免费 | 身份证+手机号 |
| 2 | 实名认证 | 平台内完成 | 即时 | 免费 | 账号注册 |
| 3 | 类目选择(个人可选类目) | 平台内选择 | 即时 | 免费 | 账号注册 |
| 4 | 隐私保护指引配置 | 平台内填写 | 0.5天 | 免费 | 无 |
| 5 | 游戏自审自查报告 | 按模板填写 | 0.5天 | 免费 | 游戏开发完成 |
| 6 | 软件著作权(软著，按变现模式) | 微信 IAA 非必填（自我声明）；IAP 必填 | 30-60工作日 | 免费(自办)/300-800(代办) | 游戏开发完成 |

**可选清单（提升竞争力/解锁功能）：**

| 序号 | 事项 | 适用场景 | 耗时 | 费用 |
|------|------|----------|------|------|
| 1 | 商标注册 | 品牌保护 | 6-12月 | 300元/类 |
| 2 | ICP备案(如有官网) | 有独立官网时 | 7-20工作日 | 免费 |
| 3 | 美术素材版权登记 | 原创美术保护 | 30工作日 | 100-300元 |

**个人开发者限制提醒：**
- 不可开通虚拟支付（内购）
- 不可选择部分类目（如棋牌、竞技对战）
- 广告变现为主要收入方式
- 单日广告展示有上限

### 路径B：企业开发者

**必办清单：**

| 序号 | 事项 | 办理方式 | 耗时 | 费用 | 前置条件 |
|------|------|----------|------|------|----------|
| 1 | 营业执照(含相关经营范围) | 工商局/线上 | 3-7天 | 0-500 | 无 |
| 2 | 微信小游戏账号注册(企业主体) | mp.weixin.qq.com | 1-3天 | 300元认证费 | 营业执照 |
| 3 | 对公账户开通 | 银行 | 3-7天 | 视银行 | 营业执照 |
| 4 | 类目选择+资质上传 | 平台内 | 1天 | 免费 | 账号认证 |
| 5 | 隐私保护指引配置 | 平台内 | 0.5天 | 免费 | 无 |
| 6 | 游戏自审自查报告 | 按模板填写 | 0.5天 | 免费 | 开发完成 |
| 7 | 软件著作权(软著，按变现模式) | 微信 IAA 非必填；IAP/抖音必填 | 30-60工作日 | 免费-800 | 开发完成 |

**版号判断分支：**

```
游戏是否含内购付费？
├── 否（纯广告变现）→ 无需版号，走备案即可
└── 是（含内购）→ 需要版号
    ├── 是否已有版号？
    │   ├── 是 → 直接使用
    │   └── 否 → 申请版号（周期6-18个月）
    │       ├── 是否等得起？
    │       │   ├── 是 → 先开发，版号下来再开内购
    │       │   └── 否 → 先纯广告上线，后续再开内购
    │       └── 版号申请材料清单 → [输出清单]
    └── 注意：2024年起小游戏也需版号（含内购的）
```

**内容备案判断分支：**

```
游戏内容是否涉及以下？
├── 历史题材 → 需额外审核材料
├── 军事题材 → 需额外审核材料
├── 宗教元素 → 需谨慎处理，咨询主管部门
├── 竞技/对战 → 需确认类目资质
├── 社交功能(聊天/组队) → 需额外合规审查
└── 以上均无 → 标准流程即可
```

### 时间线排列

**个人开发者推荐时间线：**
```
第1天：注册账号 + 实名认证 + 选类目 + 确定游戏名称
第1-5天：提交软著申请（与开发并行，越早越好）
第1-30天：开发游戏
第30天：填写隐私指引 + 自审报告
软著下证（状态为"已授权"）后：提交审核
审核通过 → 上线
（⚠️ 软著必须下证后才能提审，资质办理需前置，务必提前规划）
```

**企业开发者推荐时间线：**
```
第1-7天：注册公司/确认经营范围
第7-10天：注册小游戏账号 + 认证 + 对公账户
第10-60天：开发游戏
第50天：提交软著申请
第55天：隐私指引 + 自审报告 + 资质材料
第60天：提交审核
第60-70天：审核通过 → 上线
（如需版号：第10天即开始准备版号材料，与开发并行）
```

## 三、技术选型决策树

### 入口判断

```
按优先级依次判断：
1. 技术背景 → 决定引擎选择范围
2. 游戏类型 → 决定引擎+架构
3. 预算 → 决定资源获取方式
```

### 按技术背景分支

| 技术背景 | 推荐引擎 | 备选 | 理由 |
|----------|----------|------|------|
| 零编程基础 | 微信官方小游戏引擎/低代码平台 | 模板魔改 | 门槛最低 |
| HTML/JS前端 | Cocos Creator | Laya/原生Canvas | JS生态，学习曲线平缓 |
| Unity/C#开发 | Unity(小游戏导出) | Cocos Creator | 复用Unity经验 |
| 游戏行业经验 | Cocos Creator / Unity | 自研引擎 | 按项目需求选 |
| Python/后端开发 | Cocos Creator(学TS) | Godot(导出Web) | 需要学习前端 |

### 按游戏类型分支

| 游戏类型 | 推荐方案 | 性能要求 | 包体限制策略 |
|----------|----------|----------|--------------|
| 文字/答题/知识类 | 原生WXML+JS即可 | 极低 | 无需分包 |
| 2D休闲(消除/合成/跑酷) | Cocos Creator 3.x | 低 | 主包<4MB，资源CDN |
| 2D中度(塔防/卡牌/RPG) | Cocos Creator 3.x | 中 | 分包加载+资源压缩 |
| 2D重度(大量粒子/物理) | Cocos Creator + 优化 | 高 | 纹理压缩+LOD |
| 3D轻度(简单3D场景) | Cocos Creator 3.x / Unity | 高 | 模型压缩+按需加载 |
| 3D中重度 | Unity小游戏方案 | 极高 | 需严格优化，考虑是否适合小游戏 |
| 多人在线 | Cocos + 云开发/自建服务器 | 中-高 | WebSocket/帧同步 |
| 放置/挂机 | Cocos Creator / 原生 | 低 | 离线计算逻辑 |

### 按预算分支

| 预算 | 美术方案 | 音效方案 | 服务器方案 | 工具链 |
|------|----------|----------|------------|--------|
| 0元 | AI生成+免费素材站 | 免费音效库 | 微信云开发免费额度 | 免费工具 |
| <5000 | 素材包购买(淘宝/itch.io) | 付费音效包 | 云开发基础版 | 免费+少量付费 |
| 5000-2万 | 部分外包+素材包 | 定制BGM(1-2首) | 云服务器(轻量) | 正版工具 |
| >2万 | 全外包定制 | 全套定制 | 独立服务器+CDN | 全正版+专业工具 |

### 技术选型输出格式

```
技术选型建议
━━━━━━━━━━━━
引擎：[选择] (版本 X.X)
语言：TypeScript / JavaScript
架构：[单机/联机] [是否需要服务器]
美术管线：[方案]
资源管理：[分包策略]
开发工具：[IDE + 版本管理]
预估学习成本：[X天/周]
```

## 四、上架就绪度决策树

### 14项检查清单

| # | 检查项 | 通过标准 | 未通过处理 |
|---|--------|----------|------------|
| 1 | 游戏可玩性 | 核心循环完整，无阻断性Bug | 修复后重测 |
| 2 | 首次体验 | 3秒内可交互，无强制注册 | 优化加载流程 |
| 3 | 隐私合规 | 隐私指引已配置，弹窗合规 | 按模板配置 |
| 4 | 内容合规 | 无违规内容，符合平台内容安全规范 | 删除/替换违规内容 |
| 5 | 类目匹配 | 游戏内容与所选类目一致 | 调整类目或内容 |
| 6 | 包体大小 | 主包≤4MB，总包≤30MB(含分包) | 资源压缩/CDN化 |
| 7 | 性能达标 | 首屏<3s，帧率≥30fps，内存≤256MB(低端机≤200MB) | 性能优化 |
| 8 | 适配测试 | 主流机型（iOS/安卓头部品牌机型）无异常 | 修复适配问题 |
| 9 | 广告配置 | 广告位合理，不强制，频次合规 | 调整广告策略 |
| 10 | 分享功能 | 分享文案/图片合规，不强制 | 修改分享逻辑 |
| 11 | 用户协议 | 用户协议+隐私政策可访问 | 补充文档 |
| 12 | 软著/资质 | 软著已提交(至少受理通知) | 加急办理 |
| 13 | 自审报告 | 自审自查报告已填写完整 | 按模板补充 |
| 14 | 账号状态 | 主体认证完成，无违规记录 | 处理账号问题 |

### 逐项检查流程

```
对每一项：
├── 通过 → 标记 ✓，进入下一项
└── 未通过 → 
    ├── 需快速修复(< 1天) → 给出修复步骤 → 修复后重检
    ├── 需中期处理(1-7天) → 给出处理方案+时间预估
    └── 需长期处理(> 7天) → 涉及资质/合规项（如软著、版号）必须补齐后才能提审 → 给出办理方案与时间线
```

### 全部通过后的通过率预估

| 条件 | 预估审核通过率 | 说明 |
|------|----------------|------|
| 14项全通过 + 首次提审 | 85-95% | 首次可能被要求微调 |
| 14项全通过 + 有被拒历史 | 70-85% | 需确认之前的问题已修复 |
| 12-13项通过 | 60-75% | 未通过项可能导致拒绝 |
| <12项通过 | <50% | 建议补齐后再提交 |

**输出格式：**
```
上架就绪度评估
━━━━━━━━━━━━━━
通过：X/14 项
预估通过率：XX%

未通过项：
- [项目名]：[原因] → [处理建议] → [预计耗时]

建议：[立即提交 / 修复后提交 / 暂缓]
```

## 五、变现模式决策树

### 入口判断

```
开发者主体类型？
├── 个人开发者 → 路径A（纯广告）
└── 企业开发者 → 路径B（广告+内购）
```

### 路径A：个人开发者 → 纯广告变现

**广告类型选择：**

| 广告类型 | eCPM参考(2025) | 用户体验影响 | 适用场景 | 推荐度 |
|----------|----------------|--------------|----------|--------|
| 激励视频 | 40-120元 | 低(用户主动) | 复活/奖励/解锁 | ★★★★★ |
| 插屏广告 | 15-40元 | 中 | 关卡过渡/返回时 | ★★★☆☆ |
| Banner | 3-8元 | 低 | 非核心页面底部 | ★★☆☆☆ |
| 原生模板 | 10-25元 | 低 | 信息流/列表内 | ★★★☆☆ |
| 格子广告 | 5-15元 | 低 | 结算页/商店页 | ★★★☆☆ |

**广告位设计决策：**

```
游戏核心循环中：
├── 失败/死亡点 → 激励视频(复活/续命) [必设]
├── 关卡通过 → 激励视频(双倍奖励) [推荐]
├── 体力/次数耗尽 → 激励视频(恢复) [推荐]
├── 关卡过渡 → 插屏(每3-5关一次) [可选]
├── 主界面 → Banner [可选，收益低]
└── 结算页 → 格子广告 [推荐]

频次控制：
├── 激励视频：不限次(用户主动)
├── 插屏：间隔≥60秒，单次会话≤5次
└── Banner：非核心页面，可关闭
```

**收入预估模型：**
```
日收入 = DAU × 人均广告观看次数 × eCPM / 1000
示例：1000 DAU × 3次 × 60元 / 1000 = 180元/天
```

### 路径B：企业开发者 → 广告+内购

**付费点设计决策：**

```
付费点类型选择：
├── 去广告(一次性) → 定价 6-12元 [必设]
├── 月卡/周卡 → 定价 6-30元/周期 [高留存游戏推荐]
├── 消耗品(体力/道具) → 定价 1-6元 [中重度游戏]
├── 皮肤/装饰 → 定价 6-30元 [视觉驱动游戏]
├── 通行证/赛季 → 定价 30-68元/赛季 [长线运营游戏]
└── 礼包(首充/限时) → 定价 6-30元 [所有游戏]
```

**定价策略决策：**

| 游戏类型 | 建议定价区间 | 付费率目标 | ARPPU目标 |
|----------|--------------|------------|-----------|
| 超休闲 | 6-12元(去广告为主) | 1-3% | 8-15元 |
| 中度休闲 | 6-68元(多层级) | 3-8% | 20-50元 |
| 模拟经营 | 6-128元(月卡+道具) | 5-12% | 30-80元 |
| 卡牌/RPG | 6-648元(全档位) | 5-15% | 50-200元 |

**混合变现比例建议：**
```
超休闲：广告 90% + 内购 10%
中度休闲：广告 60% + 内购 40%
中重度：广告 30% + 内购 70%
```

**输出格式：**

## 决策树调用规则

1. **单树调用**：用户问题明确对应某一棵树时，直接走该树
2. **多树联动**：复杂问题可能串联多棵树（如"我想做个游戏"→ 类型选择 → 技术选型 → 合规路径 → 变现模式）
3. **中途切入**：用户可从任意节点切入，无需从头走
4. **条件不足**：缺少判断条件时，先提问采集，不做假设
5. **输出一致性**：同一用户同一会话内，各树输出不矛盾
