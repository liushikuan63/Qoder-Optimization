# 自审自查报告填写手册

> 适用：个人开发者 / 企业开发者
> 费用：免费（自行撰写）
> 周期：1-3天（撰写+签字/盖章+扫描）
> 最后更新：2026-07-09
> 最后核实：2026-08-03 ✓（已核实：内容与现行规则一致）
> 核实周期：每季度（审核规则变化较快，需高频核实）
> 下次核实：2026-11-03

---

## 一、什么是自审自查报告

自审自查报告是开发者向微信平台提交的书面声明，证明你的游戏内容已经过自行审查，不含法律法规和平台规范禁止的内容。它是提交小游戏审核时的必传材料。

**核心原则：报告内容必须真实。虚假报告一旦被查出，后果比没有报告更严重。**

---

## 二、报告模板结构

以下为完整的自审自查报告模板，按此结构撰写：

```
═══════════════════════════════════════════════════════

游戏自审自查报告

一、游戏基本信息

游戏名称：[与提交审核的名称完全一致]
游戏类型：[休闲益智/角色扮演/竞技/棋牌/模拟经营等]
游戏平台：微信小游戏
开发主体：[个人姓名 / 企业全称]
版本号：[V1.0]
审查日期：[YYYY年MM月DD日]

二、游戏内容概述

[用200-500字描述游戏的核心玩法、目标用户、主要功能模块。
 示例：本游戏是一款休闲益智类消除游戏，玩家通过交换相邻方块
 的位置，使三个或以上相同方块连成一线即可消除得分。游戏面向
 全年龄段用户，不含任何违反平台内容安全规范的内容。]

三、内容审查项

逐项审查以下内容，如实填写"有"或"无"，如"有"需详细说明：

1. 游戏内容是否通过平台内容安全审核：[是]
2. 游戏素材是否均具有合法授权：[是]
3. 游戏功能是否符合平台运营规范：[是]
4. 游戏是否存在安全隐患或恶意代码：[无]
5. 游戏是否存在侵犯他人合法权益的内容：[无]
6. 游戏是否存在违规分享或推广行为：[无]
7. 游戏是否存在违反社会公序良俗的内容：[无]
8. 游戏是否存在影响未成年人身心健康的设计：[无]
9. 游戏是否存在未公示概率的随机机制：[无/有，已公示]
10. 游戏是否存在虚拟货币逆向兑换功能：[无]
11. 游戏是否存在虚假宣传或误导性描述：[无]
12. 游戏是否存在未经授权的第三方IP/素材：[无]
13. 游戏是否存在渲染、夸大的不当表现：[无]
14. 游戏是否使用未经授权的第三方IP/素材：[无]
15. 游戏是否存在违规引导用户分享到社交平台的功能：[无]
16. 游戏是否存在未公示概率的随机抽取机制：[无/有，已公示]
17. 游戏是否存在虚拟货币反向兑换功能：[无]

四、技术审查项

1. 是否含有恶意代码/恶意程序：[无]
2. 是否存在未经用户同意收集个人信息的行为：[无]
3. 是否已配置隐私保护指引：[是]
4. 是否已接入防沉迷/实名认证系统：[是]
5. 是否存在利用系统漏洞获取不当利益的设计：[无]
6. 广告展示是否符合平台规范：[是]

五、运营审查项

1. 是否存在违规分享奖励机制：[无]
2. 是否存在虚假宣传/误导性描述：[无]
3. 付费项目是否明码标价：[是/不适用（纯免费游戏）]
4. 是否存在未成年人不当消费风险：[已设置付费限制]
5. 用户协议和隐私政策是否完备：[是]

六、审查结论

经审查，本游戏《[游戏名称]》[版本号]的内容符合《网络出版服务管理规定》《未成年人保护法》及微信小游戏平台运营规范的相关要求，不含上述违规内容，适合在微信平台发布运营。

本人/本单位对以上审查内容的真实性承担全部法律责任。

七、签署

个人开发者：
签名：[手写签名]
指纹：[红色印泥右手食指指纹]
日期：[YYYY年MM月DD日]

企业开发者：

日期：[YYYY年MM月DD日]

═══════════════════════════════════════════════════════
```

## 三、每一栏怎么填（详细指导）

### 3.1 游戏基本信息

| 字段 | 怎么填 | 注意 |
|------|--------|------|
| 游戏名称 | 与微信后台设置的小游戏名称完全一致 | 不能多字少字 |
| 游戏类型 | 选一个最贴切的类型 | 不要写"综合" |
| 游戏平台 | 固定写"微信小游戏" | |
| 开发主体 | 个人写姓名，企业写全称 | 与注册主体一致 |
| 版本号 | V1.0（首次提审） | 格式统一 |
| 审查日期 | 签字当天的日期 | 不能早于开发完成日期 |

### 3.2 游戏内容概述

- 200-500字，不要太短（显得敷衍）也不要太长
- 包含：玩法描述 + 目标用户 + 主要功能 + 变现方式
- 语气客观正式，不要用营销话术
- 示例：

> 本游戏《开心方块消除》是一款休闲益智类消除游戏，运行于微信小游戏平台。玩家通过交换相邻彩色方块的位置，使三个或以上相同颜色的方块连成一线即可消除并获得分数。游戏共设100个关卡，难度递增，同时提供每日挑战模式和好友排行榜功能。本游戏面向全年龄段用户，画风清新可爱，不含任何违反平台内容安全规范的内容。游戏采用纯广告变现模式，无内购付费项目。

### 3.3 内容审查项

- 绝大多数项填"无"
- 如果某项确实"有"（如游戏有轻微竞技比较），必须详细说明：
  > 有。游戏含有轻度竞技比较元素（玩家之间的消除速度比拼），但不含违规画面或不当内容，比较结果仅影响排名分数。
- 第16项（随机抽取）：如果有随机抽取，填"有，已在游戏内设置概率公示页面"
- 不要全部无脑填"无"——审核员会对照游戏实际内容检查

### 3.4 技术审查项

- 如实填写
- 第3、4项如果确实已做，填"是"
- 如果游戏不需要收集任何信息（纯单机），第2项填"无，本游戏不收集任何用户个人信息"

### 3.5 运营审查项

- 纯免费+广告变现的游戏：第3项填"不适用（本游戏无付费项目）"
- 有付费的：必须确认明码标价、付费限制已设置

## 四、签字要求（极重要，驳回率最高的环节）

### 个人开发者签字规范：

1. **手写签名**：
   - 用黑色签字笔（不能用蓝色、不能用铅笔）
   - 签身份证上的法定姓名（不能签昵称/艺名）
   - 字迹清晰可辨认
   - 不能是打印后签名（必须是原件上手写）

2. **按指纹**：
   - 使用红色印泥（文具店购买，2-5元一盒）
   - 右手食指按压
   - 指纹按在签名旁边或签名上方（与签名有重叠更佳）
   - 指纹必须清晰完整（不能模糊、不能只有半个）
   - 不能用口红、红墨水等替代印泥

3. **日期**：
   - 手写，格式：2026年7月9日
   - 不能打印日期
   - 日期必须是实际签字当天或之后的日期

### 企业开发者签字盖章规范：

1. **法人签名**：
   - 法定代表人手写签名（黑色签字笔）
   - 签营业执照上登记的法人姓名

2. **公司公章**：
   - 必须是公司行政公章（圆形，红色）
   - 不能用合同专用章、财务专用章、部门章
   - 章必须清晰完整，文字可辨认
   - 盖章位置：与法人签名有重叠（骑缝章效果更好）

3. **日期**：
   - 手写日期
   - 与盖章日期一致

### 扫描/拍照要求：

- 分辨率：300dpi以上（手机拍照选最高画质）
- 格式：PDF（推荐）或 JPG
- 大小：不超过10MB
- 内容完整：四个角都在画面内，无裁切
- 清晰：文字、签名、指纹/印章都能看清
- 无遮挡：手指不要挡住内容
- 背景干净：白纸放在桌面上拍，不要有杂物
- 不能是复印件再扫描（必须原件扫描/拍照）

## 五、企业盖章补充说明

| 章的类型 | 能否使用 | 说明 |
|----------|----------|------|
| 公司公章（圆章） | 可以 | 唯一有效的章 |
| 合同专用章 | 不可以 | 审核不认 |
| 财务专用章 | 不可以 | 审核不认 |
| 法人章（方章） | 不可以单独使用 | 可以配合公章但不能替代 |
| 部门章 | 不可以 | 无法律效力 |
| 电子章 | 视情况 | 部分审核员不认，建议用实体章 |

## 六、内容必须真实完整的警告

**这不是走形式。审核员会对照你的游戏实际内容来验证报告。**

- 报告说"无违规内容"，但游戏里有不当画面 → 驳回
- 报告说"无违规分享奖励"，但游戏里有分享得奖励 → 驳回+可能封号
- 报告说"无随机抽取"，但游戏里有随机抽取机制 → 驳回
- 报告说"已接入防沉迷"，但实际没有 → 驳回+严重警告

**虚假报告的后果：**
- 首次：审核拒绝 + 警告
- 再次：下架 + 限制提审（7-30天）
- 严重/多次：永久封号 + 主体拉黑
- 涉及法律问题的：追究法律责任

## 七、常见错误清单

| 序号 | 错误 | 后果 | 正确做法 |
|------|------|------|----------|
| 1 | 签名是打印的 | 驳回 | 必须手写 |
| 2 | 指纹颜色不对（用了口红） | 驳回 | 用红色印泥 |
| 3 | 企业盖了合同章 | 驳回 | 必须盖公章 |
| 4 | 日期没写 | 驳回 | 必须手写日期 |
| 5 | 游戏名称写错/不一致 | 驳回 | 与后台名称一字不差 |
| 6 | 审查项全填"无"无任何说明 | 可能被驳回 | 至少概述中要描述内容 |
| 7 | 扫描件模糊看不清 | 驳回 | 300dpi以上 |
| 8 | 用A4纸但只占了半页 | 不规范 | 内容充实，排版整齐 |
| 9 | 报告日期早于开发完成日期 | 驳回 | 日期逻辑要正确 |
| 10 | 个人报告盖了公司章 | 驳回 | 个人签名+指纹即可 |
| 11 | 多页报告没有骑缝章/骑缝签名 | 可能被驳回 | 多页建议加盖骑缝章 |
| 12 | 使用蓝色笔签名 | 可能被驳回 | 统一用黑色签字笔 |

## 八、操作时间线

```
Day 1: 完成游戏内容自查（实际玩一遍自己的游戏，对照审查项）
Day 2: 撰写报告（用模板，填入实际内容）
Day 3: 打印 → 签字/盖章 → 扫描 → 上传
```

> 如果是企业，可能需要协调法人签字和用章时间，建议预留额外1-2天。

## 九、版本更新时是否需要重新出具？

| 情况 | 是否需要新报告 |
|------|---------------|
| 修复BUG，内容无变化 | 不需要（沿用原报告） |
| 新增关卡/玩法，无新类型内容 | 建议更新（非强制） |
| 新增付费/随机抽取/社交功能 | 必须重新出具 |
| 游戏名称变更 | 必须重新出具 |
| 被驳回后重新提审 | 建议重新出具（日期更新） |
