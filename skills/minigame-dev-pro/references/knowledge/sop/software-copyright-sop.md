# 软件著作权申请逐步操作手册

> 适用：个人开发者 / 企业开发者（注：微信 IAA 纯广告默认《著作权自我声明》非必填；IAP 与抖音等必填，详见 compliance-rules.md RULE-002）
> 操作平台：中国版权保护中心（PC浏览器）
> 费用：官费免费 / 代办800-1500元（普通）/ 2000-5000元（加急）
> 周期：普通1-2个月 / 加急1-2周
> 最后更新：2026-07-09
> 最后核实：2026-08-03 ✓（已核实：内容与现行规则一致）
> 核实周期：每年（版权登记办法稳定，低频核实即可）
> 下次核实：2027-08-03

## 一、前置条件

| 序号 | 前置项 | 说明 |
|------|--------|------|
| 1 | 已确定游戏名称 | 软著必填时（IAP/抖音等），软著名称须与小游戏名称一字不差，确定后再申请；微信 IAA 无需软著 |
| 2 | 游戏已有可运行版本 | 需要截图写说明书，必须有实际运行的游戏 |
| 3 | 有源代码 | 需要提交前30页+后30页代码 |
| 4 | 准备好身份证明材料 | 个人：身份证；企业：营业执照+法人身份证 |
| 5 | 一个常用邮箱 | 接收审查通知 |

## 二、操作路径

### 步骤1：访问中国版权保护中心

1. 打开浏览器，访问 https://www.ccopyright.com.cn
2. 首页顶部导航 → 点击「登记」→「计算机软件著作权登记」
3. 或直接访问登记系统：版权保护中心

> 注意：认准官网域名 ccopyright.com.cn，不要进入代办机构的仿冒网站。

### 步骤2：注册账号

1. 点击页面右上角「注册」
2. 选择注册类型：
   - 个人：选择「自然人」
   - 企业：选择「法人/组织」
3. 填写注册信息：
   - 用户名（自定义，记住它）
   - 密码（8位以上，含大小写+数字）
   - 真实姓名 / 企业名称
   - 证件号码（身份证号 / 统一社会信用代码）
   - 手机号
   - 邮箱
4. 点击「注册」→ 收到验证短信/邮件 → 完成验证

### 步骤3：实名认证

注册后必须完成实名认证才能提交申请：

**个人认证：**
1. 登录后 → 右上角「个人中心」→「实名认证」
2. 上传身份证正面+反面照片
3. 填写真实姓名、证件号码
4. 提交 → 等待审核（1-3个工作日）

**企业认证：**
1. 登录后 → 右上角「个人中心」→「实名认证」
2. 上传营业执照副本照片
3. 填写企业名称、统一社会信用代码、法人姓名
4. 上传法人身份证正反面
5. 提交 → 等待审核（1-3个工作日）

> 实名认证通过后才能进行下一步。建议提前1-3天完成认证。

### 步骤4：填写申请表

登录后 → 「我要登记」→「计算机软件著作权登记」→「开始申请」

#### 4.1 软件基本信息

| 字段 | 填写内容 | 注意事项 |
|------|----------|----------|
| 软件全称 | 你的小游戏名称 | **必须与微信小游戏名称一字不差！** |
| 软件简称 | 可留空或填简称 | 简称不影响审核 |
| 版本号 | V1.0 | 格式必须是"V"+数字，如V1.0、V2.1 |
| 软件分类 | 选择「游戏软件」| 不要选"应用软件""系统软件" |
| 开发方式 | 独立开发 / 合作开发 / 委托开发 | 个人通常选"独立开发" |
| 权利取得方式 | 原始取得 | 自己开发的选"原始取得" |
| 权利范围 | 全部权利 | |

#### 4.2 开发信息

| 字段 | 填写内容 | 注意事项 |
|------|----------|----------|
| 开发完成日期 | 游戏开发完成的日期 | 必须早于首次发表日期 |
| 首次发表日期 | 游戏首次上线/公开的日期 | 未发表可填"未发表" |
| 开发运行平台 | 微信小游戏平台 | |
| 编程语言 | JavaScript / TypeScript | 按实际填写 |
| 源程序量（行） | 代码总行数 | 大致数字即可 |
| 开发目的 | 为用户提供休闲益智游戏体验 | 简要说明 |
| 面向领域 | 游戏娱乐 | |
| 主要功能 | 简述游戏玩法 | 100字以内 |
| 技术特点 | 简述技术实现 | 如"基于Cocos Creator引擎开发" |

#### 4.3 著作权人信息

| 字段 | 填写内容 | 注意事项 |
|------|----------|----------|
| 著作权人 | 个人姓名 / 企业全称 | 与实名认证信息一致 |
| 证件类型 | 身份证 / 营业执照 | |
| 证件号码 | 对应证件号 | |
| 国籍/注册地 | 中国 | |
| 省份/城市 | 按实际填写 | |

### 步骤5：准备软件说明书

**这是最耗时的材料，需要15-30页。**

#### 说明书结构模板：

```
第1页：封面
  - 软件名称（与申请表一致）
  - 版本号
  - 著作权人
  - 日期

第2页：目录

第3-5页：软件概述
  - 软件用途和背景
  - 主要功能列表
  - 运行环境说明

第6-25页：功能详细说明（核心部分）
  - 每个功能模块单独一节
  - 每节包含：功能描述 + 操作步骤 + 运行截图
  - 截图必须清晰，能看出是实际运行的软件
  - 建议包含：
    * 游戏启动/加载界面
    * 主界面/首页
    * 核心玩法界面（游戏进行中）
    * 设置界面
    * 排行榜/成就界面（如有）
    * 付费/商城界面（如有）
    * 登录/注册界面（如有）

第26-28页：技术说明
  - 系统架构简述
  - 使用的技术/引擎
  - 数据流说明

第29-30页：总结
  - 软件特点总结
  - 未来规划（可选）
```

#### 说明书要求：
- 页数：15-30页（不含封面目录）
- 截图：至少10张，清晰可辨
- 格式：Word/PDF
- 页眉：写软件名称
- 页脚：写页码
- 字体：正文宋体/微软雅黑，小四号
- 行距：1.5倍

#### 截图技巧：
- 使用微信开发者工具运行游戏后截图
- 截图分辨率不低于1280x720
- 截图中不能出现其他软件的窗口/水印
- 如果游戏还未上线，用开发者工具模拟运行即可

### 步骤6：准备源代码文档

**格式要求极其严格，不符合会直接驳回。**

#### 格式规范：
- 前30页 + 后30页 = 共60页
- 每页50行代码（不多不少）
- 第1页从代码第1行开始
- 最后一页到代码最后一行结束
- 如果总代码不足60页（3000行），则全部提交

#### 代码内容要求：
- 必须是有效的程序代码（不能全是注释）
- 不能有空行凑数（连续空行不超过2行）
- 不能全是import/require语句
- 建议包含核心业务逻辑代码
- 去掉敏感信息（API密钥、密码等）

#### 排版格式：
- 字体：等宽字体（Consolas / Courier New）
- 字号：小五号（9pt）或五号（10.5pt）
- 行距：单倍行距
- 页边距：上下2.54cm，左右3.17cm（Word默认）
- 页眉：软件名称 + 版本号
- 页脚：页码（第X页/共60页）

#### 快速生成代码文档的方法：

```bash
# 方法1：使用脚本提取代码
# 将所有.js/.ts文件合并，去掉空行和纯注释行，然后分页

# 方法2：在Word中操作
# 1. 将代码粘贴到Word
# 2. 设置字体为Consolas 9pt
# 3. 设置每页50行（页面设置→文档网格→指定行和字符网格→每页50行）
# 4. 手动检查前30页和后30页
```

### 步骤7：上传材料并提交

1. 回到申请表页面 → 「上传材料」
2. 逐项上传：
   - 软件说明书（PDF格式，建议）
   - 源代码文档（PDF格式）
   - 身份证明文件（身份证/营业执照扫描件）
3. 确认所有信息无误
4. 点击「提交申请」
5. 系统生成受理编号（记住它，用于查询进度）

### 步骤8：等待审查

- 提交后状态变为「已受理」
- 审查周期：30-60个工作日（普通）
- 审查期间可能收到补正通知（邮件/站内信）
- 收到补正通知后必须在30天内修改重交，否则视为撤回

### 步骤9：获取证书

- 审查通过 → 状态变为「已登记」
- 电子证书：在「我的登记」中下载PDF
- 纸质证书：可选邮寄（到付）或自取
- 证书上有登记号（格式：2026SR0XXXXXX）

## 三、名称一致性警告（最重要）

**软著名称必须与微信小游戏名称完全一致，一字不差。**

| 软著名称 | 小游戏名称 | 结果 |
|----------|-----------|------|
| 示例小游戏 | 示例小游戏 | 通过 |
| 示例小游戏V1.0 | 示例小游戏 | 不通过（软著多了版本号） |
| 示例小游戏 | 示例小游戏Pro | 不通过（名称不一致） |
| 示例小游戏游戏软件 | 示例小游戏 | 不通过（软著多了"游戏软件"） |

**建议：**
- 先确定小游戏名称 → 再去申请软著
- 软著"软件全称"只填游戏名称本身，不加"软件""系统""平台"等后缀
- 如果游戏要改名，必须重新申请软著（或做变更）

## 五、常见驳回原因

### 驳回1：代码文档格式不对
- 每页不是50行
- 有大量空行或注释
- 代码量不足（不到60页又没全部提交）
- **修复**：严格按50行/页排版，去掉多余空行

### 驳回2：说明书太简单
- 只有几页，没有截图
- 功能描述过于笼统
- **修复**：补充到15页以上，每个功能配截图

### 驳回3：名称不一致
- 申请表、说明书、代码文档中的软件名称不统一
- **修复**：三处名称必须完全一致

### 驳回4：版本号格式错误
- 写了"1.0"而不是"V1.0"
- **修复**：统一使用"V1.0"格式

### 驳回5：日期逻辑错误
- 首次发表日期早于开发完成日期
- **修复**：开发完成日期 ≤ 首次发表日期

### 驳回6：截图不清晰/不相关
- 截图模糊、截图是其他软件的
- **修复**：重新截取游戏实际运行画面

### 驳回7：代码与说明书不匹配
- 说明书描述的功能在代码中找不到对应
- **修复**：确保代码中包含说明书描述的核心功能实现

## 六、时间规划建议

```
游戏名称确定 → 立即申请软著（不要等开发完）
  ↓
Day 1-3: 注册账号 + 实名认证
Day 4-7: 准备说明书（截图+撰写）
Day 7-10: 准备代码文档（排版）
Day 10-11: 填写申请表 + 上传材料 + 提交
Day 11-70: 等待审查（普通）
Day 70+: 获得证书 → 可以提交小游戏审核
```

> 关键提醒：软著周期长，是整个上架流程中最长的等待项之一。务必在开发早期就启动。

## 七、FAQ

**Q: 游戏还没开发完能申请软著吗？**
A: 可以。只要有部分代码和概念设计截图即可。但说明书中的截图最好是实际运行画面。

**Q: 个人和企业申请有什么区别？**
A: 流程相同，只是著作权人不同。企业申请需要营业执照，证书上写企业名称。

**Q: 软著有效期多久？**
A: 个人：终生+死后50年。企业：首次发表后50年。实际上对小游戏来说不存在过期问题。

**Q: 一个软著能用于多个小游戏吗？**
A: 不能。每个小游戏需要对应名称的软著。

**Q: 软著证书丢了怎么办？**
A: 登录版权中心网站，在"我的登记"中下载电子证书，效力等同纸质证书。
