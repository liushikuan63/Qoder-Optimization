# 隐私保护指引编写手册

> 适用：个人开发者 / 企业开发者
> 操作平台：微信公众平台 + 游戏代码
> 费用：免费
> 周期：1-2天（编写+配置+代码实现）
> 法律依据：《个人信息保护法》《数据安全法》《相关隐私保护规定》
> 最后更新：2026-07-09
> 最后核实：2026-08-03 ✓（已核实：内容与现行规则一致）
> 核实周期：每季度（隐私法规与平台规则变动较快，需高频核实）
> 下次核实：2026-11-03

## 一、必须包含的条款

隐私保护指引必须覆盖以下五大板块，缺一不可：

### 1.1 收集字段（收集什么）

明确列出你收集的每一项个人信息：

| 信息类型 | 对应API | 是否常见 |
|----------|---------|----------|
| 微信昵称 | wx.getUserProfile | 是 |
| 微信头像URL | wx.getUserProfile | 是 |
| 微信OpenID | wx.login | 是（必须） |
| 设备型号/系统版本 | wx.getSystemInfo | 是 |
| 屏幕分辨率 | wx.getSystemInfo | 是 |
| 网络类型（WiFi/4G） | wx.getNetworkType | 常见 |
| 地理位置 | wx.getLocation | 少见（游戏通常不需要） |
| 相册/相机 | wx.chooseImage | 少见 |
| 麦克风 | wx.getRecorderManager | 少见（语音聊天才需要） |
| 剪贴板 | wx.getClipboardData | 少见 |
| 蓝牙 | wx.openBluetoothAdapter | 极少见 |
| 通讯录 | wx.chooseContact | 极少见（不建议） |

**原则：只收集游戏功能必需的信息，不多收。**

### 1.2 用途（为什么收集）

每项信息必须对应一个具体、合法、必要的用途：

| 信息 | 合法用途示例 | 不合法用途示例 |
|------|-------------|---------------|
| 微信昵称/头像 | 在游戏排行榜中展示玩家身份 | "用于精准广告投放" |
| OpenID | 识别用户身份，保存游戏进度 | "用于关联其他平台数据" |
| 设备信息 | 适配不同设备的显示效果 | "用于设备指纹追踪" |
| 网络类型 | 在网络差时降低画质 | "用于判断用户消费能力" |
| 地理位置 | （游戏通常不需要，不要收集） | - |

### 1.3 存储（怎么保存）

必须说明：
- 存储位置：微信云开发 / 自有服务器（写明服务器所在地，如"中国大陆"）
- 存储期限：如"账号存续期间及注销后30天内"
- 安全措施：如"传输加密（HTTPS）、存储加密、访问权限控制"
- 是否跨境：如"所有数据存储在中国大陆境内，不进行跨境传输"

### 1.4 共享（是否给第三方）

必须说明：
- 是否与第三方共享数据
- 如有，列出第三方名称、共享内容、共享目的
- 常见第三方：
  - 微信广告组件（共享设备信息用于广告投放）
  - 微信云开发（数据存储）
  - 数据分析SDK（如友盟，共享匿名化使用数据）
- 如没有第三方共享，明确写"本游戏不会向任何第三方共享您的个人信息"

### 1.5 用户权利

必须告知用户享有以下权利及行使方式：
- 查阅权：用户可查看自己的个人信息
- 更正权：用户可修改昵称/头像（通过微信设置）
- 删除权：用户可删除游戏数据（提供入口或联系方式）
- 撤回同意权：用户可关闭授权（通过微信设置→隐私）
- 注销权：用户可注销游戏账号（提供注销入口或联系方式）
- 投诉权：提供投诉联系方式

## 二、符合《个人信息保护法》要求

### 2.1 核心合规要点

| 要求 | 具体实现 |
|------|----------|
| 合法、正当、必要原则 | 只收集游戏功能必需的信息 |
| 目的限制 | 收集的信息只用于声明的目的 |
| 最小必要 | 不收集与游戏功能无关的信息 |
| 明示告知 | 收集前弹窗告知（不能藏在协议里） |
| 单独同意 | 敏感信息（位置、相册等）需单独弹窗 |
| 不得强制 | 用户拒绝非必需授权不影响基础功能 |
| 未成年人保护 | 14岁以下需监护人同意 |

### 2.2 敏感个人信息（需特别注意）

以下属于敏感个人信息，需要单独弹窗+明确告知必要性：
- 精确地理位置
- 生物识别信息（人脸、指纹）
- 金融账户信息
- 14岁以下未成年人的所有个人信息

**游戏通常不涉及这些，如果涉及必须额外谨慎。**

## 三、弹窗授权实现要求

### 3.1 微信官方隐私弹窗（推荐）

微信提供了官方隐私授权机制，优先使用：

```javascript
// game.js 或 app.js 中

// 方式1：使用微信官方隐私弹窗（2023年9月后推荐）
// 在 game.json 中配置：
{
  "__usePrivacyCheck__": true
}

// 调用隐私接口时，微信会自动弹出授权弹窗
// 例如调用 wx.getUserProfile 时自动触发

// 方式2：手动监听隐私授权事件
wx.onNeedPrivacyAuthorization((resolve, eventInfo) => {
  // eventInfo.privacyContractName: 隐私协议名称
  // eventInfo.privacyContractUrl: 隐私协议链接
  
  // 展示自定义弹窗（见下方）
  showPrivacyDialog(() => {
    // 用户同意后调用 resolve
    resolve({ buttonId: 'agree-btn', event: 'agree' })
  }, () => {
    // 用户拒绝
    resolve({ buttonId: 'disagree-btn', event: 'disagree' })
  })
})
```

### 3.2 自定义隐私弹窗实现

```javascript
// 自定义弹窗组件示例
function showPrivacyDialog(onAgree, onDisagree) {
  // 创建弹窗UI
  // 必须包含：
  // 1. 标题："用户隐私保护提示"
  // 2. 正文：简要说明收集什么、为什么
  // 3. 链接：可点击查看完整《隐私保护指引》
  // 4. 按钮："同意"和"不同意"（两个按钮同等大小，不能弱化拒绝按钮）
  
  // 弹窗要求：
  // - 必须在调用隐私API之前出现
  // - 不能自动消失
  // - "不同意"按钮必须可见可点击
  // - 不能把"不同意"做成灰色/极小字
}
```

### 3.3 弹窗时机

| 场景 | 弹窗时机 |
|------|----------|
| 首次打开游戏 | 如果需要获取昵称头像，在获取前弹窗 |
| 首次使用某功能 | 如首次打开排行榜需要头像，此时弹窗 |
| 新增收集字段 | 版本更新后首次打开时弹窗 |

**绝对不能：游戏一打开就弹窗要所有权限。应该按需、分时弹窗。**

## 四、用户拒绝授权的处理

### 4.1 必须遵守的原则

1. **不能反复弹窗骚扰**：用户拒绝后，同一会话内不能再次弹出相同授权请求
2. **不能拒绝提供基础服务**：用户拒绝头像授权 → 不能因此不让玩游戏
3. **不能降低体验惩罚**：用户拒绝授权 → 不能故意让游戏变卡/功能异常
4. **不能默认勾选同意**：弹窗不能预勾选"我已阅读并同意"

### 4.2 拒绝后的降级方案

| 用户拒绝的授权 | 降级处理 |
|---------------|----------|
| 拒绝头像/昵称 | 使用默认头像和"微信用户"昵称 |
| 拒绝设备信息 | 使用默认画质设置 |
| 拒绝位置信息 | 不展示附近玩家功能（其他功能正常） |
| 拒绝相册 | 不能使用自定义头像上传（其他功能正常） |

### 4.3 代码实现示例

```javascript
// 获取用户信息（带拒绝处理）
function getUserInfo() {
  wx.getUserProfile({
    desc: '用于排行榜展示',
    success: (res) => {
      // 用户同意，使用头像昵称
      saveUserInfo(res.userInfo)
    },
    fail: (err) => {
      // 用户拒绝，使用默认值
      saveUserInfo({
        nickName: '微信用户',
        avatarUrl: '/images/default-avatar.png'
      })
      // 不能弹toast说"您拒绝了授权"然后反复提示
      // 不能阻止用户继续游戏
    }
  })
}
```

## 五、后台配置操作（模板结构）

### 5.1 配置路径

1. 登录 微信公众平台
2. 左侧菜单 →「设置」→「服务内容声明」→「用户隐私保护指引」
3. 点击「更新」

### 5.2 逐项配置

系统会列出所有可能的信息类型，你只需要勾选实际使用的：

**必勾项（几乎所有游戏都用）：**
- [x] 微信昵称 → 用途填："用于在游戏内展示玩家身份"
- [x] 微信头像 → 用途填："用于在游戏排行榜中展示玩家头像"
- [x] 设备信息 → 用途填："用于适配不同设备的显示效果和性能优化"

**按需勾选：**
- [ ] 位置信息 → 除非有"附近的人"功能，否则不勾
- [ ] 相册 → 除非有上传头像功能，否则不勾
- [ ] 相机 → 除非有拍照功能，否则不勾
- [ ] 麦克风 → 除非有语音功能，否则不勾

### 5.3 隐私政策全文模板

在后台"隐私政策详情"中填入以下文本（根据实际情况修改）：

```
《[游戏名称]隐私保护指引》

更新日期：[YYYY年MM月DD日]
生效日期：[YYYY年MM月DD日]

[游戏名称]（以下简称"本游戏"）由[开发者名称]（以下简称"我们"）
开发运营。我们深知个人信息对您的重要性，将严格遵守法律法规要求，
保护您的个人信息安全。

一、我们收集的信息

1. 微信昵称和头像：当您使用排行榜功能时，我们会获取您的微信昵称
   和头像，用于在排行榜中展示您的身份。
2. 设备信息：我们会收集您的设备型号、操作系统版本、屏幕分辨率，
   用于适配游戏画面和性能优化。
3. 游戏数据：我们会记录您的游戏进度、分数、成就等数据，用于保存
   您的游戏状态。

二、信息的使用

我们收集的信息仅用于以下目的：
- 提供游戏核心功能（进度保存、排行榜）
- 优化游戏性能和用户体验
- 保障游戏安全（反作弊）

三、信息的存储

- 存储地点：中华人民共和国境内（微信云开发/自有服务器）
- 存储期限：您的账号存续期间。账号注销后，我们将在30天内删除
  您的个人信息。
- 安全措施：我们采用HTTPS加密传输、数据加密存储、最小权限访问
  控制等措施保护您的信息安全。

四、信息的共享

我们不会向任何第三方出售您的个人信息。
[如有第三方SDK] 本游戏接入了微信广告组件，该组件可能收集您的设备
信息用于广告投放，具体请参阅微信隐私政策。

五、您的权利

1. 查阅和更正：您可以通过微信"设置→隐私"查看和管理您的授权。
2. 删除：您可以联系我们删除您的游戏数据。
3. 撤回同意：您可以通过微信"设置→隐私→授权管理"撤回授权。
4. 注销账号：[提供注销方式，如"在游戏设置中点击'注销账号'"或
   "发送邮件至xxx@xxx.com申请注销"]
5. 投诉举报：如有疑问或投诉，请联系[邮箱/电话]。

六、未成年人保护

我们重视对未成年人个人信息的保护。若您是未满14周岁的未成年人，
请在监护人指导下使用本游戏，并请监护人联系我们处理您的个人信息。

七、本指引的更新

我们可能适时修订本指引。更新后的指引将在游戏内公示，重大变更时
我们会通过弹窗方式再次征得您的同意。

八、联系我们

开发者：[名称]
联系邮箱：[邮箱]
[如有电话/地址也写上]
```

## 六、常见违规点

| 序号 | 违规行为 | 后果 | 正确做法 |
|------|----------|------|----------|
| 1 | 后台没勾选但代码调用了隐私API | 审核拒绝 | 后台勾选与代码调用保持一致 |
| 2 | 后台勾选了但代码没用到 | 可能被判定过度收集 | 只勾选实际使用的 |
| 3 | 先调用API再弹窗 | 审核拒绝 | 必须先弹窗同意再调用 |
| 4 | 用户拒绝后反复弹窗 | 投诉→下架 | 拒绝后不再弹出 |
| 5 | 拒绝后不让玩游戏 | 投诉→下架 | 提供降级方案 |
| 6 | 隐私政策中没有注销方式 | 审核可能拒绝 | 必须提供注销入口 |
| 7 | 收集位置信息但游戏不需要 | 过度收集→处罚 | 不需要的不要收集 |
| 8 | 第三方SDK未声明 | 违规 | 所有第三方数据收集都要声明 |
| 9 | "不同意"按钮极小/灰色 | 违规 | 两个按钮同等显著 |
| 10 | 隐私政策是纯英文 | 可能被拒 | 必须有中文版本 |
| 11 | 更新收集字段后未更新指引 | 违规 | 新增收集必须更新 |
| 12 | 存储期限写"永久" | 不合规 | 写明确期限或"账号存续期间" |

## 七、检查清单（提审前）

- [ ] 后台隐私保护指引已配置并提交审核通过
- [ ] 勾选的信息类型与代码实际调用完全一致
- [ ] 每项信息都填写了具体用途（不是"改善体验"这种空话）
- [ ] 游戏代码中实现了隐私弹窗
- [ ] 弹窗在调用隐私API之前出现
- [ ] 用户拒绝后有降级方案，不影响基础游戏
- [ ] 不会反复弹窗骚扰
- [ ] 隐私政策全文包含：收集、用途、存储、共享、权利、联系方式
- [ ] 提供了账号注销方式
- [ ] 第三方SDK已声明（如广告组件）
- [ ] 版本更新新增收集字段时已更新指引
