# 合规社交机制设计（Social Mechanics）

> **核心原则**：微信对社交分享有**严格规范**，违规会导致限流、封号、下架。
> 社交设计必须在「利用关系链裂变」和「尊重用户体验/平台规则」之间取得平衡。
> **铁律：分享必须是用户自愿的，奖励不能与分享行为强制绑定。**（平台禁止"无深度互动的利益分享"：分享后无需任何互动即得奖励、以分享作为进入/继续游戏前提，均属违规；奖励若与被分享者的深度互动绑定则处于合规边界，需谨慎设计并以官方最新运营规范为准。新手最稳妥做法仍是分享不绑定任何奖励。）

---

## 1. ✅ 可以做的社交机制

| 机制 | 说明 | 合规要点 |
|------|------|---------|
| **好友排行榜** | 基于微信关系链的分数/进度排名 | 用开放数据域实现，合规 |
| **组队挑战** | 邀请好友组队完成任务 | 自愿组队，不强制 |
| **赠送体力** | 好友间互送体力/道具 | 接收方自愿领取 |
| **好友邀请** | 用户自愿邀请好友一起玩 | 自愿邀请，不绑定任何奖励 |
| **群挑战** | 群成员共同达成目标 | 群内自愿参与 |
| **好友超越提醒** | 「XX 超越了你」推送 | 合规的服务通知 |
| **炫耀战绩** | 通关后自愿分享到朋友圈/群 | 用户主动触发 |
| **围观/点赞** | 查看好友成就并点赞 | 自愿互动 |

---

## 2. ❌ 不能做的社交机制（违规红线）

> 以下行为违反《微信小游戏运营规范》，可能导致**限流/封号/下架**。

| 违规行为 | 为什么违规 | 后果 |
|---------|-----------|------|
| **分享得道具**（分享后才给奖励） | 违规分享奖励，强制绑定奖励与分享 | 限流/下架 |
| **强制分享**（不分享不能继续游戏） | 强制用户分享，破坏体验 | 封号 |
| **虚假「好友在玩」** | 伪造社交信息误导用户 | 下架 |
| **分享后自动关注** | 未经同意关注/订阅 | 封号 |
| **分享解锁体力**（唯一获取途径是分享） | 变相强制分享 | 限流 |
| **违规分享话术**（「分享到 3 个群领奖励」） | 违规分享奖励 | 限流/封号 |
| **频繁分享弹窗** | 骚扰用户 | 限流 |
| **分享排行榜奖励**（按分享次数排名） | 违规分享奖励 | 下架 |

### 2.1 合规判断口诀
> **「分享是结果，不是条件」**
> - ✅ 玩家玩得很爽 → 自愿分享炫耀
> - ❌ 玩家想继续玩 → 必须分享才行

## 3. 微信开放数据域使用（好友排行实现）

### 3.1 什么是开放数据域
- 微信为保护用户隐私，将好友关系数据隔离在**独立沙箱（开放数据域）**
- 主域**无法直接获取**好友头像、昵称、关系链
- 必须在开放数据域内渲染好友数据，再以贴图形式传给主域

### 3.2 好友排行榜实现流程
```
1. 主域上报玩家分数到微信（wx.setUserCloudStorage）
2. 创建开放数据域子域（sharedCanvas）
3. 子域内调用 wx.getFriendCloudStorage 获取好友数据
4. 子域内渲染排行榜 UI（Canvas 绘制）
5. 主域将 sharedCanvas 作为贴图显示
```

### 3.3 关键 API
| API | 用途 | 域 |
|-----|------|-----|
| `wx.setUserCloudStorage` | 上报玩家数据 | 主域 |
| `wx.getFriendCloudStorage` | 获取好友数据 | 开放数据域 |
| `wx.getGroupCloudStorage` | 获取群成员数据 | 开放数据域 |
| `wx.getUserCloudStorage` | 获取自己的数据 | 开放数据域 |

### 3.4 注意事项
- 开放数据域是**独立 JS 运行环境**，不能访问主域变量
- 子域 Canvas 尺寸需与显示区域匹配
- 性能：排行榜数据有缓存，避免频繁拉取
- 隐私：只能在开放数据域内使用好友数据，不能导出到主域

## 4. 群分享卡片设计

### 4.1 分享卡片要素
```
wx.shareAppMessage({
  title: '我在XX游戏闯到第50关，你能超过我吗？',  // 吸引力文案
  imageUrl: '分享图URL',  // 5:4 比例，< 128KB
  query: 'from=share&level=50'  // 自定义参数
})
```

### 4.2 高转化卡片设计原则
| 要素 | 设计要点 |
|------|---------|
| **标题** | 制造好奇/挑战/炫耀，如「99% 的人卡在第 8 关」 |
| **图片** | 5:4 比例，画面吸睛，有游戏特色，文字少而大 |
| **个性化** | 带上玩家成绩/进度，制造「比较」动机 |
| **利益点** | 展示玩家成绩与挑战目标，激发好奇与挑战欲（不绑定奖励） |

### 4.3 分享触发时机（合规）
- ✅ 通关高峰时刻（玩家最爽时主动炫耀）
- ✅ 获得稀有成就时
- ✅ 玩家**主动点击**分享按钮
- ❌ 不在失败/卡关时强制分享
- ❌ 不弹窗引导分享

### 4.4 分享回流设计
- 被分享者点击卡片进入游戏，体验核心玩法（新玩家内容按正常新手流程，与分享动作无关）
- 分享者不获得任何游戏内奖励（分享为纯自愿行为，不绑定奖励）
- 合规要点：所有分享/邀请均为用户自愿触发，分享动作不绑定任何游戏内奖励

## 5. 社交裂变合规设计模式

### 5.1 合规裂变三原则
1. **自愿**：所有分享/邀请由用户主动触发
2. **去奖励化**：分享/邀请不绑定任何游戏内奖励，靠内容本身与社交荣誉驱动
3. **真实**：社交信息真实，不伪造「好友在玩」

### 5.2 合规裂变模式

| 模式 | 机制 | 合规性 |
|------|------|--------|
| **好友排行** | 关系链排名激发竞争 | ✅ 完全合规 |
| **群挑战** | 群成员共同目标 | ✅ 合规 |
| **好友邀请** | 用户自愿邀请好友一起玩 | ✅ 合规（自愿，不绑定奖励） |
| **战绩炫耀** | 通关后自愿分享 | ✅ 合规 |
| **好友互助** | 互送体力/加速 | ✅ 合规 |
| **拼团/组队** | 组队享加成 | ✅ 合规（自愿组队） |

### 5.3 裂变漏斗优化
```
曝光（分享卡片）→ 点击（卡片吸引力）→ 进入游戏（加载速度）→ 留存（核心循环）
```
- 优化卡片点击率：A/B 测试标题/图片
- 优化加载速度：首包 < 4MB，秒开
- 优化回流落地：被邀请者直接进入游戏体验核心玩法

### 5.4 裂变红线（再次强调）
- ❌ 不做违规分享奖励（「分享到 3 个群」）
- ❌ 不强制分享（「分享才能继续」）
- ❌ 不伪造社交（假「好友在玩」）
- ❌ 不做按分享次数排名的发奖排行

## 6. 社交设计检查清单

- [ ] 所有分享是否用户自愿触发？
- [ ] 奖励是否与「分享动作」解绑？
- [ ] 是否避免了违规分享话术？
- [ ] 好友排行是否用开放数据域实现？
- [ ] 分享卡片是否 5:4 比例、< 128KB？
- [ ] 分享/邀请是否与游戏内奖励解绑？
- [ ] 社交信息是否真实（无伪造）？
- [ ] 是否避免了频繁分享弹窗？

---

## 7. 违规应急

- 若收到微信违规通知，**立即下架相关分享功能**
- 自查所有分享触发点和奖励逻辑
- 整改后重新提审
- 严重违规（封号）需走申诉流程，准备合规说明材料
