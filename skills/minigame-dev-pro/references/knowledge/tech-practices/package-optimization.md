# 包体优化实战指南

> 目标：主包 ≤ 4MB，总包 ≤ 30MB，首屏加载 ≤ 3秒。
> 平台口径：本文以**微信小游戏**为准（全局对象前缀 `wx.`、包体限制 4/30/4MB）。抖音对应前缀 `tt.`、包体 16/20MB（+VP 30MB），QQ/快手/支付宝/百度/淘宝/快游戏各有差异，均以各平台开放平台官方文档为准，详见 `references/data/platforms.json` 与 `references/data/spec-registry.json`。禁止把微信数值/接口当全平台通用。

## 1. 分析当前包体构成

### 1.1 使用开发者工具分析
1. 打开微信开发者工具 → 工具栏 → "详情"
2. 查看"本地代码"大小（即主包大小）
3. 点击"代码依赖分析"查看各模块占比
4. 关注：图片、音频、第三方库、未使用代码

### 1.2 包体构成典型分布
```
典型未优化项目（15MB）：
├── 图片资源：60-70%（未合图、未压缩的PNG）
├── 音频资源：15-20%（未压缩的WAV/高码率MP3）
├── 第三方库：10-15%（完整引入的lodash、moment等）
├── 游戏代码：5-10%
└── 其他（字体、配置JSON）：5%
```

### 1.3 分析命令（Cocos Creator项目）
```bash
# 查看构建产物大小
du -sh build/wechatgame/*
# 找出大文件
find build/wechatgame -size +100k -exec ls -lh {} \;
# 按类型统计
find build/wechatgame -name "*.png" -exec du -ch {} + | tail -1
find build/wechatgame -name "*.mp3" -exec du -ch {} + | tail -1
```

## 2. 图片优化

### 2.1 TexturePacker 合图
- **工具**：TexturePacker（付费）/ Free Texture Packer（免费）
- **设置建议**：
  - 单张图集不超过 2048×2048（兼容性好）
  - 高端机可用 4096×4096
  - 格式：PNG-8（≤256色）或 PNG-32（需透明）
  - 开启 Trim（去除透明边距）
  - 开启 Rotate（旋转填充）
  - 算法：MaxRects 或 Shelf
- **收益**：减少DrawCall 50-80%，减少文件数量

### 2.2 格式选择
| 场景 | 推荐格式 | 说明 |
|------|---------|------|
| UI图标（纯色/少色） | PNG-8 | 体积小，256色够用 |
| 需透明的精灵 | PNG-32 / WebP | WebP体积减少25-35% |
| 背景图（不需透明） | JPG（质量75-85） | 体积最小 |
| 大量同类小图 | 合图PNG | 减少请求数 |
| 超高清背景 | WebP / 远程加载 | 不放主包 |

### 2.3 压缩工具
| 工具 | 平台 | 压缩率 | 特点 |
|------|------|--------|------|
| TinyPNG | 在线 | 30-50% | 有损，肉眼无差 |
| pngquant | CLI | 40-60% | PNG-32→PNG-8 |
| ImageOptim | macOS | 20-40% | 无损 |
| Squoosh | 在线 | 可调 | Google出品，支持WebP |
| XnConvert | 跨平台 | 可调 | 批量处理 |

### 2.4 九宫格（Nine-Patch）
- 适用场景：按钮、面板、对话框等可拉伸UI
- 一张小图代替多尺寸切图
- Cocos Creator：Sprite组件 → Type → Sliced
- 原图建议：边距 ≥ 圆角半径的2倍

### 2.5 远程资源策略
- 非首屏资源全部放远程（CDN）
- 首次加载后缓存到本地文件系统
- 版本管理：URL带版本号 `res/v1.2.3/level1.png`
- 加载策略：预加载 + 懒加载结合
- 失败重试：3次重试 + 降级占位图

## 3. 代码优化

### 3.1 移除未使用模块
- Cocos Creator：项目设置 → 模块配置 → 取消勾选不用的模块
  - 不用3D：取消 3D 相关
  - 不用物理：取消 Physics
  - 不用粒子：取消 Particle
  - 不用Spine/DragonBones：取消对应模块
- 收益：引擎代码可减少 500KB-2MB

### 3.2 代码压缩
- 构建时开启代码压缩（Terser/UglifyJS）
- Cocos Creator：构建面板 → 压缩引擎代码 / 压缩游戏代码
- 移除 console.log（生产环境）
- 移除 source map（生产环境）

### 3.3 分包策略
```
主包（≤4MB）：
├── 引擎核心代码
├── 游戏入口/启动逻辑
├── 首屏UI资源
├── 公共工具函数
└── 加载管理器

分包1 - levels（关卡资源）：
├── 第1-50关配置
├── 关卡特有图片
└── 关卡特有音频

分包2 - shop（商店/社交）：
├── 商店UI
├── 排行榜界面
└── 分享相关

远程资源：
├── 后续关卡资源
├── 活动资源
├── 高清背景
└── 背景音乐
```

### 3.4 第三方库精简
| 库 | 完整大小 | 替代方案 |
|----|---------|---------|
| lodash (70KB) | 按需引入单函数 | 自己写工具函数 |
| moment.js (300KB+) | day.js (2KB) | 或直接不用 |
| axios (30KB) | wx.request 封装 | 小游戏原生API |
| jQuery | 完全不需要 | 原生DOM/引擎API |

## 4. 音频优化

### 4.1 格式和码率
| 类型 | 推荐格式 | 码率 | 采样率 |
|------|---------|------|--------|
| BGM（背景音乐） | MP3 | 64-128kbps | 44100Hz |
| 短音效（<3s） | MP3 / AAC | 64kbps | 22050Hz |
| 极短音效（<0.5s） | WAV（8bit） | - | 22050Hz |

### 4.2 优化技巧
- BGM 使用单声道（非立体声），体积减半
- 短音效裁剪静音头尾
- 同类音效复用（如多个消除音效共用2-3个）
- 工具：Audacity（免费）导出时选择合适码率
- 在线压缩：mp3smaller.com

### 4.3 远程加载策略
- BGM 全部放远程（单首200-500KB）
- 高频短音效放包内（<50KB的）
- 首次播放前预加载
- 使用 `wx.downloadFile` + 本地缓存

## 5. 分包策略详解

### 5.1 主包放什么（≤4MB 黄金空间）
- 引擎运行时（Cocos约1.5-2.5MB）
- 游戏启动场景（Loading界面）
- 核心游戏循环代码
- 首屏必需的小图（图标、按钮）
- 全局配置数据

### 5.2 分包怎么拆
- **按功能拆**：商店、设置、社交各一个分包
- **按关卡拆**：每N关一个分包
- **按场景拆**：每个大场景一个分包
- 原则：用户第一次进入不需要的内容，都放分包

### 5.3 分包加载代码
```javascript
// 按需加载分包
wx.loadSubpackage({
  name: 'levels',
  success: () => {
    console.log('分包加载成功');
    // 加载分包内资源
  },
  fail: (err) => {
    console.error('分包加载失败', err);
    // 重试或提示
  }
});

// 带进度条
const task = wx.loadSubpackage({ name: 'levels' });
task.onProgressUpdate((res) => {
  console.log(`加载进度：${res.progress}%`);
});
```

## 6. 实测检查清单

### 发布前包体检查
- [ ] 主包大小 ≤ 4MB（开发者工具"详情"查看）

## 7. 各引擎构建优化配置

### 7.1 Cocos Creator 3.x
```
构建面板设置：
├── 发布平台：微信小游戏
├── AppID：填写正确
├── 设备方向：portrait / landscape
├── 初始场景：选择Loading场景
├── 主包压缩类型：合并所有JSON / 合并所有纹理
├── 压缩引擎代码：勾选
├── 压缩游戏代码：勾选（Terser）
├── MD5 Cache：勾选（资源版本管理）
├── 远程服务器地址：填写CDN地址
├── 分包配置：按场景/功能配置
```

### 7.4 Phaser 3（手动配置）
```javascript
// webpack.config.js 优化
module.exports = {
  optimization: {
    minimize: true,
    minimizer: [new TerserPlugin({
      terserOptions: {
        compress: { drop_console: true }
      }
    })],
    splitChunks: {
      chunks: 'all',
      maxSize: 4 * 1024 * 1024 // 4MB分包
    }
  }
};
```

### 7.5 Unity 小游戏方案
```
优化重点：
├── 使用 IL2CPP + Strip Engine Code
├── 纹理压缩：ASTC（iOS/安卓高端）/ ETC2（安卓）
├── 音频压缩：Vorbis
├── 关闭不用的 Unity 模块
├── AssetBundle 远程加载
├── 代码裁剪：Managed Stripping Level → High
└── 注意：Unity转小游戏包体天然偏大，需额外优化
```
