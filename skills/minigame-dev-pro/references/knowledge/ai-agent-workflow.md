# AI Agent 开发范式

> 数据时效：2026-07（AI Agent 是2026年新兴的开发范式）
> 置信度：中（Agent 能力快速演进，部分内容需验证）

---

## 一、AI Agent 与传统 AI 辅助的区别

| 维度 | 传统 AI 辅助（ai-tools.md） | AI Agent 开发 |
|------|---------------------------|--------------|
| 交互方式 | 人提问 → AI 回答 | 人给目标 → Agent 自主执行 |
| 自主性 | 低（每步需人确认） | 高（可连续执行多步） |
| 工具使用 | 人调用工具 | Agent 自主调用工具 |
| 适用场景 | 单点咨询 | 复杂多步任务 |
| 人工介入 | 每步介入 | 关键节点介入 |

### 核心差异

```
传统 AI 辅助：
  人："帮我写个登录功能"
  AI：给出代码 → 人复制粘贴 → 人测试 → 人反馈

AI Agent：
  人："实现登录功能并测试"
  Agent：分析需求 → 写代码 → 运行测试 → 发现Bug → 修复 → 再测试 → 通过 → 报告
```

## 二、2026年 AI Agent 在小游戏开发中的应用

### 可自主完成的任务

| 任务 | Agent 能力 | 人工介入点 |
|------|-----------|-----------|
| 生成项目脚手架 | ★★★★★ 完全自主 | 确认技术栈 |
| 实现标准功能（登录/支付/分享） | ★★★★☆ 大部分自主 | 确认业务逻辑 |
| Bug 定位修复 | ★★★★☆ 大部分自主 | 确认修复方案 |
| 性能优化 | ★★★☆☆ 部分自主 | 确认优化方向 |
| 关卡/内容生成 | ★★★☆☆ 部分自主 | 验证可玩性 |
| 合规审查 | ★★★★★ 完全自主 | 无（用 compliance-scan.mjs） |
| 部署发布 | ★★☆☆☆ 需谨慎 | 必须人工确认 |

### 不可自主完成的任务

- 核心玩法设计（需人的创意判断）
- 手感/打击感调优（需人的体感反馈）
- 数值平衡终调（需真人测试数据）
- 商业策略决策（需人的商业判断）

## 三、Agent 工作流设计

### 工作流1：自动开发+预览+修复循环

```
人："给游戏加个分享功能"

Agent 执行流程：
1. 分析现有代码结构
2. 生成分享功能代码（基于 wx.onShareAppMessage）
3. 自动调用 run-game.mjs 预览
4. 等待2秒，调用 get-logs.mjs 检查日志
5. 如果有错误：
   a. 分析错误原因
   b. 修复代码
   c. 回到步骤3（最多5次）
6. 如果无错误：
   a. 调用 compliance-scan.mjs 检查合规
   b. 如果有违规分享奖励机制 → 修正
   c. 报告完成
```

### 工作流2：自动就绪度检查

```
人："这个游戏能上线了吗？"

Agent 执行流程：
1. 调用 readiness-check.mjs（14项检查）
2. 调用 compliance-scan.mjs（10条红线）
3. 调用 package-analyzer.mjs（包体分析）
4. 汇总三项结果
5. 如果有阻断项：
   a. 列出阻断项
   b. 给出修复方案
   c. 询问"要我自动修复吗？"
6. 如果全通过：
   a. 输出"可以提审"
   b. 给出提审步骤
```

### 工作流3：自动性能优化

```
人："游戏有点卡"

Agent 执行流程：
1. 调用 perf-profiler.mjs --mode inject（注入打点）
2. 提示用户运行游戏1-2分钟
3. 调用 perf-profiler.mjs --mode read（读取数据）
4. 分析性能瓶颈：
   a. FPS<30 → 渲染优化
   b. 内存高 → 资源释放
   c. 帧率波动 → GC优化
5. 给出优化建议（带具体代码）
6. 询问"要我自动优化吗？"
7. 优化后重新打点验证
8. 调用 perf-profiler.mjs --mode revert（恢复）
```

## 四、Agent 的安全边界

### 必须人工确认的操作

```
🚫 Agent 不能自主执行：
├── 发布上线（publish.mjs 必须人工确认）
├── 删除文件（破坏性操作）
├── 修改合规相关代码（需人工审查）
├── 修改支付逻辑（需人工审查）
├── 修改用户数据处理（需人工审查）
└── 花钱操作（买量/外包）
```

### Agent 可自主执行的操作

```
✅ Agent 可以自主执行：
├── 代码生成和修改（非敏感模块）
├── 运行预览和测试
├── 读取日志和分析数据
├── 执行自检脚本（只读不写）
├── 生成文档和报告
└── 性能打点注入和恢复（有备份机制）
```

## 五、Agent 开发的优秀实践

### 实践1：小步快跑

```
✗ 错误：让Agent一次性"开发整个游戏"
✓ 正确：让Agent分步"先做登录"、"再做关卡"、"再做分享"
```

### 实践2：每步验证

```
每完成一个功能：
1. Agent 自动预览（run-game.mjs）
2. Agent 自动检查日志（get-logs.mjs）
3. Agent 自动合规扫描（compliance-scan.mjs）
4. 全绿后再进入下一步
```

### 实践3：保留人工否决权

```
Agent 提出方案 → 人确认 → Agent 执行
即使Agent能自主，关键决策也要人确认
```

### 实践4：使用结构化输出

```
所有Agent执行结果用JSON格式：
├── 便于Agent自己解析
├── 便于人审查
└── 便于后续处理
```

## 六、与现有 ai-tools.md 的关系

- `ai-tools.md`：聚焦"AI 辅助人工"——人主导，AI 辅助
- `ai-agent-workflow.md`（本文件）：聚焦"Agent 自主执行"——Agent 主导，人监督

### 演进路径

```
阶段1（2024）：人工为主，AI 偶尔咨询
阶段2（2025）：AI 辅助，人主导（ai-tools.md）
阶段3（2026）：Agent 自主，人监督（本文件）
阶段4（未来）：Agent 全自主，人只定目标
```

### 当前阶段的核心认知

```
2026年 Agent 的能力边界：
├── 能做：标准化任务、重复性工作、有明确规则的判断
├── 不能做：创意决策、体验判断、商业策略
└── 正确用法：把标准化任务交给Agent，人专注创意和判断
```
