### RULE-001: ICP备案

- 级别：P0（阻断性，无备案不可上架）
- 适用：个人/企业（全部）
- 要求：小游戏必须完成ICP备案后才能提交审核上架。备案主体必须与小游戏注册主体完全一致（名称、证件号一字不差）。
- 费用：免费（通过微信公众平台提交，管局审核不收费）
- 周期：提交后管局审核7-20个工作日（各省不同，广东通常7-10天，北京10-15天）
- 检查点：
  - 注册小游戏账号后立即启动（因为周期长）
  - 提交审核前必须确认备案状态为"已通过"
- 违反后果：无法提交审核，小游戏无法上架。未备案上线被查到将面临通信管理局罚款（个人500-1000元，企业1万-10万元）并关停网站/应用。
- 办理路径：
  1. 登录微信公众平台 微信公众平台
  2. 左侧菜单 → 设置 → 基本设置 → 小程序备案
  3. 点击"开始备案"
  4. 填写主体信息（个人：姓名+身份证；企业：营业执照+法人信息）
  5. 填写小程序信息（名称、服务内容类型选"游戏"）
  6. 上传材料（身份证正反面/营业执照、负责人手持身份证照片）
  7. 提交 → 平台初审（1-2天）→ 管局终审（7-20工作日）
  8. 审核通过后获得备案号（格式：粤ICP备XXXXXXXX号-XA）
- 常见坑点：
  - 主体名称必须与营业执照/身份证完全一致，"有限公司"不能写成"有限责任公司"的简称
  - 个人备案：网站负责人必须是主体本人，不能委托
  - 企业备案：负责人可以是法人或授权负责人（需授权书）
  - 服务内容类型选错会被驳回，游戏类必须选"游戏"
  - 备案期间不要修改小程序名称，否则需要重新备案
  - 同一主体下多个小程序需要分别备案，但共用主体信息
- 来源：https://developers.weixin.qq.com/miniprogram/product/
- 最后验证：2026-07-09

### RULE-002: 软件著作权（软著）

- 级别：P0（阻断性，提交审核时必须上传）
- 适用：按平台与变现模式分流（非全部必填）
- 要求（平台×变现模式矩阵）：
  - **微信 IAA**（纯广告、不开通虚拟支付）：默认《著作权自我声明》，软著**非必填**；
  - **微信 IAP / 抖音等**：软著**必填**，须上传与游戏名称完全一致的《计算机软件著作权登记证书》，软著名称必须与小游戏名称一字不差；
  - 其他平台以各平台官方资质规范为准（执行期核实，未核实标 unknown）。
- 注：仅名称含英文/"软件"字样、涉及品牌或公众人物、或牌类/捕鱼类目时，即便 IAA 也须提交软著。
- 费用：官费免费（中国版权保护中心不收费）；代办费800-1500元（普通）/ 2000-5000元（加急）
- 周期：普通申请1-2个月；加急1-2周（费用翻倍以上）
- 检查点：
  - 游戏名称确定后立即启动（因为周期长）
  - 名称变更时必须重新申请软著
  - 提交审核前确认证书已到手
- 违反后果：无法通过审核，小游戏无法上架。使用他人软著或伪造证书将面临法律追责。
- 办理路径：
  1. 访问中国版权保护中心 https://www.ccopyright.com.cn
  2. 注册账号 → 实名认证（个人：身份证；企业：营业执照+法人身份证）
  3. 在线填写《计算机软件著作权登记申请表》
  4. 准备材料：
     - 软件说明书（15-30页，含操作截图）
     - 源代码文档（前30页+后30页，每页50行，共60页）
     - 身份证明文件
  5. 在线提交 → 等待审查（30-60工作日）
  6. 审查通过 → 下载电子证书 / 邮寄纸质证书
- 常见坑点：
  - **名称一致性是最大坑点**：软著名称"示例小游戏"，小游戏名称"示例小游戏Pro"→ 审核不通过
  - 版本号建议写"V1.0"，不要写"1.0"或"v1.0"（格式要求）
  - 开发完成日期必须早于首次发表日期
  - 源代码不能全是注释或空行，每页必须满50行有效代码
  - 说明书截图必须清晰，能看出是实际运行的软件
  - 个人申请：著作权人填个人姓名；企业申请：填企业全称
- 来源：https://www.ccopyright.com.cn（中国版权保护中心官网）
- 最后验证：2026-07-09

### RULE-003: 自审自查报告

- 级别：P0（阻断性，提交审核时必须上传）
- 适用：个人/企业（全部）
- 要求：提交小游戏审核时，必须上传《游戏自审自查报告》，证明游戏内容已经过开发者自行审查，不含违规内容。报告必须真实、完整、签字/盖章。
- 费用：免费（自行撰写）
- 周期：1-3天（撰写+签字/盖章）
- 检查点：
  - 每次提交审核前都需要（版本更新内容变化大时需重新出具）
  - 签字/盖章后扫描上传
- 违反后果：审核直接拒绝。虚假报告一旦被查出，将面临下架+封号+可能的法律追责。
- 办理路径：
  1. 下载/编写自审自查报告模板
  2. 逐项填写：
     - 游戏基本信息（名称、类型、玩法描述）
     - 内容审查项（是否含违规内容，符合平台内容安全规范）
     - 技术审查项（是否含恶意代码、是否合规收集用户数据）
     - 运营审查项（是否有违规分享奖励、是否有未公示的概率）
  3. 结论：声明"经审查，本游戏不含上述违规内容"
  4. 签字：
     - 个人：手写签名 + 红色印泥按指纹 + 日期
     - 企业：法人签字 + 公司公章（红色）+ 日期
  5. 扫描/拍照（清晰、完整、无遮挡）
  6. 在小游戏审核提交页面上传PDF/JPG
- 常见坑点：
  - 签名必须手写，不能打印签名后扫描
  - 指纹必须用红色印泥，不能用口红等替代（颜色不对会被驳回）
  - 企业必须盖公章（圆章），合同章/财务章无效
  - 日期必须填写，且不能早于游戏开发完成日期
  - 游戏名称必须与提交审核的名称完全一致
  - 内容审查项不能全部打勾"无"而不做任何说明，至少要有简要描述
- 来源：https://developers.weixin.qq.com/minigame/product/index.html（微信小游戏运营规范）
- 最后验证：2026-07-09

### RULE-004: 隐私保护指引

- 级别：P0（阻断性，审核必查项）
- 适用：个人/企业（全部）
- 要求：小游戏必须在后台配置《隐私保护指引》，且游戏内首次收集用户信息前必须弹窗告知并获得用户同意。指引内容必须符合《个人信息保护法》要求。
- 费用：免费
- 周期：1-2天（编写+配置）
- 检查点：
  - 提审前必须配置完成
  - 每次新增信息收集字段时必须更新
  - 用户首次打开游戏时弹窗必须出现
- 违反后果：审核拒绝；已上架的被举报后下架整改；严重者面临网信办处罚（最高5000万元或上年度营业额5%罚款）。
- 办理路径：
  1. 登录微信公众平台 微信公众平台
  2. 左侧菜单 → 设置 → 服务内容声明 → 用户隐私保护指引
  3. 点击"更新"或"填写"
  4. 逐项勾选收集的信息类型：
     - 微信昵称、头像（wx.getUserProfile）
     - 设备信息（wx.getSystemInfo）
     - 位置信息（wx.getLocation，如适用）
     - 相册/相机（wx.chooseImage，如适用）
  5. 每项填写：收集目的、使用方式、存储期限
  6. 提交审核（平台审核通常1-3天）
  7. 代码中实现弹窗授权：
     - 使用 wx.onNeedPrivacyAuthorization 或自定义弹窗
     - 用户同意前不得调用任何隐私接口
- 常见坑点：
  - 后台勾选了收集位置信息，但代码里实际没用到 → 审核可能通过但属于过度收集
  - 后台没勾选但代码里调用了 → 审核直接拒绝
  - 弹窗必须在调用隐私API之前出现，不能先调用再弹窗
  - 用户拒绝授权后不能反复弹窗骚扰，不能因此拒绝提供基础服务
  - "改善用户体验"不是合法的收集理由，必须写具体用途
  - 第三方SDK收集的信息也必须声明
- 来源：https://developers.weixin.qq.com/minigame/dev/guide/open-ability/privacy
- 最后验证：2026-07-09

### RULE-005: 防沉迷系统

- 级别：P0（阻断性，无防沉迷不可上架）
- 适用：个人/企业（全部）
- 要求：所有小游戏必须接入实名认证和防沉迷系统。未成年人只能在周五、周六、周日及法定节假日每日20:00-21:00游玩1小时。必须实现付费限制。
- 费用：免费（使用微信提供的实名接口）
- 周期：技术接入1-3天
- 检查点：
  - 提审前必须完成接入并测试通过
  - 每次更新涉及登录/付费逻辑时需回归测试
- 违反后果：审核拒绝；已上架被举报后下架；企业面临新闻出版署处罚（罚款+吊销许可）；个人开发者封号。
- 办理路径：
  1. 使用微信提供的实名认证能力（小游戏登录即由平台完成实名认证与防沉迷时长控制，无需自行采集身份证信息）：
     - 调用 wx.checkIsUserAdvisedToRest 获取防沉迷建议（根据当天游戏时长提示是否建议休息）
     - 已开通虚拟支付的小游戏可调用 wx.requestFacialRecognition 做人脸核验
  2. 或使用国家网络游戏防沉迷实名认证系统（企业）：
     - 访问 实名认证系统（实名认证接口）
     - 申请接入 → 获取接口凭证 → 技术对接
  3. 实现以下功能：
     - 实名登录：未实名用户不可进入游戏（平台侧统一处理）
     - 时长限制：未成年人仅周五六日+法定节假日20:00-21:00可玩1小时，其余时段一律禁止登录
     - 主动响应 wx.checkIsUserAdvisedToRest 返回的休息建议
     - 付费限制：8岁以下禁止付费；8-16岁单次≤50元月≤200元；16-18岁单次≤100元月≤400元
     - 家长监护：提供家长绑定和查询入口
  4. 测试：用未成年人测试账号验证所有限制生效
- 常见坑点：
  - 微信小游戏的防沉迷主要依赖微信平台能力，不需要自己建实名数据库
  - 但必须在代码中处理 wx.checkIsUserAdvisedToRest 的返回值
  - 节假日列表需要每年更新（国务院发布后手动维护或接入API）
  - "游客模式"不能跳过防沉迷限制，游客也必须实名
  - 付费限制是按自然月计算，不是按30天滚动
  - 测试时注意：成年人账号不会触发限制，必须用未成年测试号

> ⚠️ 说明：现行限制为未成年人"仅周五/六/日及法定节假日 20:00-21:00 可玩 1 小时"（2021年9月起施行，此前为每日1.5小时/节假日3小时）。
> 网络流传的"2026年进一步收紧至1小时"说法不准确（1小时/日制自2021年起即为现行标准）。
> 如官方后续有新规，以微信官方最新公告和实名认证系统实际配置为准，需实时验证。

- 来源：https://developers.weixin.qq.com/minigame/introduction/guide/zxbsm.html
- 最后验证：2026-07-09

### RULE-006: 游戏版号

- 级别：P0（有内购付费的游戏必须持有）
- 适用：企业（个人开发者无法申请版号）
- 要求：含有内购付费（用户充值购买虚拟物品/货币）的游戏必须取得游戏出版主管部门颁发的《网络游戏出版物号》（即"版号"）。纯广告变现、无任何内购的游戏目前不强制要求版号。
- 费用：申请本身免费，但准备材料+合规整改通常花费数万至数十万元（含法律咨询、内容修改、测试等）
- 周期：6个月-2年不等（2024年约110-120款/月、2025年约80款/月，2026年已提速至月均100款以上，排队仍较长；以国家新闻出版署当月公示为准）
- 检查点：
  - 立项时确定变现模式：有内购 → 必须规划版号
  - 提审前确认：纯广告变现可跳过；有内购必须持有
- 违反后果：无版号上线内购 → 下架 + 罚款（违法所得5-10倍）+ 企业负责人追责。微信平台审核时也会拦截。
- 办理路径：
  1. 确认是否需要版号（有内购=需要）
  2. 准备材料：
     - 游戏完整版本（可玩、无BUG）
     - 游戏脚本/剧情文本
     - 防沉迷系统接入证明
     - 企业营业执照 + ICP许可证（注意是许可证不是备案）
     - 游戏自审报告
     - 出版合同（需有出版资质的单位）
  3. 找有出版资质的代理单位（如出版社）
  4. 代理单位向省级新闻出版局提交申请
  5. 省局初审 → 出版主管部门终审
  6. 获得版号（格式：国新出审[2026]XXXX号）
- 常见坑点：
  - 个人开发者无法申请版号，必须通过企业+出版单位
  - ICP许可证（增值电信业务经营许可证）≠ ICP备案，版号需要的是许可证
  - 审批期间游戏内容不能大改，否则需要重新排队
  - 版号与游戏名称绑定，改名需要重新申请
  - 现实中大量小游戏选择"纯广告变现"，不涉及内购则无需版号
  - 版号发放量随政策波动：2025年月均约80款，2026年已提速至月均100款以上（以当月公示为准）
- 来源：游戏出版主管部门官网
- 最后验证：2026-07-09

### RULE-007: 内容备案（游戏备案）

- 级别：P1（企业运营类游戏需要）
- 适用：企业
- 要求：网络游戏运营企业应在游戏上线后30日内向文化主管部门（现为各地文化和旅游厅/局）进行内容备案。含UGC内容（用户生成内容，如聊天、自定义昵称、社区）的游戏必须备案。
- 费用：免费（行政备案不收费）
- 周期：材料齐全后1-3个月
- 检查点：
  - 上线后30天内完成
  - 游戏内容重大更新后需变更备案
- 违反后果：责令整改 + 罚款（1万-3万元）；拒不整改的吊销相关许可。
- 办理路径：
  1. 登录全国文化市场技术监管与服务平台 文化市场管理平台
  2. 注册企业账号 → 实名认证
  3. 选择"网络游戏备案" → 填写备案表：
     - 游戏名称、类型、运营单位
     - 游戏内容简介（500字以内）
     - 是否含UGC功能
     - 防沉迷系统说明
     - 虚拟货币/道具说明
  4. 上传材料：
     - 营业执照副本
     - ICP许可证
     - 版号证明（如有）
     - 游戏截图（10张以上）
     - 防沉迷系统截图
  5. 提交 → 等待审核（1-3个月）
  6. 获得备案编号
- 常见坑点：
  - 2019年机构改革后，游戏管理职能有所调整，但部分地方备案仍走原有系统
  - 纯单机、无联网功能的小游戏可能不需要备案（各地执行标准不一）

  - 备案信息必须与实际运营内容一致，虚报会被撤销
  - 各地文旅部门要求可能略有差异，建议先电话咨询当地部门

### RULE-008: 违规分享奖励

- 级别：P0（审核直接拒绝）
- 适用：个人/企业（全部）
- 要求：不得强制、暗示用户分享；不得利益诱导分享至朋友圈；分享利益活动不得存在"无深度互动"、规则不明确、误导用户等违规行为。判定要点：**分享与奖励之间必须存在"深度互动"缓冲**——若"分享后无需任何互动/深度互动即得奖励"，或以分享作为进入、继续游戏的前提，均属违规；分享不得与进入/解锁关卡等核心流程强制绑定。
- 费用：不适用
- 周期：不适用（设计阶段就要避免）
- 检查点：
  - 游戏设计阶段
  - 每次提审前自查
  - 运营活动期间
- 违反后果：审核拒绝；已上架的被举报后下架；严重的封禁分享能力（7天/30天/永久）；多次违规封号。
- 办理路径（合规做法）：
  1. 分享功能只能是"用户主动触发"：
     - 用户点击"分享"按钮 → 弹出分享面板 → 用户选择分享目标
     - 分享按钮不强制、不暗示，不阻断游戏进度
  2. 可以做的：
     - 提供分享按钮（不强制）
     - 排行榜展示（不要求分享才能查看）
     - 合规的"深度互动"社交：邀请好友组队、协作通关等（奖励绑定被邀请者的深度互动而非单纯分享动作）
  3. 不能做的：
     - "分享3个群获得复活机会"
     - "分享到朋友圈解锁新关卡"
     - "分享后无需任何互动即领金币/道具"
     - 弹窗提示"分享到群可获得XXX"
     - 分享后检测是否真的分享成功（微信已禁止此API）
- 常见坑点：
  - "分享后无深度互动即得奖励"是最常见的违规，很多开发者误以为只要文案写"自愿分享"就合规
  - 以分享作为进入/继续游戏的前提（强制分享）一律违规
  - 微信已关闭 shareAppMessage 的 success 回调，无法判断是否真的分享了
  - 群排行（群排名）功能需要单独申请，不能私自实现
  - 审核员会实际点击分享按钮测试，不要心存侥幸
  - 新人开发者建议采用最保守做法：分享不绑定任何奖励；确有"邀请好友组队/协作"奖励需求时，务必确保存在可验证的深度互动，并以微信官方最新运营规范为准
- 来源：https://developers.weixin.qq.com/minigame/product/index.html
- 最后验证：2026-07-09

### RULE-009: 随机抽取概率公示

- 级别：P1（审核检查项）
- 适用：个人/企业（全部，有随机抽取机制的）
- 要求：游戏中任何涉及随机获取虚拟物品/角色的机制（随机抽取、随机掉落付费道具），必须在游戏内明确公示每项物品的获取概率。概率必须真实，不得暗改。
- 费用：免费
- 周期：设计阶段完成
- 检查点：
  - 提审前确认概率公示页面可访问
  - 每次调整概率后必须同步更新公示
- 违反后果：审核拒绝；被举报后下架整改；构成欺诈的面临消费者权益保护诉讼（退一赔三）。
- 办理路径（合规实现）：
  1. 在游戏内设置"概率公示"入口（随机抽取界面必须有明显链接）
  2. 公示内容：
     - 每个奖池的所有物品列表
     - 每个物品的精确概率（如：SSR角色 1.6%、SR角色 13%、R角色 85.4%）
     - 保底机制说明（如：90次必出SSR）
     - 概率是否含保底（必须说明）
  3. 公示位置：
     - 随机抽取界面直接可见或一键跳转
     - 游戏设置/关于页面
     - 首次进入随机抽取界面时弹窗告知
  4. 技术要求：
     - 概率必须与服务端实际配置一致
     - 不得使用"伪随机"欺骗用户（显示概率≠实际概率）
     - 保底计数必须准确
- 常见坑点：
  - 概率精确到小数点后一位是最低要求，建议精确到两位
  - "概率UP"活动必须说明UP后的具体概率，不能只写"概率提升"
  - 保底机制如果跨奖池不继承，必须明确说明
  - 免费随机抽取和付费随机抽取的概率可以不同，但都必须公示
  - 审核员会截图概率公示页面，确保文字清晰可读
  - 概率公示不能藏在"用户协议"里，必须在随机抽取界面直接可达
- 来源：https://developers.weixin.qq.com/minigame/product/index.html
- 最后验证：2026-07-09

### RULE-010: 虚拟货币反向兑换

- 级别：P0（绝对红线）
- 适用：个人/企业（全部）
- 要求：严禁提供任何形式的虚拟货币/虚拟道具反向兑换为法定货币（人民币）的通道。即：用户充值的钱不能通过任何方式换回人民币。游戏内经济系统必须是单向的（法币→虚拟物品），不能形成闭环。
- 费用：不适用
- 周期：不适用（设计阶段必须避免）
- 检查点：
  - 游戏设计阶段
  - 经济系统设计评审
  - 每次更新涉及交易/兑换功能时
- 违反后果：立即下架 + 永久封号 + 可能构成相关刑事犯罪（刑事追责）。这是所有红线中后果最严重的之一。
- 办理路径（合规边界）：
  1. 绝对禁止：
     - 游戏币兑换人民币
     - 道具/装备官方回收换钱
     - 提供C2C交易且平台抽成（形成交易所）
     - 积分/代币兑换现金奖励（超过一定金额）
  2. 允许的：
     - 法币充值购买游戏币/道具（单向）
     - 游戏内道具之间的兑换（金币换钻石等）
     - 未使用充值余额的退款（用户主动申请，走微信退款通道）
     - 活动奖励为实物奖品（但需缴税说明）
  3. 需谨慎的情形：
     - 微信现金奖励：单次≤1元、每日总额有限制时可作为运营活动
     - 但绝不能让用户形成"玩游戏赚钱"的预期
- 常见坑点：
  - 游戏内赚取虚拟物品再换钱的行为模式绝对违法
  - 即使不直接提供兑换，如果默许第三方交易平台存在也可能被追责
  - 棋牌类游戏尤其敏感，特定对局付费模式已被定性为违规行为
  - 微信现金裂变（玩游戏→发现金奖励）超过一定规模会被认定为变相兑换
  - 设计经济系统时请法务确认，不要自行判断合规性
- 来源：https://developers.weixin.qq.com/minigame/product/index.html
- 最后验证：2026-07-09

### RULE-011: 侵权IP

- 级别：P0（法律红线）
- 适用：个人/企业（全部）
- 要求：游戏中不得使用任何未获授权的知识产权，包括但不限于：动漫/影视/游戏角色形象、品牌商标、音乐作品、字体、他人代码/素材。必须拥有全部素材的合法使用权。
- 费用：不适用（使用原创素材免费；购买授权费用不等）
- 周期：不适用
- 检查点：
  - 美术设计阶段（每个素材确认来源）
  - 提审前全面自查
  - 收到侵权投诉时立即响应
- 违反后果：审核拒绝/下架 + 权利方民事索赔（通常数万-数百万元）+ 严重的构成刑事犯罪（侵犯著作权罪，3年以下有期徒刑）。微信平台会配合权利方执行下架。
- 办理路径（合规做法）：
  1. 美术素材：
     - 使用原创设计（保留设计过程文件作为证据）
     - 购买正版素材（保留授权协议和发票）
     - 使用明确标注CC0/免费商用的素材（保留截图证据）
     - 委托外包时在合同中约定知识产权归属
  2. 音乐/音效：
     - 使用免费商用音乐库（如 freesound.org CC0素材）
     - 购买正版音乐授权
     - 自行创作
  3. 字体：
     - 使用免费商用字体（思源黑体、思源宋体、阿里巴巴普惠体等）
     - 购买字体授权（方正、汉仪等）
     - 绝对不要使用未授权的付费字体
  4. 代码：
     - 注意开源协议（GPL会传染，MIT/Apache可用）
     - 不要直接复制他人游戏代码
  5. 被投诉时：
     - 24小时内下架争议内容
     - 联系投诉方协商
     - 准备授权证据或原创证据
- 常见坑点：
  - "致敬"和"借鉴"在法律上不构成免责，相似度够高就构成侵权
  - 网上搜到的图片≠免费使用，百度图片绝大多数有版权
  - 字体侵权是最容易被忽视的，一个字体可能索赔几千到几万
  - 使用AI生成的图片目前法律权属不明确，建议保留生成记录
  - 即使游戏下架了，侵权损害赔偿仍然可以追诉（诉讼时效3年）
  - 微信有IP保护投诉通道，权利方投诉后平台会快速下架
- 来源：https://developers.weixin.qq.com/minigame/product/index.html
- 最后验证：2026-07-09

### RULE-012: 广告超比例

- 级别：P1（审核检查项）
- 适用：个人/企业（全部，广告变现的）
- 要求：小游戏内广告展示不得影响核心游戏体验。具体限制：激励视频广告每次必须用户主动触发；插屏广告不得在游戏核心操作中弹出；广告总时长不得超过游戏时长的合理比例。Banner广告不得遮挡核心游戏区域。
- 费用：不适用
- 周期：不适用
- 检查点：
  - 广告设计阶段
  - 提审前完整体验一遍，记录广告出现频率
  - 用户投诉广告过多时
- 违反后果：审核拒绝；用户投诉后平台警告；严重的限制广告能力（降低eCPM或关闭广告组件）。
- 办理路径（合规做法）：
  1. 激励视频广告（推荐）：
     - 必须由用户主动点击触发（如"看广告获得复活"）
     - 按钮文案明确告知是广告（"观看视频广告"）
     - 用户可以随时关闭（但关闭则不获得奖励）
     - 不能自动播放
  2. 插屏广告：
     - 只能在自然间歇点展示（关卡结束、返回主页）
     - 不能在游戏操作过程中突然弹出
     - 频率限制：建议每次会话不超过2-3次
     - 必须有明显的关闭按钮
  3. Banner广告：
     - 只能放在屏幕顶部或底部边缘
     - 不能遮挡游戏操作区域
     - 不能覆盖在按钮上方导致误触
  4. 格子广告：
     - 只能放在非游戏核心页面（如设置页、排行榜页）
  5. 比例控制：
     - 单局游戏中广告时间不超过游戏时间的30%（建议）
     - 连续广告之间至少间隔60秒
     - 首次进入游戏前5分钟不弹广告（让用户体验核心玩法）
- 常见坑点：
  - "看广告复活"是合规的（用户主动触发），"强制看广告才能继续"是违规的
  - 广告按钮不能伪装成游戏按钮（如把广告入口做成"领取奖励"的样子）
  - 误触率过高会被平台判定为违规（按钮太小、关闭按钮不明显）
  - 广告加载失败时不能卡住游戏流程
  - 审核员会完整体验游戏，广告太多会直接拒绝
  - 用户投诉"广告太多"是微信下架小游戏的常见原因之一
- 来源：https://developers.weixin.qq.com/minigame/dev/guide/open-ability/ad/ad
- 最后验证：2026-07-09

### RULE-013: 内容合规红线

- 级别：P0（绝对红线，零容忍）
- 适用：个人/企业（全部）
- 要求：游戏内容必须符合平台内容安全规范，不得包含法律法规禁止的内容。所有素材、文案、玩法设计均需通过平台内容安全审核。
- 费用：不适用
- 周期：不适用
- 检查点：
  - 游戏策划阶段（题材选择）
  - 美术设计阶段（地图、标识、徽标）
  - 文案撰写阶段（对话、描述）
  - UGC内容审核（用户昵称、聊天、自定义内容）
  - 每次更新前
- 违反后果：立即下架 + 永久封号 + 行政处罚（罚款+吊销许可）+ 可能刑事追责。微信平台对此零容忍，无申诉机会。
- 办理路径（合规做法）：
  1. 地图使用：
     - 必须使用官方审定的标准地图
     - 不要使用任何非官方来源的地图素材
  2. 文字内容：
     - 全部内容需通过平台内容安全审核
     - 不确定的内容建议完全回避
  3. 视觉内容：
     - 所有视觉素材需符合平台内容安全规范
     - 军事题材需谨慎处理
  4. UGC审核（如有用户输入功能）：
     - 在服务端/云函数接入微信内容安全接口：文本 security.msgSecCheck、图片 security.imgSecCheck；小游戏可选用"游戏内容安全"服务端接口（gamesecurity.mediaCheck 等）
     - 用户昵称、自定义文本必须经服务端审核通过后再展示
     - 建立内容安全词库并定期更新
  5. 不确定时的原则：宁可删除，不要冒险
- 常见坑点：
  - 地图是最常见的踩雷点，网上下载的地图素材90%有问题
  - 历史题材游戏（三国类、战争类等）中不得歪曲历史事实
  - 用户自定义昵称中可能出现违规内容，开发者有审核义务
  - 微信审核采用AI+人工双重审核，漏网概率极低
- 来源：https://developers.weixin.qq.com/minigame/product/index.html
- 最后验证：2026-07-09

### RULE-014: 批量注册

- 级别：P0（绝对红线）
- 适用：个人/企业（全部）
- 要求：严禁通过批量注册小游戏账号、使用虚假主体信息注册、买卖/租借他人账号等方式违反平台管理。一个主体（个人/企业）注册的小游戏数量有上限，不得通过多主体超限注册。
- 费用：不适用
- 周期：不适用
- 检查点：
  - 账号注册时
  - 平台定期巡检
- 违反后果：所有关联账号永久封禁（包括已上架运营的）；主体信息列入黑名单（该身份证/营业执照永远无法再注册）；严重的追究法律责任。
- 办理路径（合规做法）：
  1. 个人主体：
     - 一个身份证最多注册5个小程序/小游戏
     - 必须使用本人真实信息
     - 不得借用他人身份证注册
  2. 企业主体：
     - 一个营业执照最多注册50个小程序/小游戏
     - 必须使用企业真实信息
     - 不得注册空壳公司来增加额度
  3. 合规扩展：
     - 确实需要更多额度 → 联系微信官方申请提额
     - 集团企业可以用不同子公司主体分别注册（但必须是真实运营的子公司）
  4. 账号管理：
     - 不用的账号走正规注销流程
     - 不得在第三方平台买卖账号
     - 不得将账号租借给他人使用
- 常见坑点：
  - 同一WiFi/IP下批量注册会触发风控
  - 使用虚拟手机号注册会被识别
  - 关联识别不仅看主体，还看设备指纹、IP、操作行为
  - 即使每个账号单独看都合规，批量行为本身就会被判定违规
  - 被封禁后申诉成功率极低（平台规则明确）
  - 不要相信任何声称可保证注册成功或维持账号运营的第三方服务
- 来源：https://developers.weixin.qq.com/minigame/product/

## 平台合规要点（CP-01 ~ CP-04）

> 以下为当前平台重点合规要点（编号 CP），与 14 条红线并列关注，不作为红线计数。

### CP-01: AI生成内容审核
- 级别：P1（影响审核通过率）
- 要求：AI生成的美术、文案、代码需确保无侵权、无违规
- 背景：AI降低门槛导致同质化，平台审核标准提高
- 建议：AI生成内容必须人工审核后再使用

### CP-02: 广告素材一致性
- 级别：P1
- 要求：推广素材必须与实际游戏玩法一致
- 后果：不一致会推高获客成本、增加竞争压力、可能被平台处罚
- 来源：2026 ChinaJoy论坛明确提及

### CP-03: 四类劣质游戏整治
- 级别：P0
- 背景：2026年官方新规重点整治
- 四类：（需以官方公告为准，通常包括：粗制滥造、抄袭换皮、不当消费引导、危害未成年人）
- 建议：确保游戏有实质性内容，不是简单换皮

### CP-04: 未成年人保护加强
- 级别：P0
- 说明：现行限制为"仅周五/六/日及法定节假日 20:00-21:00 可玩 1 小时/日"（2021年9月起施行，此前为每日1.5小时/节假日3小时）
- 如官方发布新规，以官方公告为准，需实时验证
- 建议：按最严标准实现，宁可多限不可少限
