# 干净交付流水线

## 概述

按当前请求交付本地提交或远端 PR，不自动升级交付范围。固定顺序：归属核对 → 相应强度验证 → 说明 → 获准的提交/发布 → 结果汇报。

## 一、动手前：分辨改动归属

1. 跑 `git status --short`，逐项区分「我这轮改的」与「工作区里本就有的」。
2. 同一仓库可能有多个会话 / AI 工具并行改动。看到非本会话改动（尤其 `zz-*.test.ts`、`*.probe.*`、临时脚本这类命名）：
   - 先读内容判断来源；
   - **不提交、不还原、不修改**；
   - 报告发现 + 给处置选项（留给原会话 / 我来验证后提交 / 部分提交），不替用户拍板。
3. 只 `git add` 本轮自己创建 / 编辑过的明确路径；**不要用 `git add -A` / `git add .`**。
4. 暂存后 `git status` 复核一遍，确认没混入他人改动或敏感文件（`.env`、凭据）。

## 二、提交：说明语言跟随仓库惯例 + 可失败测试

- commit message 与 PR 标题 / 描述的语言**跟随目标仓库惯例**：上游 / 开源仓库用英文（含 why / impact / verification），内网仓库沿用团队既有语言；回复用户的自然语言仍用简体中文。
- 每条修复单独成 commit，并带一个**能失败的测试**。
- **本地增量 commit** 前跑**相关测试**（一条能失败的判据 + 与改动相关的测试即可）；**推送 / 开 PR / 部署 / 发布前**才跑**全量测试**，且**一次跑全**（批量模块尤其注意——曾出现 JCEF 模块中断导致后面的插件模块根本没跑，等于没验就推送）。

## 三、推送前：同步目标分支

若目标分支落后上游：先把目标分支与上游同步（用不可变对象方式造合并提交直接推 ref，**不动本地分支 / 工作树**），PR 才只显示本批次的文件；否则 PR 会混进几百个上游同步文件。

### 官方认证与发布验收

- 用户要求先拉取时，先检查工作区和本地提交，真实 fetch 后保留本地修复完成合并；不能把旧 origin 引用当最新状态。推送前再次同步核对，不 force、reset、amend，也不修改 Git 配置或跳过 hooks。
- 用官方 CLI 核验账号、目标、权限和真实远端状态；OAuth scope 变化保留单独批准，不读取历史令牌。连接失败与认证失败分开诊断，短时 IP 或 UA 对照不等于长期根因。
- 同一批准批次的认证覆盖到 CI、Release 下载与内容核验结束；结束后按用户选择保留官方安全存储或清理临时认证，不提前清理造成重复登录。
- 后台任务逐步传播真实退出码；通知 exit 0 不等于内部每步成功，须核对远端提交、工作流结论和资产摘要。已停止任务不自行恢复，不无限重试或换工具绕过审批。
- 固定标签与源提交，资产用无空格名称；同名资产下载比 SHA-256，一致才可保留，不一致停止并报告。按平台返回的真实链接下载 ZIP 与校验文件，分开报告公开可达性、内容一致性和包内消费者验证。

## 四、PR：永远只保留一个

- fork / 上游里存在未合入主分支的旧 PR（哪怕成链的 20 个）要撤回，只保留当前这一条；采用严格唯一 PR 口径时，连上游仓库里同名的历史 PR 一并撤回。
- **撤回 / 关闭是对外可见动作**：执行前用选项式提问让用户拍板，拿到明确选择再动；撤回时留统一说明注释。

## 五、汇报格式

- PR 链接 + 文件数 / 增删行 + mergeable 状态。
- 未做 / 未验证的部分与已落地部分**严格分开写**，不要把后者说成前者。
- 被问代码量 / 体量时给**成分拆解**而非单一数字：按子系统分类、标注测试占比、区分"继承自既有分支"与"本轮新增"，并说明"能不能更小、代价是什么"。

## 六、边界

- 本地文件修改、测试和明确路径暂存在当前任务范围内自主推进；创建 commit 须用户明确要求。所有 push（含已有同名特性分支）、SVN commit、PR、部署和发布都是对外动作。
- 对外或不可逆动作须有效授权覆盖仓库、目标、环境和批次；已有明确同范围授权不重问，新增范围再弹窗。force-push、重置、删分支和关闭 PR 的明确批准要求保留。
- 提交前确认无敏感文件（`.env`、凭据、密钥）混入。

## 七、与其他技能的配合

- 验收判据本身是否可信：见 `verify-before-claim`。
- 前端交付的页面级验收：见 `verify-ui-in-browser`。
- 推送 / 发布类请求：若环境启用了 `security-scan` 的 L3 深度审查前置，先按该技能的开关处理。
