# 技能引用与能力去向审计

适用于技能维护、吸纳和合并。先检查已安装或当前仓库的真实内容与写入归属，不把旧摘要、mtime、陌生备份或一次读取失败当成另一会话拥有文件的证明。

## 只读检查

从当前已安装技能的准确入口运行[只读检查器](scripts/audit-references.cjs)：

```text
node "<本技能实际目录>/scripts/audit-references.cjs" "<目标技能目录>" [其他技能目录]
```

扫描从SKILL.md开始的本地引用，递归已链接Markdown。支持中文、嵌套目录、Markdown目标及scripts/references/assets的行内路径和多扩展名；visited集合终止循环。仅检查可达文件，不遍历聊天、整个HOME或全盘。

- 退出0：所提取引用存在；`filesScanned`和`refsScanned`说明覆盖，零引用不等于完整。
- 退出1：存在缺失，JSON的missing列出相应引用。
- 退出2：输入无效、不可读、超出边界、链接/特殊文件、文件变化或资源上限；不能误报为“缺失”或成功。

多目标时读取失败优先于缺失。existing/missing保留单目标兼容字段；errors单列原因。只读取请求技能根内的普通文件，外链或嵌套symlink不跟随；不执行被引用脚本，不联网，不写目标。

围栏代码、HTML注释、远端链接和占位符排除；不处理引用式Markdown、嵌套圆括号链接、动态shell路径或完整语法。因此真实代码块命令、跨技能/客户端级helper和不支持语法要人工复核依赖与安装落点。包级白名单/分发范围继续用根目录的skill-reference-integrity检查器；它与本工具检查的根范围不同。

## 缺失后先判断来源

1. 重读当前文件、确认实际目录及是否移动/停用，核对内容摘要和具体任务归属。遇到并发变化保留双方材料，先裁决，不自动重建或覆盖。
2. 分别考虑从未分发、遗漏依赖、旧路径、移动、删除及不可读；没有证据时标未定，不从搜索无命中反推“从未存在”。
3. 只有确有必要且当前范围允许时，按文件名、任务ID及已知来源定向读最小历史片段；不批量扫描或上传完整聊天、私人记忆与账号资料。
4. 同域功能已有可调用承接时优先合并/改引用；按“原能力→承接入口→验证”记录独有内容去向，不能只删引用让检查变绿。

## 修复与验证

检查许可、依赖与准确层级，保留本地定制、上游来源和行尾。脚本实际执行正常/缺参/失败对照；描述按真实应触发与不应触发请求判断，人工语义审查不称为宿主路由实测。

重跑本工具并复核代码块真实命令、安装依赖及入口；分发修改还要检查包级引用、重建元数据并从最终包安装。文件存在、安装成功和宿主真实触发分别报告。

方法从Codex个人local-skill-quality提炼后独立实现；保留本技能原有来源判定、能力让渡和并发归属步骤，不移植宿主状态或历史记录。
