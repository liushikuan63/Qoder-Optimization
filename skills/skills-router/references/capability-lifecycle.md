# 安装与使用的能力闭环

包内文件、已安装、宿主真实触发和业务验证是不同状态。包根 `install.cmd` 进入 `scripts/install-package.cjs`，主动规划更新和缺失能力；基础安装接好现有 `UserPromptSubmit` 路由，而非只把源码留在仓库。接续记忆仍是独立可选项，不因启用能力路由而自动采集会话。

| 状态 | 处理 |
|---|---|
| 已安装、包内一致 | 保留；任务相关时主动提示使用 |
| 已安装、新包不同，且所有本地副本完整匹配旧登记包 | `UPDATE`，安装确认范围内更新并保留恢复资料 |
| 已安装、本地自改或旧来源无法核对 | `REVIEW_UPDATE`，审查差异，不能自动覆盖 |
| 未安装、通用或符合明确偏好 | `ASK_INSTALL`，询问后按选中条目安装 |
| 未安装、专业且不符合偏好或本轮明确选择 | `SKIP`，不全量安装、不反复打扰 |
| 插件/MCP 等平台状态未知 | 保持未知，用平台工具核对，不假称未安装 |

默认先展示计划。`--yes` 只接受基础路由和有资格的既有能力更新，不等于同意所有可选新能力；`--install <exact-id>` 才表示选择对应缺失条目。本地改动或来源未知不能因 `--yes` 被强制覆盖。当前明确选择也包含它的必要依赖；关闭主动建议不妨碍明确安装，但必要依赖有本地改动时仍须审阅。

## 明确偏好

客户端 `capability-preferences.json` 可声明：

```json
{
  "schema": 1,
  "enabled": true,
  "preferredIds": ["skill:parallel-orchestration"],
  "excludedIds": [],
  "preferredKeywords": [],
  "excludedKeywords": []
}
```

无偏好资料时仅按包内通用规则推荐，不读历史会话猜习惯，不把一次安装自动写成永久偏好。一般排除优先；本轮明确肯定点名的用户指令优先于旧偏好。引用示例、咨询与否定不是使用授权。

## 任务主动触发

自定义客户端通过接线命令的 `--client-root` 明确绑定当前 hook 进程，不依赖宿主继承 `QODER_HOME`；不改全局环境或 HOME。旧两参数接线可就地升级，跨客户端或多余参数冲突会拒绝。

- 当前任务相关、已安装且尚无使用选择：`ASK_USE`，询问是否用该能力处理本任务，并给真实入口。用户选择后读取 `SKILL.md`、必要引用或脚本入口并实际使用，不能只列路径后忽略。
- 已有明确指名或适用授权：直接按原授权路由，不重复问。缺失且通用/偏好匹配才询问安装，专业不匹配跳过；无关轮次保持安静。
- 同会话同能力/同动作提醒去重，新会话重新判断；运行台账仅记录提示投递，不代表用户批准、技能读取或业务完成，不保存完整 prompt 或凭据。
- hook 不安装、不联网、不执行项目或业务命令。宿主模型收到提示后用真实问答工具提问，缺工具时用文本；拒绝、取消或沉默均不构成批准。
- 用客户端 `capability-advisor.json` 的 `{"enabled":false}` 可关闭主动提醒；偏好资料的 `enabled:false` 同样保持安静。

## 验收边界

安装后核对真实客户端的脚本依赖、唯一接线、包指针和完整技能索引；冲突保留现状和恢复资料。正负对照覆盖已装使用、缺失通用、明确偏好、专业跳过、排除、明确指名、会话去重与新会话。原生客户端是否真实投递、模型是否提问、用户选择后业务是否完成分别验收；synthetic hook 测试不替代原生 UI。
