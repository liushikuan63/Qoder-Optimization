# 开发交付与行为对照

按本次改动影响，说明实现为何正确，并让独立验收者能从最终产物复核。小型文案改动只需核对事实、链接与差异；功能、配置、运行或交付行为变化，补足相应注释、现有文档和实际流程。

## 从行为确定验收对象

分享包、扩展或环境复现，先列一条完整链：

**本机行为 → 可分享实现 → 安装依赖 → 注册接线 → 真实触发 → 关键结果。**

逐段标明入口与能失败的判据。文件存在、索引可见、健康回执、触发日志和业务结果是不同层次：检查器返回允许，不证明守卫真的运行；注册 enabled，不证明当前进程加载了配置；构建成功，不证明分发包可安装。

保留一条违规应拦、一条正常应放，以及取消/超时或桥接失败对照。替身须保留会改变结果的宿主约束，如服务注入、异步错误、真实 argv、超时和权限询问；不得把所有工具强制成功的替身当生产效果。

## 文档与实现同步

- 注释解释不变量、设计原因、并发/失败恢复及兼容边界，贴近实际实现；不复述逐行代码。
- 优先更新现有 README/Wiki/参考入口。核对实际生产调用链、锁定版本和命令；默认行为、示例、本轮新增与尚未接线分别说明。
- 文档中不复制凭据、账号、真实数据、私人记忆或易变的用户安装路径。必要外部服务写成独立前置，不通过公开配置暗接作者环境。
- 文档门禁通过只说明所检查结构符合要求，语义和运行效果仍须从真实证据判断。

## 干净安装与旧环境增量

两种环境分别安装最终分发包，不用源码目录运行结果替代。

| 场景 | 至少核对 |
| --- | --- |
| 干净环境 | 包身份/摘要、必要依赖、准确落点、注册接线、首次触发、核心结果及正常失败路径 |
| 旧环境增量 | 已装版本与可信旧来源、本地定制、偏好/私有配置、显式新选择、重复运行幂等、失败回滚与恢复材料 |

仅逐字节符合可信旧包的副本可以自动更新；本地变化单独审阅，不能把当前内容复制成“可信基线”。安装后读回实际配置和入口；持久化选择、日志、认证计数等副作用须在声明范围内。

## 独立实装证据

实现者先自测，再由独立验收执行者在兼容真实环境安装、启动并走关键路径。同一机器上的独立执行可以构成独立检查，但须准确标记机器归属，不能称为另一台或云端实测。

1. 冻结源码提交和最终包，记录文件名、大小、SHA256、平台/架构、运行时、验收者与时间。版本号相同不等于字节相同。
2. 实际执行安装器，保存准确参数、退出码、原始日志与目标目录；启动安装后的准确入口并验证受影响流程。
3. 保留首红和失败对象。换包或修复后重新关联摘要与结果，不覆盖首红，也不挪用旧版通过。
4. 按包、平台和范围分别给 PASS、FAIL、SKIP、PREREQ 或未验证。模拟输入、原生 worker、GUI、真实账号与付费 provider 的证据分别标明。
5. 交付前复核最终差异、生成物、公开内容和引用。发布后下载正式全部附件核对摘要及成员，远端状态以实际读回为准。

安装成功但源码关联缺失时，同时记录成功流程与追溯缺口。超时或结果未知先按操作标识只读查回，确认幂等性与现有预算后才决定重试；取消与目标变化撤销旧的待执行方案。

## 来源与边界

根据 Codex 个人 `local-development-delivery` 的可复验方法独立整理，复用 Qoder 已有发布与验证入口，不移植宿主配置或账号。不把某个项目的成功推广为所有机器、所有 GUI 或模型自主选择均已通过。
