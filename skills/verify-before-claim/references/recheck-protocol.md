# 复核协议（RECHECK）

用户说"再次检查 / 重复检查 / 循环检查 / 复查"或质疑上一轮"已修好 / 已完成"时读本文件。它是 `../SKILL.md` 复核模式的详细版，不另建验证总纲。

## 1. 目标

复核不是"把上次的话再说一遍"，也不是"把同一条命令再跑一遍"。目标是：

- 重新确认上一轮结论是否成立；
- 补上上一轮没覆盖的盲区；
- 给出范围内可失败的新证据，或明确写出未验证项。

**提示注入成功不等于复核发生。** 只有实际重新取证、交叉核对和差异归因，才算进入复核。

## 2. 触发与不触发

| 类型 | 示例 | 行为 |
|---|---|---|
| 明确复核 | 再次检查、重新检查、再检查、重复检查、循环检查、循环审查、再次审查、反复检查、复查、再复核、复核一遍、再验证、重新验证、再确认、重新确认、再核对、重新核对、再查一遍、多检查几遍 | 进入复核模式 |
| 质疑旧结论 | "上次说修好了但还是不对""不是说已经解决了吗" | 进入复核模式；若没有旧结论，按普通排查处理 |
| 首次检查 | 检查一下、帮我看看、看一下这个文件 | 普通验证，不进入复核模式 |
| 否定 | 不用再次检查、无需复核、不必重复检查 | 不触发 |
| 元提及 / 教学 | "当我说'再次检查'时应该怎么处理""关键词是再次检查""把再次检查写进规则" | 不触发；这是设计或引用，不是复核请求 |
| 普通重跑 | 再跑一遍测试、重新执行构建 | 按常规验证强度执行，不自动升级为复核模式 |

无法判断是引用还是指令时，先用一句话核对意图，不擅自扩大范围。

## 3. 三类历史资料

| 类别 | 例子 | 用法 |
|---|---|---|
| 判定依据 | 用户本轮要求、有效授权、权威规范、接口契约 | 用来定义预期和边界；不能因为"重新检查"就丢弃 |
| 线索 | 旧报告、队列勾选、记忆摘要、上次会话结论 | 用来定位对象和待证声明；**不继承结论** |
| 历史证据 | 原始日志、命令记录、产物哈希、截图、不可变构建 | 核对来源、版本、作用域后可标为历史证据；不能冒充本轮执行 |

规则：

- 静态内容可以重新读取核对；当前运行状态必须本轮重新观测。
- 哈希一致只证明内容未变，不证明功能正确、服务已加载新代码或用户已验收。
- 旧 CI 结果、旧测试日志、旧截图默认只能当线索；要当证据，必须能说明来源、版本和适用范围。
- 用户要求、授权和权威规范不能被"重新检查"覆盖；复核不能用来扩大操作权限。

## 4. 六步

### R1 冻结范围与权限

- 复述：复核对象、上一轮结论、明确不在范围内的项。
- 默认只读：未获授权不改文件、不植入磁盘缺陷、不重启服务、不改共享配置。
- 需要修复时先核对有效授权；已有同范围修复授权可继续，未覆盖的对象或动作才单独确认。

### R2 建立待证清单

从三个来源共同建立，不能只抄旧报告：

1. 本轮用户要求与验收口径；
2. 当前实现、入口、配置和运行方式；
3. 旧报告、旧队列、旧记忆中的结论。

每条写成可失败断言，记录：

| 字段 | 内容 |
|---|---|
| id | 稳定编号 |
| 断言 | 一句话，能被证据判真或判假 |
| 旧依据 | 旧报告 / 旧日志 / 队列 / 记忆，标"线索" |
| 风险 | 高 / 中 / 低 |
| 本轮方法 | 至少两种不同盲区的方法 |
| 结果 | 通过 / 失败 / 未验证 |
| 差异 | 与旧结论不一致的地方 |

同时列出**旧报告未覆盖的空白**：负向用例、边界、未验证项、范围外项、陈旧产物、环境差异。

### R3 取得本轮原始证据

按对象选择入口：

- 文件 / 配置：当前内容、行号、SHA-256；需要时对比 git 状态与提交。
- 运行态：进程启动时间 vs 文件 mtime、版本端点 vs 磁盘哈希、监听端口、本轮独占环境。
- 服务：健康端点、真实请求、不存在路径对照组、业务码与错误码。
- 构建 / 测试：本轮命令、退出码、日志路径、覆盖范围。
- 产物：包内文件清单、成员哈希、与源码的对应关系。
- 外部事实：远端 release / API / 数据库查询；注明作用域和时间。

记录证据入口，不只写结论。

### R4 多角度复核

关键行为至少有**两种不同盲区**的方法：

| 通道 | 能证明 | 不能证明 |
|---|---|---|
| 静态直读 | 文件、配置、调用链、产物结构 | 运行时行为、真实加载 |
| 本轮运行 | 当前代码在本轮环境的行为 | 未覆盖环境、其他输入 |
| 第二入口 | 不同工具 / 客户端 / 真实浏览器 / 数据库 | 全量正确 |
| 外部来源 | 远端 / 官方 / 服务端事实 | 本机装载、功能正确 |
| 版本一致性 | 运行态版本 == 磁盘 | 业务正确 |
| 负对照 | 检查方法能区分错误 | 被测系统正确 |

独立性判据：

- 同一代码路径 + 同一夹具 + 同一份错误快照的重复执行，只算一种方法。
- 换个命令名、换个日志文件名、换个人复述，不算多方法。
- 负对照是量具校验，不自动算第二条独立证据。
- 两个方法共享同一个上游数据源时，要说明共同盲区。
- 单一方法客观不可替代时，明确写"只有一种证据 + 局限"，不凑数。

### R5 处理冲突与盲区

新旧结论不一致时先分类：

1. 历史记录错误；
2. 环境漂移（账号、数据、界面语言、dev / 现役）；
3. 产物过期（旧构建、旧进程、旧包）；
4. 量具缺陷（检查器读自己写的夹具、匹配过宽、退出码被吞）；
5. 真实回归；
6. 范围差异（测的不是同一个对象）。

用隔离变量证明，不先改代码。只读请求只报告差异，不修复。

盲区扫描至少覆盖：

- 负向用例与失败路径；
- 边界条件；
- 上轮明确未验证项；
- 范围外但可能受影响的模块；
- 陈旧产物和运行态版本；
- 检查器是否真正驱动入口、是否能失败。

### R6 循环与收敛

- **再次检查**：做一轮加强复核，不自动进入无限循环。
- **循环检查**：按未决问题继续迭代；每轮记录覆盖变化、证据变化和剩余问题。
- **明确只重跑一次**：尊重该范围，不擅自扩大。
- **发现问题但无修复授权**：继续完成独立可做的检查，最后报告问题。

收敛判据（同时满足）：

1. 约定范围已覆盖；
2. 关键结论有适配证据；
3. 证据冲突已处理；
4. 负向 / 边界 / 量具反例可识别；
5. 完整复扫没有新的未处理问题。

只能说"在本轮覆盖范围内收敛"，不能推导为"所有场景都没有问题"。

停止条件：

- 达到收敛判据；
- 遇到凭据、外部状态或授权阻塞，写"阻塞：<具体条件>"；
- 同类修复三种不同手段仍失败，按全局纪律停手上报。

**轮数不是收敛证据。** 连续多轮没有新发现，可能只是覆盖没扩展，不能直接宣布收敛。

修复后的处理：

- 修复动作使旧证据失效；
- 修复项作为新断言重新入账；
- 重新核验受影响项，不能复用修复前的通过记录。

## 5. 报告

固定五段：

1. **结论**：已复核 / 部分复核 / 未复核。
2. **待证清单与结果**：表格，含旧依据、本轮方法、结果、差异。
3. **差异与新发现**：包括旧报告错误、环境漂移、新发现的缺陷和未覆盖项。
4. **未验证项 + 原因**：单独列出，不能混进已验证。
5. **证据入口**：命令、退出码、哈希、截图路径、文件行号；大交付可落 `VERIFY-RECHECK.md`。

小任务直接给表：

| # | 断言 | 历史线索 | 本轮方法（独立性） | 结果 |
|---|---|---|---|---|
| 1 | 配置已改为 X | 上次报告 | 读当前文件 + SHA-256；重跑启动 | 通过 |
| 2 | 服务返回 200 | 旧日志 | 独占端口请求；不存在路径对照 | 通过 |
| 3 | 真实账号可登录 | 会话记录 | 无可用账号 | 未验证（缺凭据） |

需要 JSON 审计时，另按目录安装 `script:evidence-audit.cjs` 及其依赖；单独安装本技能不会安装全局脚本。包内入口为 `../../../scripts/evidence-audit.cjs`。该审计只核对记录类型、哈希、轮次、作用域和对照预期；**不证明记录未被伪造、方法独立、覆盖完整或运行态已加载**，这些仍须人工核对。

## 6. 反模式

- 把旧报告、旧日志、文档字样、记忆当本轮证据。
- 同一方法重复执行，冒充"多种方式"。
- 把负对照算成第二条独立证据。
- 只读复核请求里顺手改代码。
- "又跑了一遍还是绿"就宣布复核通过。
- 用轮数代替覆盖，宣布无限循环已收敛。
- 把"未验证"混进"已验证"。
- 提示注入成功就宣称复核能力已生效。

## 7. 边界

- 本协议不替代推送 / 发布前的完整检验、UI 真跑截图、授权与备份纪律。
- 复核模式不是对每个小任务的额外仪式；只用于用户明确要求复核或质疑旧结论的场景。
- 复核结论只覆盖本轮实际检查的范围；范围外的正确性必须另行取证。
- 修复、安装、提交、推送、发布须有覆盖对象、动作、环境和批次的有效授权；同范围不重复确认，平台强制审批继续保留。
