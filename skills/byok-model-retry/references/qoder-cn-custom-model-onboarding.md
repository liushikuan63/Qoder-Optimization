# Qoder CN 自定义模型接入与保存验收

## UI 路径

用户菜单 → 设置 → 模型 → 添加模型 → 自定义/OpenAI Compatible → 选择协议（优先按上游能力选择 Responses API）→ 填 endpoint、API Key、Model ID → 配置能力 → 校验并添加。

控件名称和页面结构可能随版本变化；现场控件树优先，不按旧坐标点击。

## 保存不是验收

1. 保存前记录 `settings.json` 的 mtime、目标 provider 是否存在和相关代理日志时间点。
2. 只有在本地夹具或不会锁号的测试凭据上做一次错误 Key 负对照；生产/共享账号不得用故意错误凭据撞鉴权。
3. 保存后读取 `providers.qoder-custom-*`，只报告 `baseUrl` 是否匹配、`apiKey` 掩码与长度、`type=openai-compatible`、`protocol`、`model` 和 mtime，绝不回显 Key。
4. UI 的“校验通过/已保存”若错误 Key 也通过，就明确判为无区分力；真正端到端业务调用仍需单独执行并取证。
5. 编辑态 Key 留空可能表示沿用旧值，不得据空输入框判“密钥被清除”。

代理日志按时间戳过滤，不按递增 id 归因；代理重启后 id 可能从 1 重数。并行会话存在时，毫秒接近也不能单独证明是本轮请求。

## 本地中转接入

1. 先走 `inspect-untrusted-tool-package` 审计中转包的出口、危险 API、日志脱敏、安装目录和卸载半径。
2. 安装到独立目录，禁止与 Qoder 的 `scripts/skills/rules/memory` 目录同址。
3. UA 判定只改变一个变量：同一无敏感测试请求分别用默认 UA 与目标 UA；不要把“无 Key 也 401”直接解释为 Key 失效。
4. Key 有效性与协议验证属于联网动作：需授权后执行一次模型列表请求和一次最小流式请求，观察首包、事件序列和正常终态；可能计费时先说明。
5. 随应用启动、守护重拉和 Startup 写入是独立系统变更，单独批准；已有端口先确认属主，不重复起实例。
6. 验收至少覆盖：正例、错误 Key 负控、流式终态、工具调用。不能安全构造的分支标“未验证”。

密钥只放本机凭据存储或应用受保护配置，不进源码、日志、技能、记忆或汇报。
