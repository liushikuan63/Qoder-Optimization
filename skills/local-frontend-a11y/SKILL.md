# 本地交互无障碍检查

保留当前 React/Vue/HTML 和组件库约定。先看现有组件是否已处理语义与焦点，避免重复叠加 ARIA；针对本次受影响组件作判断。

- 可操作元素优先原生 button/link。表单中非提交按钮明确类型，链接仍应有合适地址；不能只给 div 加 onClick 就视为键盘可用。
- 输入有可访问名称，label 与控件正确关联；placeholder 不替代 label。错误/帮助信息关联到输入，required/invalid 与真实状态一致；只改变颜色不能传达错误。
- 弹窗核对可访问名称、打开后焦点、Tab 范围、Escape 行为及关闭后回焦点。真实模态还需验证背景不能被键盘或指针操作；aria-modal 只表达语义，不能代替焦点管理与背景隔离。菜单与 tab 使用所选组件模式的键盘约定；不要把所有浮层都套同一组角色。
- 图标按钮有名称，装饰图不重复朗读；动态异步结果的通知方式适度。自动化规则不能判定完整屏幕阅读器体验。

运行现有 a11y lint/自动检查时保留实际结果；在可用浏览器中用键盘测试关键路径、检查焦点位置与名称。没有真实键盘/辅助技术验收时明确相应边界。只有本次任务要求合规评估时才扩大到标准级审计，不以局部检查宣称整体达标。
