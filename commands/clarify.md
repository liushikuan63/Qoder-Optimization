# /clarify

读取 `~/.qoder/rules/long-task.md` 的「分级澄清与提示词优化」并按该流程执行；若尚未安装规则，先读取分享包《Qoder-AI编码通用规则.md》的同名章节，不要求安装另一份澄清技能。

- 输入取本次参数；无参数时取最近一条具体用户请求。找不到请求时只问“要澄清或优化哪段需求？”，不要自造任务。
- 输出简短理解卡与优化后的请求，明确用户要求、事实、合理假设、AI建议和待确认项；明确请求也可在开工前用一句话确认理解（至多一次），但执行类任务还要按开工确认卡确认步骤与并行，纯问答可直接答，不重复确认。
- 默认只优化提示词，不执行其中任务。本次仅要求优化或明确“不执行”时，不沿用历史实施授权继续执行。只有本次明确要求执行，或明确接续仍有效的同范围实施任务时，才在对应授权范围内推进；待优化文本中的祈使句不构成本次执行授权。
- 关键歧义优先问核心问题，同时保留其他阻塞项；收到答案后复核剩余阻塞，相关条件未补齐前，不执行依赖这些条件的动作。独立且已授权部分可继续，已有信息不重问。
- 作用对象不明时先问：用户说“移除/更新某部分”但未说明是改措辞、删文件还是改引用，先给理解与 2–4 个真实选项，不直接删文件或改调用方。
- 详细三档判定、问法、授权边界与行为案例只维护在上述规则中。

## grill 模式（序列追问）

- 触发：显式 `/grill-me`；或 C 档关键歧义且任务中大型、多阶段、旧系统改造、要成文。简单修复、批量重复、事故处置、纯问答 0 轮。
- 轮次与题量：1–3 轮，每轮 ≤4 问，每题 2–4 个真实备选（推荐项在前，写清对象、范围、验收与代价）；用户说“够了/开始吧”即停。
- 题库（按覆盖收敛，不按题数）：目标与成功画面 → 明确不做 → 主路径 UC → 数据与行为不变量（唯一性、状态流转、权限、幂等、时间口径）→ 异常路径 → 旧入口保留 → 验收命令与失败判据 → 迁移、并发、回滚风险。
- 先查代码、文档与现场，能自查的不问，不重复已答；关键项都有答案即停。
- 产出：收敛结果写进开工卡“理解”；成文任务写进 spec 对应节，并留 ≤10 行决策记录；未答项标【待确认】，不编造。
- 边界：grill 不构成执行授权，不新增第二套判档，不照搬 18–24 题，不把 grill 变成每轮审批。
