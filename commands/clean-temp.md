# /clean-temp

显式 /clean-temp 或跨任务批量清理先列清单、弹窗确认；普通任务收尾不自动调用本流程，只清理本会话明确可丢弃且无引用的中间件。

## 步骤

1. **扫描（只列不删）**：跑 `node ~/.qoder/scripts/tmp-sweeper.js --json`
   （默认只扫 `%TEMP%/qoder-work`）。阈值：图片 / 文本 >3 天、脚本 >15 天。
2. **合并本轮产物**：把**本次会话**新产生的临时文件（截图、`*.log`、一次性 `.cjs` / `.mjs`、
   导出的中间 `.json` / `.md`）一并列进清单——它们多半还没满 3 天，扫描器不会报，
   但"用完即删"针对的正是这一批。
3. **列清单 + 弹窗确认**：按 `年龄 / 类型 / 大小 / 路径` 列出，用 `AskUserQuestion` 一次问全，
   给 ≥3 方案（推荐项＝**全部清理**；其余如"只清超期件""本轮不动"），
   写明推荐项（"推荐：X"）。**这一步不能省**：只有人知道哪些还在用。
4. **执行**：拿到确认后跑 `node ~/.qoder/scripts/tmp-sweeper.js --apply`；
   本轮专属文件用**精确路径**逐个 `rm`，**不要**用通配符批量删。
5. **复验并记录**：再跑一次不带 `--apply` 的扫描，确认清单为空；把
   `删除 N 个 / 保留 M 个 / 复验结果` 写进汇报。脚本每次运行都会往
   `~/.qoder/tmp/tmp-sweeper/heartbeat.log` 追加一行，可事后核对。

## 一次性 vs 可复用（命名即归属，收尾按此分流）

命名只提供线索，必须结合本会话产物记录与引用核验；不能仅凭文件名决定删除。

| 形状 | 归属 | 收尾处置 |
| --- | --- | --- |
| `*.<8位会话id>.*`（如 `mb-diag-7ef52d28.ps1`、由它产出的日志） | **本会话一次性探针** | 逐个精确 `rm` |
| 中间截图 `*-after-<n>.png` / `*-final.png` / `*-1.png` | 一次性过程件 | 删，只留**修复前 / 修复后各一张** |
| 语义命名（`asus-mbmanager-recycle.ps1`、`capture-printwindow.ps1`） | **可复用助手** | 保留；被记忆 / 文档引用的路径不得删 |
| 证据件（带结论语义的名字，如 `asus-mbmanager-before-s1003.png`） | 长期证据 | 保留 |

- **保留意图优先**：用户明确保留或被证据/文档引用的产物不得因会话ID命名而删除。
  名称不清晰时可在获准范围内改名，但不把改名或写记忆作为保留文件的前置。
- **本机临时根是 `%TEMP%/qoder-work`**（即 `C:\Users\<user>\AppData\Local\Temp\qoder-work`）：
  `tmp-sweeper.js` 默认只扫它；放在**别处**（如 `D:\tmp`）的产物**扫不到**，需显式 `--root <路径>`
  或按精确路径处理，否则"超期兜底"对那个目录是静默失效的。
  > 注：入站包原文写"本机临时根是 `D:\tmp`"，那是**对方机器**的实况；本机（2026-10-12 复核）仍是
  > `%TEMP%/qoder-work`，故按本机口径落笔。

## 安全边界（违反即停手）

- **只扫我方临时根 `%TEMP%/qoder-work` 与显式 `--root` 传入的目录**。
  **绝不用 `qoder*` 这类宽前缀扫 `%TEMP%`**：Qoder 会为每个会话建 `qoder-XXXX-cwd` 目录
  （实测数百个），宽前缀会把宿主自己的会话目录当垃圾删掉——那等于掀掉正在跑的会话。
  脚本里已有一条硬否决（路径任一段匹配 `qoder-*-cwd` 一律跳过，即使被 `--root` 指到）。
- **绝不删**：仍在使用的证据（台账引用的截图、还没提交完成的补丁）、
  别人会话的在途产物、`.git` 下任何内容、配置目录。
- 不确定属不属于本会话 ⇒ **保留并在清单里点名**，不要靠猜删除。
- 守卫自身要先自证会咬：`node ~/.qoder/scripts/tmp-sweeper.test.js`（17 条，含"新鲜文件不许被列、
  不许被删"的对照组）。
