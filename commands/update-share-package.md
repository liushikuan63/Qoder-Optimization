# 更新分享包（升版 → 同步 → 重建 → 打包 → 验证）

**原则（2026-10-14 用户定策）**：分享包的执行**一律以使用者习惯为主**——取舍跟着使用者的真实用法走，不把"更规范/更优雅"强加给收件人或本机。并包方向（回流包并入）的必做收尾是「合并后审阅 AGENTS.md 与技能（先给编辑建议再改）」，见技能 `merge-inbound-qoder-package` 阶段 7；本命令出包时，文档与清单的措辞同样按该原则回读一遍。

## 公开仓库版本优先走固定提交发布

1. 核对本轮授权、目标仓库与指定版本。先检查工作区和本地提交，真实 fetch 后保留本地修复合并；推送前再同步。指定版本已存在时核对标签和资产，不擅自顺延、覆盖或改旧标签。
2. 公开仓库是交付源。本机 pack-share-extras.js 是私有白名单导出器，不能覆盖仓库 pack-share-extras.cjs，更不能把整个用户配置拷入公开仓库；私人文稿、凭据、暂停状态与本机队列不提交或入包。
3. 在源码仓库预演 `node scripts/pack-share-extras.cjs . --version <版本>`，检查差异并备份后才加 --apply。它只重建包内元数据，不复制本机资料。同步 VERSION 两行、catalog.package.version、manifest.version、双语 README、清单、计数、下载链接和许可证。
4. 文案逐段核对模型、工具、作者和使用者的主体—动作—对象及限定。“模型换个方式又从头踩一遍”不能改成“换个人”；真实同事反馈和安装体验仍保留。数字集合、条数与术语检查不代替语义核对。
5. 按锁文件准备依赖，在隔离 HOME/USERPROFILE/TEMP/TMP/TMPDIR 下运行 `.github/run-tests.js`；Windows 非临时场景沙箱不能落在守卫识别的临时根。扫描和产物校验独立执行，不能修改安全边界或跳过 Git hooks 凑绿。
6. 仅提交明确文件。用 `.github/build-release.js <标签> <仓库外产物目录> <已验提交>` 从 Git 跟踪文件白名单构建：无空格同名顶层目录、核心 ZIP 与可选离线附件 ZIP（各带 .sha256）、分区并集 == 提交文件集、独立解包逐成员比对；平台相关字节（gzip OS 字节）两端归一化。构建失败不推送或发布。
7. 获准推送标签后检查真实 Actions。draft 一律按 REST 返回的 release id 读回（不按 tag 查 draft）；对同名资产下载比摘要，不一致就停止、不替换；再从公开 Release 下载两份资产，验证摘要、版本、范围与包内 register/search/install。认证下载与匿名可达分别报告。
8. 官方 gh 认证覆盖同一批准批次到远端验收结束；OAuth 权限变化单独批准，已停止任务不恢复。更新本机队列与实际完成统计，未验证项直说。
9. **部署与按需技能更新询问（必做，不得跳过）**：发布 / 下载复验通过后，先跑 `node ~/.qoder/scripts/pkg-catalog.cjs drift --catalog "<新包目录>/catalog.json"` 对照新包列出「已安装但与包内内容不同」的按需条目，再必须用 `AskUserQuestion` 询问用户是否部署到现役客户端，给真实备选：① 全量三路合并部署（现役 live / 旧包 / 新包，保留现役较新内容）；② 仅部署本次缺口（逐项列出新增/变更文件）；③ 暂不部署。询问里必须同时列出 drift 命中的按需技能/脚本，并单独问是否更新（逐条「更新 / 查看差异 / 保持现状」）。用户明确选择后才执行；沉默、取消只保留发布结果，不授权部署或更新。部署/更新前逐文件三路比对并备份，保留本地较新内容；完成后重建两侧索引、跑现役相关测试与 `skills-doctor`。汇报必须分开写「包内已发 / 现役已部署 / 按需技能已更新 / 现役较新未覆盖 / 用户拒绝或未部署项」。**反例**：只汇报发布成功就结束、连续多次升版从未询问部署、只部署主包却不检查已装按需技能是否落后——均按交付未完成处理。

## 单独获准的私有白名单导出

以下旧导出链不作为公开版本的输入。先核验当前脚本、导出范围和回滚方式，所有内容变动完成后最后打 ZIP；新版名称不含空格，指定版本不自动顺延。

1. 取当前版本：在发布目录找最新的 `Qoder-Optimization - x.y.z` 目录（及其同名 zip）——2026-10-28 起分享包更名为开源版 `Qoder-Optimization`，版本线从 `0.0.1` 起；早期版本在桌面，名为 `Qoder优化 x.y`，脚本 `check-share-docs.js` / `prune-share-packages.cjs` 仍兼容旧名。发布目录以实际为准（本机当前在下载目录下的 `Qoder-Optimization（qoder优化）\`），操作前先 `ls` 确认实际路径。
2. 升版：复制当前版为无空格的新版目录 `Qoder-Optimization-x.y.z`（用户指定版本时严格从其指定；旧版保留作回滚点，不删除）。**目录名、zip 名、VERSION、catalog 和 manifest 的版本必须同批一致**。
3. 同步文档：把全局配置（AGENTS.md / rules / 记忆）的实质变更同步进新版的两份 md：`Qoder-AI编码通用规则.md`、`Qoder-个人规则生成提示词.md`。
4. 重建记忆包：`node ~/.qoder/scripts/pack-generic-memory.js <暂存目录>` —— 自检必须全绿（替换逐条命中、索引与收录一一对应、`[[链接]]` 不悬空、敏感词零命中），**用 `echo EXIT=$?` 确认退出码 0 再继续**（管道会吞退出码，不要 `| tail`）；通过后 `tar -czf` 打包进新版目录，删除其中的旧 tar.gz。
5. 重打 zip：`node ~/.qoder/scripts/pack-folder.js "<新版目录>" "<新版目录>.zip"` —— 使包内顶层目录名与新版本号一致。
5b. 打入自建技能与 MCP 模板：`node ~/.qoder/scripts/pack-share-extras.js "<新版目录>"` —— 产出 `<新版>/skills/`（白名单自建技能）与 `<新版>/mcp/`（占位符版 MCP 配置 + 说明）；**自检必须 exit 0**（技能齐全 + 产物敏感词零命中）。新增自建技能时同步更新脚本里的白名单。**注意：本步会改动包内内容但不会重打 zip——5b 执行后必须重跑第 5 步，再做第 6 步**（否则 zip 落后目录一步）。
6. 双重验证：`node ~/.qoder/scripts/check-share-docs.js "<新版目录>"`（文档清单：yaml 块含 trigger、计数=磁盘实测、旧技能名残留、围栏成对）+ `node ~/.qoder/scripts/verify-share-package.js "<新版目录>.zip" "<记忆包暂存目录>"`（分发物独立复验：结构 / 敏感词零命中 / 链接不悬空 / 与暂存逐文件哈希一致）。两条都必须 exit 0。verify 的第二个参数传「**只含一个顶层导出目录的父目录**」——脚本内部按 `readdirSync(参数)[0]` 拼路径，直接传导出目录本身会 ENOTDIR 崩溃，父目录混入其他文件会取错条目。
6c. 漂移核验（判断"包内是否落后于本机"只能用这条，**不要**用 `md5sum` 裸比 包内↔本机）：`node ~/.qoder/scripts/pack-share-extras.js "<新版目录>" --check` —— 它把本机当前内容用同一套拷贝+脱敏逻辑重算到临时目录再逐字节比对，exit 0 即无陈旧文件。原因：`SCRIPT_SANITIZE` 会**有意**改写少数脚本（实测 3 个：`rules-weekly-audit.js` / `session-budget.js` / `stop-gate.test.js` 里的 `C:\Users\x` 换成 `<用户目录>`），裸比会把这些误报成"陈旧、需要反向覆盖"，照着改就把内网形态样例打回分发包。判据自证：对新版应 exit 0，对上一版应 exit 1 并列出缺失/陈旧条目。
7. 收尾：清理临时目录，汇报新版路径、回滚点与「已验证 / 未验证」清单。
