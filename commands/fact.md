# /fact

把「用户明确口径、已定架构决定、硬性约束」钉进每轮自动注入的登记簿，避免长会话里被稀释掉。

## 用法

- `/fact` 或 `/fact list`：查看本目录已登记的硬事实
- `/fact add <一句话>`：登记（同一句重复登记自动去重；满 12 条时最旧的掉出）
- `/fact remove <序号>`：按序号删除
- `/fact clear`：清空本目录

底层命令：`node ~/.qoder/scripts/fact-ledger.cjs --add "<文本>" | --list | --remove <n> | --clear`
存储：`~/.qoder/facts/<cwd 哈希>.md`，**按目录隔离**，不会串到别的项目。

## 什么该钉

- 用户明确的口径 / 禁项 / 验收标准（例如「禁 any」「只读审阅不写文件」）
- 已定的架构决定与命名约定
- 反复踩到的环境硬约束（例如「本机禁装 C 盘」）

## 什么不该钉

- 会过期的进度状态 → 放 `.qoder-work-queue.md`
- 代码能推导出的结构 → 读代码即可
- 凭据 / 内网地址 → 只进本机凭据文件

## 验收

1. 登记后 `--list` 能看到，序号连续；
2. 下一轮对话开头应出现「【硬事实登记簿 · … N/12 条】」注入段；
3. 无登记时 hook 必须**零输出**（不占任何 token）。
